# OwO Agent 效能核心改造方案（换心不换壳）

> 版本：v1.0 实施稿
> 日期：2026-09-23
> 范围：`crates/owo-agent-core`（工具层 + 权限矩阵 + 系统提示词 + 循环策略）
> 原则：**不动**权限审批 / 沙箱 / 审计 / diff-revert / MCP / SSE / HTTP 服务面；**重做**模型效能核心

---

## 一、根因诊断（代码证据）

| # | 短板 | 位置 | 后果 |
|---|------|------|------|
| 1 | `read_file` 整文件读入：无行号、无分页、无大小保护、非 UTF-8 直接报错 | `tools.rs` ReadFileTool | 大文件打爆上下文；模型引用代码无锚点 |
| 2 | 无内容搜索（`search_files` 只搜文件名，手写递归 depth8/200 条） | `tools.rs` SearchFilesTool | 找代码只能 list_dir+read_file 暴力遍历，数轮烧光预算 |
| 3 | 无精准编辑：`write_file` 整文件覆盖 | `tools.rs` WriteFileTool | 改一行重传整个文件，token 贵且易改坏 |
| 4 | `run_command` 60s 硬超时、输出无上限 | `tools.rs` RunCommandTool | 跑测试/构建超时；超长输出打爆上下文 |
| 5 | 系统提示词只有三句话 | `context.rs` build_system_prompt | 模型无工程纪律：不先读就改、盲目遍历、失败瞎重试 |
| 6 | 多工具调用串行执行 | `agent.rs` run_turn `for call in calls` | 并发 read 慢一倍以上 |
| 7 | 上下文按条数截断（200 条）+ 字符/2 粗估 token | `agent.rs` estimate_tokens | 预算不精确 |

**结论**：安全外壳（审批/沙箱/审计/快照/MCP）成熟且已验证（362 测试），全部保留。模型效能 = 模型 × 工具信息密度 × 提示质量——后两项全弱，本方案集中补齐。

## 二、工具层改造规格（W1，效果收益 ~80%）

### 2.1 `read_file` v2 —— 行号 + 分页

```
参数：{ path: string (必填),
        offset: int  (1-based 起始行，默认 1),
        limit:  int  (行数，默认 2000) }
返回：{ path, total_lines, start_line, end_line, truncated, content }
```

- `content` 为 `cat -n` 风格：6 宽右对齐行号 + `\t` + 行文本
- 超出 `limit` 或内容超 50k 字符 → 截断，末行附
  `[已截断：显示第 X-Y 行 / 共 N 行；继续读取用 offset=Z]`
- 大小保护：>10MB 拒读；前 8KB 含 `\x00` 判二进制拒读
- UTF-8 lossy 解码（不再因编码报错）
- **描述改写**（教用法）："读取文本文件，返回带行号内容。长文件用 offset/limit 分页；编辑文件前必须先读目标区段。"

### 2.2 `grep` 🆕 —— 内容搜索（最优先）

```
参数：{ pattern: string (必填，正则；编译失败自动降级为字面子串),
        path:   string (搜索根，默认工作区),
        glob:   string (文件名过滤，如 "*.rs"),
        ignore_case: bool (默认 false),
        max_results: int (默认 50) }
返回：{ pattern, matches: [{ path, line_number, line }], truncated, hint? }
```

- 递归遍历（`regex` crate 正式依赖；遍历复用手写递归模式）
- **忽略目录**：`.git target node_modules dist build __pycache__ .owo-attachments .vscode .idea`
- 二进制文件跳过（同 8KB 嗅探）；单行匹配截 300 字符
- 0 匹配 → `hint: "无匹配；可尝试 ignore_case=true、放宽 pattern 或换搜索根 path"`
- **权限级别**：`Read`（放行，不打扰用户）

### 2.3 `edit_file` 🆕 —— 精准编辑（str_replace 语义）

```
参数：{ path: string (必填),
        old_str: string (必填，须与文件内容完全一致，含缩进),
        new_str: string (必填),
        replace_all: bool (默认 false) }
返回：{ path, replaced, preview }
```

- 出现 0 次 → `Err("未找到 old_str；请先 read_file 核对（注意首尾空白与缩进），用完整唯一片段重试")`
- 出现 >1 次且未设 `replace_all` → `Err("old_str 出现 N 次；请扩大上下文使其唯一，或 replace_all=true")`
- 写前自动快照（复用现有 `session.snapshots` 机制 → **天然接入既有 diff/revert**）
- 非 UTF-8 文件明确报错（避免 lossy 写回破坏字节）
- `preview` 返回第 1 处修改点 ±3 行（模型自校验）
- **权限级别**：`Write`（与 write_file 同档，走审批）
- **描述改写**："对已有文件做局部精准替换。old_str 必须先通过 read_file 确认且唯一。新建文件用 write_file。"

### 2.4 `write_file` —— 语义降级

描述改为："新建文件，或改动极大时的整文件重写（覆盖）。**对已有文件做局部修改优先用 edit_file**。自动快照，可 diff/revert。" 行为不变。

### 2.5 `list_dir` v2

```
参数：{ path?: string (默认 "."), max_entries?: int (默认 200) }
返回：{ path, entries: [{ name, is_dir, size }], truncated }
```

- 忽略 2.2 同款目录表；`size` 为文件字节数（目录为 0）
- 截断时 `truncated: true`（模型应改用更具体的 path）

### 2.6 `run_command` v2 —— 超时可配 + 输出上限

```
参数：{ command: string (必填), cwd?: string,
        timeout_secs: int (默认 60，上限 600) }
返回：{ command, exit_code, stdout, stderr, truncated_stdout, truncated_stderr }
```

- 沙箱路径（Job 隔离 + deny 片段）**原样保留**，仅参数化超时
- stdout/stderr 各截 30k 字符并标注 `[输出已截断]`

## 三、权限矩阵更新（`permissions.rs`）

`level_for()` 与 `tool_levels()` 新增两行：

| 工具 | 级别 | 决策路径 |
|------|------|----------|
| `grep` | `Read` | 默认放行（同 read_file） |
| `edit_file` | `Write` | 默认 Ask → 审批链（Auto-review → 用户） |

## 四、系统提示词重写（`context.rs`）

`build_system_prompt` 追加工程纪律段（保留 configured / AGENTS.md 注入顺序）：

```
工程纪律（必须遵守）：
1. 修改文件前必须先用 read_file 读到目标区段；old_str 以读到的内容为准。
2. 查找代码/定义/用法优先 grep，不要用 list_dir 盲目遍历。
3. 长文件用 offset/limit 分页读取；引用位置时使用行号。
4. 局部修改用 edit_file（唯一 old_str）；只有新建文件或大重写才用 write_file。
5. 改动代码后，如工作区有测试/构建脚本，运行验证后再汇报。
6. 工具报错是信息不是失败：读错误详情 → 调整参数重试；连续 2 次同错误必须换思路。
7. 不要假装成功；被审批拒绝的操作换安全路径，不要原参数重试。
```

## 五、循环策略升级（W2）

1. **并行工具执行**：`ToolCalls(calls)` 按 `Policy::level_for` 分组——`Read` 级调用 `futures::join_all` 并行，`Write/Execute/Inject` 级保持串行。
   - 实现要点：只读工具不触碰 `session`（现状已满足：ReadFile/Grep/ListDir/SearchFiles 只用 `workspace`/`policy`）；为并行组构造无 `&mut Session` 的执行上下文，避免借用冲突。
2. **token 预算**：`estimate_tokens` 保留字符/2 粗估（够用），`context_limit` 条数截断保留作兜底——本项收益小，放最后。
3. 验证基准（`scripts/`）：固定 15 任务回归集（定位→编辑→跑测试），记录成功率/平均轮数/token，改造前后对比。预期：同任务轮数 -40%、token -50%。

### 实施中暴露并修复的存量缺陷（非本次改造引入）

1. **`observe` 情景记忆测试**：断言用硬编码 `2026-08-12`，超 30 天保留期被 `prune()` 淘汰 → 改取当前时间。
2. **`memory_graph` 4 项**：同根因，预置数据在 `MemoryStore::new()` 时被淘汰 → 测试内放宽 `OWO_MEMORY_RETENTION_DAYS`（数据入库即被清，真机也会这样，值得留意）。
3. **`revert` diff 路径退化**：`relative_display` 拿原始 workspace 去 strip canonical 路径，本机 `Administrator ↔ ADMINI~1` 导致 strip 失败回退绝对路径 → 两侧统一 canonical 后再比较（**修的这是真实健壮性问题**）。
4. **`eval` mock 缺陷**：`KeywordProvider` 把 system 提示词也纳入关键词匹配，新增的"工程纪律"里有"读取"二字即污染全部用例分支 → 改为只取最后一条 user 消息。
5. **`usage` 成本恒为 0**：成本被量化到微美元/毫美元，单次请求（150 token ≈ 3e-7 美元）被抹零 → 精度提到纳美元。**`/usage` 面板此前所有小额请求成本都显示 0，是真 bug**。
6. **`usage` 测试竞态**：两个用例共用 `usage::global()` 单例 → 加串行锁。

### 环境备忘（下次会话必读）

**本机无任何 MSVC 工具链**（`link.exe` / `lld-link.exe` / `cl.exe` / `rc.exe` 全无）、**无 MSVC CRT**（全盘无 `libcmt.lib` / `vcruntime.lib` / `libcpmt.lib`）、**无外网**（github / crates.io 均超时），故既装不了 VS Build Tools，也无法用 `xwin` 拉取 CRT。

因此 `rust-toolchain.toml` 固定的 `x86_64-pc-windows-msvc` **无法链接出可执行文件**。根因不是「缺链接器」这么简单：`ort`（onnxruntime）与 `sherpa-onnx` 的 Windows 预编译包是 **MSVC C++ 静态库**，其 `__CxxFrameHandler4` / `__GSHandlerCheck` / `__std_terminate` 属 MSVC C++ 运行时，std 符号是 MSVC 修饰名（`??1?$basic_string@...`），与 MinGW 的 Itanium ABI **不可能互相解析**——故 GNU 目标同样链接不出 exe（已实测）。这是 ABI 级不兼容，补单个文件解决不了。

**已打通的替代路径**：`owo-agent-core` 新增 `native-inference` 特性（默认开启）门控 ort / sherpa-onnx。关闭后 OCR 自动降级 Media.Ocr / Paddle 云、本地 STT 返回「未启用」，其余能力不受影响。

```powershell
# ① 类型检查（全 workspace + 全 test target）：需指向原始 prebuilt lib 目录
$env:ORT_LIB_PATH="D:\working OWOWOWOWOWO\OwO\agent-sdk\target\sherpa-onnx-prebuilt\sherpa-onnx-v1.13.5-win-x64-static-MT-Release-lib\lib"
$env:SHERPA_ONNX_LIB_DIR=$env:ORT_LIB_PATH
cargo +stable-x86_64-pc-windows-gnu check --workspace --all-targets --target x86_64-pc-windows-gnu

# ② 出可执行文件：不需要 ORT/SHERPA 环境变量
cargo +stable-x86_64-pc-windows-gnu build -p owo-agent-cli --bin owo-agent --no-default-features --target x86_64-pc-windows-gnu
```

- `cargo check` 无需 `lib*.a` 副本，直接指原始 prebuilt `lib` 目录即可（曾为 GNU 命名建的 `target\gnu-link-staging` 已删）。
- `--no-default-features` 要真正向下透传，`[workspace.dependencies]` 里必须给 `owo-agent-core` / `owo-agent-server` 标 `default-features = false`——否则 Cargo 会**忽略成员的覆盖并告警**，特性门形同虚设。
- 并行度用 `-j 4`（`-j 8` 以上会触发 link.exe 1318/1140）。
- **删除文件后进回收站**：释放磁盘需 `Clear-RecycleBin -DriveLetter D -Force`，否则 `Get-PSDrive` 显示空间不回落。
- git 可执行文件原路径 `C:\大创\tools\MinGit\cmd\git.exe` 已失效，需重新定位。

## 七、非目标（明确不做）

- 不重写 server/权限/沙箱/审计/MCP/会话存储
- 不改 HTTP API 与 openapi.json（契约冻结）
- 不引入 codex-rs 外部依赖（仅参考其提示词与 apply_patch 语义设计）
- 不做流式工具输出（W2 视基准结果再定）
