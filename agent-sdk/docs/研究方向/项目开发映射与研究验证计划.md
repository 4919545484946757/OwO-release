## 建议的阶段交付

**阶段 A：形成可评审契约。** 对一个典型文件开发任务记录入口、用户约束、任务计划、工具授权、文件变更、验收、审计和失败终态。将现有多条执行路径映射到同一张表，指出重复和不一致，保留实际源码位置。

**阶段 B：验证任务可靠性。** 对最小真实工具任务分别引入取消、进程中断、重试、审批撤销和迟到回调。结果绑定确切源码和最终文件哈希，明确不可复核或未运行项。

**阶段 C：验证协作收益。** 选独立文件、共享接口、深依赖和冲突型任务，比较 Single、固定 Team、共享工作区、隔离 worktree。任务初始状态、模型、权限和总预算一致；统一最终验收，报告成功率、墙钟分布、用量、返工与人工介入。

**阶段 D：研究自动优化。** 从阶段 B/C 的脱敏轨迹中提候选工作流，在保留任务上验证。流程版本、权限效果和回退策略都进入交付物。

## 每项任务最少包含

问题与触发条件、当前行为证据、建议行为、受影响模块、权限和事务边界、数据兼容、失败/取消/恢复、必要契约检查、真实任务评价及停止条件。Rust 验证遵循 AGENTS.md 的 ORT、资源、并发规则；研究材料整理本身不需要启动构建。

## 设计选型的边界

不直接把本地研究包当运行依赖。先确定需要借鉴的机制，再核对该提交源码、许可证和适配成本。不得以外部论文指标填报 OwO 的成功率、速度或成本，也不据此放宽现有审批与交付门禁。
