# Agent 发展方向与研究问题

## 从本库研究可以形成的技术主线

早期工具型 Agent 研究重视推理、动作和反馈；多 Agent 研究进一步讨论角色、消息和任务分解。工作流优化研究探索自动生成更好的调用程序，记忆研究处理长期任务的信息组织。近期软件协作和失败研究让工程问题更具体：依赖如何满足、读状态是否过期、变更如何集成、成功由谁判断。

这一脉络来自本库选材，不是对所有研究的完整趋势统计。主要来源包括 [自治 Agent 综述](https://arxiv.org/abs/2308.11432)、[软件工程 Agent 综述](https://arxiv.org/abs/2408.02479)、[工作流综述](https://arxiv.org/abs/2508.01186)、[多 Agent 开发经验](https://arxiv.org/abs/2608.11965)、[记忆综述](https://arxiv.org/abs/2602.19320) 和 [安全综述](https://arxiv.org/abs/2608.28490)。

## 可以落为研究课题的问题

| 问题 | 假设 | 如何检验 |
| --- | --- | --- |
| 自适应并行是否减少浪费 | 根据任务依赖与协调成本选择并发，比固定角色数更合适 | 同预算对比单 Agent、固定 Team、自适应调度 |
| 共享上下文怎样保持新鲜 | 基础快照缓存加依赖版本校验，可减少重复读取与旧信息返工 | 变更依赖文件，测拒绝、重读、返工与成功率 |
| 隔离与共享如何组合 | 只读探索、共享接口确认、隔离实现的混合策略可能更合适 | 相同任务比较多种工作区拓扑 |
| 持久化工作流能否可靠恢复 | 事件、操作 ID 与收据能识别重复或未决副作用 | 在关键提交窗口中断，核查最终状态与审计 |
| 失败轨迹能否改善流程 | 受限候选优化可减少重复模型/工具步骤 | 训练/保留集分离，计入搜索成本并保留安全门禁 |
| 记忆如何避免污染与过期 | 来源、作用域和 revision 有助于拒绝无依据事实 | 旧版本、恶意工具输出及跨项目隔离实验 |
| 交付判断能否减少虚假完成 | 验收绑定最终 revision、证据和未解决问题 | 人为制造失败或变更漂移，检查终态 |

## 对产品路线的含义

先把用户目标、任务状态、工具动作、变更和验收连成一条可追踪执行链。随后根据实际耗时和失败证据优化上下文、调度与恢复。工作流自优化和复杂跨 Agent 协作应有清楚的数据、预算和保留集。

多模态桌面、跨机器、自动学习等方向需要单独的环境和验收；论文或独立 crate 的存在不能证明端到端可用。本项目可以把它们作为扩展研究面，同时维护可稳定验证的核心链路。
