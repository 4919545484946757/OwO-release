# 权限、注入防御与协议

## 通信协议和执行授权各有职责

MCP 把工具与上下文能力暴露给客户端；A2A 提供跨 Agent 的发现、任务和消息交互。连通协议后仍要验证调用者、工作区、工具效果与授权有效期。外部 Agent 的结果、工具输出、网页和仓库文档都保留来源和信任级别。

本地资料：[Rust MCP SDK](../研究资料库/project-notes/modelcontextprotocol--rust-sdk/README.md)、[A2A Python SDK](../研究资料库/project-notes/a2aproject--a2a-python/README.md)、[MCP Agent](../研究资料库/project-notes/lastmile-ai--mcp-agent/README.md)。Rust MCP SDK 选读中保存了 Service、请求 ID、进度 token 和服务角色的源码声明；需继续看 transport 与生命周期，不能仅凭协议接口推断完整取消和回收。

## 注入检测不能替代执行限制

[AgentDojo](https://arxiv.org/abs/2406.13352) 与 [InjecAgent](https://arxiv.org/abs/2403.02691) 研究工具返回中的间接提示注入。[2026 检测器评估](https://arxiv.org/abs/2610.03448) 指出公开基准上的检测排名可能不能迁移到 Agent 工具输出；这是一项近期预印本结果，应结合自己的输入分布复核。

建议同时衡量攻击成功率、正常任务成功率、误报率和额外成本。宿主仍执行授权、作用域、参数与效果检查，模型或检测器不能给自己扩大权限。摘要和长期记忆也应保留外部材料的信任级别。

## 面向多 Agent 的具体检查

| 情形 | 应记录的判据 |
| --- | --- |
| Worker 请求越出写范围 | 宿主拒绝，保留请求与审计 |
| 审批已撤销 | 未执行动作被阻止；正在执行的动作按规则取消 |
| 旧 attempt 迟到提交 | epoch/attempt 校验拒绝，并保留事件 |
| 外部工具建议执行命令 | 作为数据处理，重新按当前用户授权判断 |
| Agent 产物携带新的“系统要求” | 不提升其指令优先级 |
| 跨进程或跨机器调用 | 绑定身份、会话、请求、授权与结果；避免只信远端成功字段 |

这些是建议的验证项，本轮没有宣称现有实现都通过。
