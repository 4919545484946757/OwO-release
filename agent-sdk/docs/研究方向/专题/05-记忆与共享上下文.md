# 记忆与共享上下文

## 先分清要保存的内容

| 内容 | 建议归属 | 新鲜度与验证 |
| --- | --- | --- |
| 当前运行与节点状态 | RunStore / EventLog | attempt、epoch、revision |
| 项目接口与已确认事实 | ProjectSpace / SharedFacts | 源码版本、证据引用、失效条件 |
| 用户偏好与长期知识 | Memory store | 来源、时间、作用域、删除与冲突 |
| 大型文件和产物 | Artifact / CAS | 内容哈希、类型、归属和权限 |
| 近期模型交互 | Session context | token 预算、工具调用配对、摘要来源 |

[CoALA](https://arxiv.org/abs/2309.02427) 用于分类，[MemGPT](https://arxiv.org/abs/2310.08560) 用于分层上下文管理，[Generative Agents](https://arxiv.org/abs/2304.03442) 用于观察、检索、反思与规划的组合。[A-MEM](https://arxiv.org/abs/2502.12110) 与 [Mem0](https://arxiv.org/abs/2504.19413) 提供记忆组织与长期检索方法。[2026 记忆综述](https://arxiv.org/abs/2602.19320) 可用于核对评价维度。

## 检索到的信息还需要判断来源

同一接口的旧说明和新实现可能冲突。记忆条目需要 source、observed_at、revision、scope 和 evidence_refs；从模型推测产生的内容不能升级为已确认项目事实。摘要继承原内容的信任级别，不能通过“写入记忆”把外部指令转成用户授权。

压缩上下文时保留未完成任务、约束、关键工具结果和可定位产物；工具调用与对应结果不应拆散。旧 source revision 变化后，使相关摘要失效或要求重新读取。

## 多 Worker 共享的内容要足够小

团队级基础快照可按 revision 复用，节点级读取只附带依赖产物、接口约束和必要文件事实。新节点启动时验证依赖版本；缓存键不能只用 team_id。写入记忆与写入代码分别处理，避免一个 Worker 的推断覆盖团队事实。

本项目已有 ProjectSpace、CAS、上下文和 memory 相关模块；本专题只提出检查方向，没有判定它们都已具备上述约束。
