# 评测与交付验收

## 基准覆盖不同能力

| 能力 | 论文和项目 | 可借鉴内容 |
| --- | --- | --- |
| 仓库缺陷修复 | SWE-bench、SWE-agent、Agentless | 固定基线、补丁、环境与测试 |
| 多 Agent 软件协作 | CooperBench、AsynCodeBench、CAID、PASC | 冲突、依赖、集成及协作消融 |
| 通用交互任务 | AgentBench、AgentBoard | 多回合与过程进度 |
| 浏览器自动化 | WebArena | 环境任务与最终状态检查 |
| 真实桌面任务 | OSWorld | 应用状态、文件与跨应用工作流 |
| 用户、工具与策略 | tau-bench、tau2-bench | 对话、工具和领域规则 |
| 工具注入安全 | AgentDojo、InjecAgent | 正常任务与攻击任务对照 |

原始论文：[SWE-bench](https://arxiv.org/abs/2310.06770)、[AgentBench](https://arxiv.org/abs/2308.03688)、[AgentBoard](https://arxiv.org/abs/2401.13178)、[WebArena](https://arxiv.org/abs/2307.13854)、[OSWorld](https://arxiv.org/abs/2404.07972)、[tau-bench](https://arxiv.org/abs/2406.12045)、[tau2-bench](https://arxiv.org/abs/2506.07982)。每个基准的结果只对应其任务和环境。

## 适合本项目的分层评测

先做可确定复现的契约层：工具输入、权限、取消、状态转移、恢复与产物绑定。再做受控模型层：模型调用真实工具，检查最终文件和审计。最后做同模型真实任务与桌面交互层，证明入口到交付的闭环。各层结果分别记录，不能让 mock 结果覆盖真实任务层。

单 Agent 与 Team 使用相同任务、初始代码、模型、工具和验收。总预算包含规划、实现、评审、返修和集成调用。预先定义超时、失败和人工介入规则，重复运行并报告分布；仅挑最好的 Team 样本会产生偏差。

## 最小结果记录

每个样本记录源码身份、dirty 状态、模型配置、任务输入、权限范围、初始与最终产物哈希、验收命令/判据、退出码、模型用量、墙钟、失败原因和人工介入。缺失 usage 时保留“未知”；未配置价格时不虚构费用。

协作另记关键路径、ready wait、预算/租约等待、上下文组装、重复修改、冲突、返工与依赖解决时间。[AsynCodeBench](https://arxiv.org/abs/2609.32662) 提供依赖级评价视角；[MAST](https://arxiv.org/abs/2503.13657) 提供失败分类视角。[生产评估研究](https://arxiv.org/abs/2605.01604) 用于考虑持续漂移和真实运行失败，不能仅依赖一次离线分数。

## 接受交付的对象

验收针对最终集成版本，而不是某 Worker 先前的文件或 commit。开放问题、权限拒绝、取消和证据缺失要进入最终状态。测试通过的版本与交付版本不一致时，结论需要重新验证。

本轮只整理这些评测资料及设计，不执行基准、训练、Rust 构建或云端模型评测。
