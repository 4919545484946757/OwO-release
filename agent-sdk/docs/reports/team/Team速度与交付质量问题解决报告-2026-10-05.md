# Team 速度与交付质量问题解决报告

日期：2026-10-05
范围：本轮源码检查聚焦 `agent-sdk` 云端任务提交、状态读取、取消、队列恢复与重试生命周期。这是 Team 质量闭环的后端基础设施修复，不代表 `/team` 相对 Single 的速度或整体交付质量已得到验证。

## 结论

本轮确认并修复了一类会直接拉低多角色交付稳定性的任务生命周期问题：HTTP 提交、状态读取和取消此前可能被长时间持有的队列锁拖住；此外，一次可重试的远端失败会把任务重新置为 `Queued`，但 runner 已消费派发信号，导致任务没有后续重试。现在提交使用独立短锁持久化后立即返回，查询从磁盘快照读取，取消通过 watch 信号交给 runner；HTTP 与 CLI 的执行路径会对指定任务执行可取消的退避重试，直到终态。

这改善的是后端响应和任务不丢失语义，尚无可运行的 Cargo、HTTP/SSE 或真实远端执行证据。因此不能据此声称 Team 已更快、全部任务都能稳定完成，或已优于 Single。

## 代码调整

- `POST /cloud/tasks` 通过短时提交锁分配 ID 并持久化，不再等待执行队列的长生命周期写锁；远端任务由后台 runner 执行。
- `GET` 状态与结果读取经过 task ID/文件身份校验后读取持久化记录，避免等待执行锁。
- 活动任务取消只发送取消请求并立即返回 `cancel_requested`；runner 负责远端中止、终态记录与流事件收尾。任务开始前已收到的取消也会阻止远端提交。
- 队列恢复会把崩溃前的 `Running` 状态恢复为 `Queued`，并校验持久化文件名与任务身份。队列为恢复和新提交的任务建立派发 token，runner 按具体 task ID 执行。
- 修复可重试失败后的悬空任务：同一次 runner 生命周期内按退避策略重试到终态，并持续响应取消。CLI `cloud submit --run` 使用同一指定任务重试路径，避免误跑更早恢复的其他任务。
- 服务端 OpenAPI 与 TypeScript OpenAPI 描述同步了异步提交和取消请求语义。

## 质量与效率影响

这轮减少了提交/查询/取消与执行锁之间不必要的串行等待，也避免重试任务因派发 token 已消费而永久停在队列中。远端执行仍由单个队列写锁串行；长退避期间会暂时阻塞其他执行任务。因此它解决了任务状态可靠性与控制面的锁耦合，没有实现多任务并行执行，也没有消除 Team 的模型调用、上下文传输和集成开销。

恢复出的任务目前要等 HTTP 队列被初始化且有新的提交触发 runner 才会被派发；进程关闭也还没有等待 detached runner 收尾。两项仍是可靠性缺口。

## 2026-10-06 追加：Team 自动准入统计口径修复

源码对照发现评测的不确定性口径与自动 Team 门禁不一致：ProductEval 的配对 delta 置信区间已经按 `case_id` 聚类，承认重复运行不能视作独立任务；收益门禁却以 `runs_total` 判断是否达到 30 个样本。单个 case 重复 30 次因此可能被错误当作 30 个独立证据，足以让噪声很大的组进入 auto-Team 候选。

## 2026-10-06 追加：云端任务进度 SSE 交付修复

源码链路复核发现，云任务 SSE 路由发送 `event: progress` 命名事件，而 Goal 面板只监听 `EventSource.onmessage`。浏览器只将未命名的 `message` 事件交给该回调，所以界面看似建立了连接，却收不到命名的实时进度。面板现在注册 `progress` 事件监听器，并将正常帧写入进度日志；默认 `message` 保持兼容。

同一链路中，慢 HTTP 消费者会让广播 ring 溢出，服务端此前收到 `Lagged(skipped)` 后直接继续，无法知道丢失了哪些阶段事件。服务端现在发出 `stream_gap` 进度帧（任务 ID、跳过数量、重新订阅与核对结果提示）后结束该流，避免静默丢失。Goal 面板能把这条恢复提示显示给用户。新增 Server Rust 契约测试覆盖广播溢出场景；新增 Node 测试在真实 Goal 面板脚本上触发命名进度事件和 gap 提示并断言日志渲染。

Node 定向测试通过。Rust 源码格式静态检查通过，但 Server Rust 测试未运行：最新资源仍低于 Cargo 门槛。Browser 插件未提供，仓库也没有 Playwright package/workflow；`pnpm exec playwright --version` 因当前工作区没有 package 失败，因此未完成真实浏览器截图与交互验收。证据见 [云端 SSE 进度交付证据](../../qa/evidence/cloud-sse-progress-delivery-20261006.json)。


## 2026-10-06 追加：云端 SSE 自动按序号续传

在前一轮明确慢消费者的 gap 提示后，继续补齐自动恢复链路。云任务持久化后、HTTP 暴露 task ID 前，同步在 `CloudSseHub` 注册订阅源，客户端能在后台 runner 尚未启动时先建立有效连接。hub 为每个 task 保存单调序号，SSE 帧设置标准 `id:`；新订阅根据 `Last-Event-ID` 在锁内取得后续历史并先建立实时接收端，消除重放与实时订阅间隙。广播队列溢出时的 gap 帧保留最后已交付游标，浏览器自动重连后能够重放保留帧。

历史容量按事件数和字节数双重限制。若游标前的历史已经被淘汰，服务端计算并显式报告缺失数量，随后只发送当前保留的后缀；最终结果仍应通过任务结果接口核对。不存在的 task ID 会收到 `task_not_found` 终态消息。Goal 面板让 EventSource 对临时断线自动续传，并在 `succeeded`、`failed`、`canceled`、task 不存在或游标已经覆盖终态时主动关闭，避免终态后循环请求。

新增 Server Rust 测试源码检查预注册任务的首事件订阅、Last-Event-ID 过滤、frame ID、历史淘汰缺口、慢消费者 gap、unknown task 及终态游标后的关闭；Goal Node 测试 2/2 通过。Server Rust 测试未运行，内存仍低于仓库 Cargo 门槛；没有真实浏览器或断网/重连验收。证据记录在 [云端 SSE 进度交付证据](../../qa/evidence/cloud-sse-progress-delivery-20261006.json)。

## 2026-10-06 追加：结构化风险输入扫描复杂度上限
