## 1. 扩展审查结论

CLI 已经有共享 Daemon 接入、流式正文、工具开始/结束、审批、计划更新、宿主完成统计、Team SSE 跟踪及断线重连；不能概括成“CLI 没开发完”或“没有进度”。

问题在于若干入口只改本地展示状态，未形成宿主约束；几处完成摘要丢掉宿主质量状态；进度展示多是事件文字，缺少阶段耗时、无进展检测和执行身份；多个后台功能的恢复、存储和权限边界仍不同源。

这轮优先发现：

1. **只读档位不可靠**：全局 `--permissions read-only` 在 turn 没有被消费，REPL/TUI 的 plan 模式没有请求级只读接线。
2. **默认数据根不一致**：CLI 使用 `%LOCALAPPDATA%/OwO/Agent`，Electron 核心使用其 `data` 子目录；没有显式统一时不会发现同一实例/会话库。
3. **取消与终态有明显缺口**：TUI 审批时 Ctrl+C 被分支拦住，TurnFailed 后仍可能追加“✓ 完成”；一次性 turn 对 blocked/unverified 也未建立可靠退出码。
4. **后台结果可能被读错或丢失**：Goal API 按随机 UUID 文件名字典序挑“最新”；Cloud CLI 默认目录含 PID；Workflow 历史列表和详情恢复不是同一条链。
5. **扩展执行未完全通过统一宿主**：Goal 子代理重新创建 Policy，Workflow real 后端直接写文件/调用 MCP，需要核对父策略收紧、收据和审计是否能贯穿。
6. **测试覆盖存在可定位盲区**：路由源清单按行扫描、不递归；绿色测试不能覆盖所有跨行路由和子目录装配。

优先级沿用上一文档：P0 为基础约束/执行路径严重缺陷，P1 为任务/状态/恢复可靠性问题，P2 为展示、资源或验证覆盖缺口。**S** 表示源码与调用链确认，**A** 表示用当前算法规则构造的示例，**V** 表示需实测的风险；A 不是运行了 Rust 代码。

## 5. CLI / TUI / Client 详细审查

### C-01：声明为全局的选项没有全局生效（P0/P1）

[main.rs](../../../crates/owo-agent-cli/src/main.rs) L31–36 将 output/permissions 声明为 global，L105–131 只把两者传给 turn，把 output 额外传给 capabilities；REPL、TUI、cloud、doctor 等分派不消费它们。[commands/turn.rs](../../../crates/owo-agent-cli/src/commands/turn.rs) L108 附近只比较 Trusted，没有处理 ReadOnly。

因此 `--permissions read-only turn ...` 没有主动收紧宿主请求；`--output jsonl repl` 仍可输出欢迎、提示符及普通文字。read-only 不能靠默认宿主档位碰巧只读实现。

另一个输出风险：main L99–103 的 tracing fmt 没有指定 stderr。当前本机依赖 tracing-subscriber 0.3.23 的 fmt 默认 writer 是 stdout；开启会产生日志的过滤配置后，日志可污染 JSONL。这与 ui_output.rs 的 stdout 协议注释不一致，不能据注释判定已经隔离。

**修复**：定义每个命令支持的全局能力，支持的必须传到底，不支持的参数应明确拒绝。只读以请求/会话有效 Policy 约束，不得为了一个 CLI 调用改全局 Daemon 档位。日志固定 stderr；JSONL 生命周期事件带 session_id/turn_id/completion。

**验收**：read-only 下写/执行工具确实被宿主拒；JSONL 每行可解析，verbose/RUST_LOG 和异常也不污染 stdout；未知/不支持组合非零退出并给原因。

### C-02：plan 模式没有改变宿主执行范围（P0）

[repl_daemon.rs](../../../crates/owo-agent-cli/src/commands/repl_daemon.rs) L177–184 只设置 self.read_only 和文案；L617–623 调 open_turn 没有只读信息。[tui.rs](../../../crates/owo-agent-cli/src/tui.rs) L522–532 toggle_mode 同样只改 bool，L866–892 不把它传给运行任务。TUI 初始 --agent plan 也只进入该本地状态。

协议 [CreateSessionRequest](../../../crates/owo-agent-protocol/src/lib.rs) L670–675、[turns.rs](../../../crates/owo-agent-client/src/turns.rs) 的 TurnRequest 没有对应权限 override。默认 REPL 的 read_only 标志也没有通过完整系统提示收紧宿主；即使加提示仍不能替代 Policy。

**修复**：在宿主验证的 request/session permission context 中执行“父允许范围 ∩ 本次只读收紧”，工具清单同步只读。plan/build 的选择与有效宿主档位分别显示，不能通过 build 把原本更严格的全局政策放宽。

**验收**：同一 Daemon 下 plan 会话不能写，build 会话按各自许可执行；切模式、恢复会话、全局档位变更后仍正确。

### C-03：TUI 审批打开时无法用 Ctrl+C 取消（P1）

[tui.rs](../../../crates/owo-agent-cli/src/tui.rs) L380–388 的 approval 分支只识别 y/t/w/n，随后直接 return；Ctrl+C 的 abort 分支在 L390 之后，永远到不了。run_turn_task L1112–1127 等用户 oneshot 最多 300 秒，期间不继续读取服务端失败/取消事件。

**表现**：界面提示 Ctrl+C 可中止，但待审批阶段做不到；另一个客户端已经取消，也可能暂时读不到终态。

**修复**：最高优先级处理 abort/exit；审批响应独立于事件接收，不暂停整个 SSE 消费。取消或 PermissionResolved/TurnFailed 到达时撤销当前卡与 responder，保留真实原因。

**验收**：待审批时 Ctrl+C、Esc 的明确行为、其他客户端取消、审批过期、重复点击均不会留下 300 秒死等。

### C-04：TUI 审批不足以审阅具体动作（P1）

[tui.rs](../../../crates/owo-agent-cli/src/tui.rs) L1098–1118 用 PermissionRequest 创建 ApprovalInfo，只保留 tool/reason/level，丢掉 args/redacted_args/risk_note/explain。文件操作的 reason 可能只是“工作区内写文件”，不能证明用户知道改哪个文件、改什么。

L505–518 在发送到本地 responder 后立刻显示“已允许（工作区长期）”；网络 respond_permission 错误在 L1125 被丢弃。Server 当前写/执行只能批准本次，不生成可复用 Grant，TUI/行式 CLI 却对所有审批都展示 task/workspace 选项。

**修复**：复用现有完整脱敏审批卡 DTO；按 tool effect 显示实际支持的 scope。将“已提交决定”和“宿主已接受、是否创建 Grant”分开，失败可重试或明确作废。

**验收**：路径、参数、影响和风险可读；写操作不会显示虚假的长期授权；网络失败不显示已经执行/授权成功。

### C-05：结束事件和最终摘要没有统一完成语义（P1）

一次性 [turn.rs](../../../crates/owo-agent-cli/src/commands/turn.rs) 记录 Final、ToolResult、TurnFailed，却不把 TurnStats.completion_status 归入最终裁决；render_final 在人类模式输出“[完成]”，JSONL turn_result 缺 completion_status、completion_record、turn_id。blocked/unverified 统计事件本身不会让函数返回 Err。

[tui.rs](../../../crates/owo-agent-cli/src/tui.rs) run_turn_task L1088–1178 没有 TurnFailed 分支，发给 UI 后继续得到 Ok(TurnSummary)；drain_events L923–936 可以在失败行之后再追加“✓ 完成”。REPL L700–705 也不按 failed/completion_status 区分摘要符号。

**修复**：统一 TurnResult reducer，分别处理 transport、completion 与取消；机器最终行保留宿主状态和证据。退出码区分执行失败/取消/结果待验收，纯问答 ResponseComplete 可以正常结束；不能一律把 Candidate 当成功交付或硬失败。

**验收**：Final→TurnFailed、Final→blocked stats、accepted stats、取消、缺终态、重放失败分别输出一致结果和退出码。

### C-06：最终答案可能遗漏宿主补充内容，TUI 又会重复（P1）

[ui_output.rs](../../../crates/owo-agent-cli/src/ui_output.rs) L486–495 中只要 streamed=true，Final.text 就不重新渲染。模型流出的候选文字与宿主最后追加的验收说明、回退文本或修复后结论未必一致；前面的文本可见不代表最终文本完整。

TUI 结束时先 flush_streaming，再把完整 final_text 推到 transcript，见 L925–928，因此常规流正文与最终答案又有重复风险。多次验证返修的模型正文还可能串到一起。

**修复**：为每次 response 建立正文版本，流式只对应当前候选；最终 host text 与候选比对，替换或补充有明确来源的片段。TUI 同一最终版本只展示一次，保留先前失败候选为可折叠记录。

**验收**：流式全文=Final、Final 有额外验收声明、多模型修复、空回答兜底、断线重放均内容正确且无重复。

### C-07：管道输入与审批输入混用（P1）

[turn.rs](../../../crates/owo-agent-cli/src/commands/turn.rs) prompt-from-stdin 先 read_to_string 到 EOF，之后 human/plain 的审批仍 read_line；plain 不是稳定非交互策略，只有 JSONL 显式默认拒绝。[repl_daemon.rs](../../../crates/owo-agent-cli/src/commands/repl_daemon.rs) run_piped 逐行读任务，内部审批又读取同一个 stdin。

例如管道“任务一\n任务二\n”：任务一触发审批，第二行可能被当成审批回答并拒绝，任务二再也不会作为任务执行。同步 readline 还阻止该消费者读取权限过期/终态。

**修复**：明确 interactive、deny-if-approval-needed、external-approval 三种模式；任务流和决定流采用独立协议，不借用下一行任务。非交互缺授权返回 approval_required 及可恢复身份，不自动扩大权限。人工阅读时事件接收也持续运行。

**验收**：多行任务、完整 stdin prompt、EOF、外部审批、审批超时和 Ctrl+C 都不吞任务；stdout/退出码稳定。

### C-08：Rust 流客户端仍有等待与协议边界缺口（P1/P2）

**验收**：建连等待可取消、半开连接可诊断、终态后不等无限 EOF，多行/CRLF/UTF-8/超限/分页重放有明确契约。

**修复**：先确认持久化再发布成功，保存失败进入明确状态；历史读取、断电后 interrupted 判定和当前运行查询共用持久索引。历史快照只读，不自动重放动作。已终态内存条目按容量/TTL 淘汰，必要详情从磁盘加载。

**验收**：磁盘满、写 meta/outcome 失败、执行中崩溃、完成后重启、历史详情查询，既不假成功也不永远 running。

### C-25：Automation 触发与执行之间有崩溃/容量断点（P1）

[automation.rs](../../../crates/owo-agent-extensions/src/automation.rs) L230–247 先改变 last_run_at 再 save；文件直接整份覆盖，load 解析失败静默保留空/部分默认。upsert/remove/toggle 同样先改内存再写，失败没有回滚。

[server lib.rs](../../../crates/owo-agent-server/src/lib.rs) L790–806 即使并发槽已满也 fire 更新触发时间，再记录 skipped；one-shot 可能被消费。L845–853 在 fire 已保存后才 spawn，没有 durable dispatch record，崩溃会留下“触发过但未执行”。record_run 写失败多处被忽略；同一 interval task 也没有 task-specific 在飞租约。

RunPrompt 明确只读，这是当前安全边界，不应为实现写任务自动放宽；产品必须向用户说明这种自动化不执行写/命令类任务。

**修复**：采用持久 trigger/run_id/lease/outbox，定义满载时 queue/coalesce/skip 政策；同任务是否允许重叠显式配置。原子提交、加载损坏诊断与失败回滚，执行台账写失败不能静默丢失。无人值守授权单独设计。

**验收**：触发后 spawn 前崩溃、并发满、one-shot、长 interval 执行、磁盘失败、重启恢复，每项有确定去向，不能重复副作用或丢一次性任务。

### C-26：Settings 更新与秘密、作用域仍不同源（P1）

[Settings](../../../crates/owo-agent-core/src/settings.rs) L224 起整个结构 serde(default)；[settings_update](../../../crates/owo-agent-server/src/settings_api/mod.rs) L648–682 接受 Settings 后整份保存并覆盖 policy/deny/hooks/spec。只提交 model 的部分 JSON，其余字段会变默认值，可能无意清空用户收紧配置。

Settings.load L300–308 把损坏 JSON 静默变默认；save L311–318 直接覆盖文件。ProviderSettings 明文 api_key 在 workspace/settings.json，与现行 AGENTS 凭据不得落配置的规则冲突（不仅是上轮 Electron config.json）。settings_update L704–707 只把 api_key_env 名字存到 OWO_PROVIDER_API_KEY_ENV；OpenAI Provider 主配置读取 OPENAI_API_KEY，不消费该别名。

**修复**：区分明确 Replace 与局部 Patch；未传字段保留，显式清空可审阅。配置 parse_error 进入诊断，不默认恢复宽松策略。有效 Provider/凭据来源与壳和 Daemon 同源，遵守环境注入约束；敏感旧配置迁移不静默删除。修改策略必须明确作用域，不能模型设置顺便重置权限。

**验收**：局部更新不会清空 deny/hooks/spec；坏文件保留并报错；命名环境变量实际生效；保存/备份/导出无密钥正文。

### C-27：路由契约提取器有已定位的覆盖盲区（P2）

[route_contract_tests.rs](../../../crates/owo-agent-server/tests/route_contract_tests.rs) L51–68 按 source.lines 扫 .route( 同行引号；L72–101 只 read_dir 顶层 .rs，不递归子目录。当前 routes.rs 已有大量 rustfmt 跨行声明，专项脚本同文件完整匹配 138 条、现有规则 93 条，遗漏 45 条；子目录也有 7 个 router 文件。

## 8. CLI 进度应怎样优化

### 8.1 不再把“有一行输出”当作任务进度闭环

建议复用宿主事件与 Activity/Team snapshot，统一定义：

```text
ProgressIdentity:
  session_id / goal_id / team_id / run_id
  turn_id / step_id / attempt_id / execution_epoch
  progress_revision

ProgressState:
  phase, phase_entered_at, last_progress_at
  action_summary, target_summary
  wait_reason, retry_count, budget_remaining
  completed_items, pending_items
  completion_status, evidence_refs
```

phase 至少涵盖 preparing、compacting、waiting_provider、running_tool、waiting_approval、waiting_user、waiting_lease、verifying、persisting、cleaning_up、terminal。reasoning 是一种模型进展，不等于完成正文；正在校验或持久化也不应退成泛化“思考中”。

### 8.2 三种 CLI 表面采用同一状态 reducer

| 表面 | 推荐行为 |
| --- | --- |
| Human REPL/turn | 当前阶段与持续时间、最后进展、当前工具/等待原因；阶段切换产生一行关键记录 |
| TUI | 固定状态栏、详细待办/工具面板、可折叠日志，审批/提问/取消不能被刷新盖掉 |
| Plain | stdout 只最终结果；进度和诊断走 stderr；非交互授权需求返回稳定码 |
| JSONL | task_started / phase_changed / tool_started / tool_finished / approval_required / task_completed/failed 等带身份与版本；最终行携宿主状态 |
| Team watch | 明确正在跟踪哪个 Team/attempt；重试和返工重置显示；停止跟踪不会冒充取消 Team |

“已完成 3/5 个已知步骤”可以显示；动态 DAG 还会新增验证/返工时，不显示未经定义的 60% 全任务完成率。无法计算 ETA 就展示阶段耗时和 last progress age。

### 8.3 回收与错误要进入进度语义

取消应显示三步：请求已提交→正在停止/清理→宿主确认已停止，或清理失败。不要本地 bool 一改就打印“已取消”；不要传输 EOF 一到就打印“完成”。

工具 wall time、Provider wait、审批、租约、排队、验证和写盘分别计时；并行 worker 内部时间不与墙钟相加。先复用已有 metrics/span，不额外调用模型来生成“百分比进度”。

## 10. 建议补充的定向测试与实际验收

| 测试场景 | 必须证明 |
| --- | --- |
| --permissions read-only / --agent plan / Tab→plan | 写/命令均被宿主收紧，其他会话不受副作用 |

| TUI File/MCP 审批 | 具体参数/范围可见，宿主确认决定后才显示接受 |

| Final 带宿主追加文字 | 最终结果不遗漏；TUI 正文不重复 |
| stdin 多任务与审批 | 下一条任务不被当审批吞掉，EOF 不冒充许可 |
| SSE 建连无头/收终态不关连接 | 本地取消可用、看门狗按阶段工作 |
| Daemon 换 PID/port/token | 重新发现实际实例，安全请求可恢复，写操作不重复 |
| 默认 CLI+Electron 启动 | 一个数据根、一个 DB 所有者、同一会话与回合 |
| Goal 多 run、重启、反序 UUID | latest 正确、状态绑定自己的 plan/attempt |
| Goal/子代理在父 readonly/deny 下 | 限制继承，取消和内部事件向宿主传播 |
| Team 同状态重试、AwaitingHuman | 新 attempt 可见，等待有明确下一步 |
| Workflow default/mock/real/typo | 模拟显式、错误 400，real 经 ToolHost |
| Workflow 写盘失败/重启历史查询 | 失败明确、历史可读、无永久 running |
| Automation one-shot 满载/崩溃 | 明确 queue/skip/恢复，不丢触发或重复副作用 |

| Settings partial patch / bad JSON | 不清空其他限制，不静默放宽，不写密钥 |
