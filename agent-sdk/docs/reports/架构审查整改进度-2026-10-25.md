## 存储迁移界限

注册表根不变。首次打开新注册表时，旧 templates/*.json 在一个事务内导入 workflow-templates.sqlite3，原文件保留不改。之后数据库是规范状态，旧 JSON 不作为缺失记录的自动回退，以免删除后复活。迁移文件错误使整批回滚并返回错误，修复源文件后可重试。不要让新旧版本二进制同时修改同一注册表，也不要通过删除备份 JSON 重置模板。

revision 独立于社区 version；有效变更的完整模板与 SHA-256、删除记录均保留历史。修订不改变已有运行快照，不授予执行或写权限。兼容 save_template 仍支持既有内部调用；必须把用户更新全部接入 expected_revision 统一服务才能完成 F6。


## F6 版本入口接线增量

## 最新增量：AI 草稿与模板原子采纳

本轮修复最后一处已确认的模板/采纳状态双写：原接口先提交模板修订、再写 drafts/*.json，第二步失败会让模板与草稿状态不一致。当前草稿文档迁入同一个 workflow-templates.sqlite3，没有新增数据库、Agent、工具宿主或执行权限入口。

### 实现与行为

- WorkflowDraft 文档与内部 storage_revision 放在现有状态 crate。storage_revision 是宿主并发身份，serde 跳过，不由模型 JSON 或模板社区 version 提供，也不冒充模板 revision。
- 生成、收敛、详情、列表、验证回写、采纳、删除都使用规范数据库。普通更新使用 CAS；验证查询期间若发生采纳或删除，旧回写返回 workflow/draft_conflict，不覆盖新状态、不自动重试。
- 采纳继续先执行共享工作流结构校验与当前 Worker 工具可用性检查，再在一个 IMMEDIATE 事务中检查草稿版本、模板 CAS、内置来源保护，并共同提交模板修订及 adopted_revision。任一步失败整批回滚。
- 完全相同候选的重复采纳，仅当对应模板修订仍为当前版本时幂等成功，不新增历史。模板已被其他人编辑或删除时拒绝旧采纳，不推断最新版本、不复活删除记录。显式 expected_revision 的原有人工审阅更新语义保留。
- 普通诊断/验证写入不能伪造 adopted_revision 或修改已经采纳的模板身份；模板变更必须再次经过原子采纳路径。删除草稿保留内部删除记录，且不删除已经采纳的模板。
- 历史 workswarm/drafts/*.json 在首次打开草稿存储时整批事务迁移。文件身份、文档格式、常规文件和 2 MiB 上限均检查；错误使整批回滚，修复后可重试。原文件保持不变；迁移标记完成后不再作为读取回退，删除不会被备份复活。旧 adopted_revision 仅保留历史记录，不填造缺失基础版本，幂等判断仍须与实际当前模板文档和修订共同核对。不要同时运行新旧二进制写同一数据根。
- 两份 OpenAPI、生成 TS 类型同步草稿并发冲突和存储失败响应；路由契约检查覆盖所有草稿路由。现有业务 DTO/路由地址保持兼容。
