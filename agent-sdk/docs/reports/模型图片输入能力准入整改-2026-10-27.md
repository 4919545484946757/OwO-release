# 模型图片输入能力准入整改（2026-10-27）

对应原审查 F8/F9。本批补充按实际连接和模型绑定的能力声明与请求前校验；它不验证远端模型的视觉理解，也不代表整个多模态工作流已验收。外观重做继续暂停，只改模型配置与执行行为。

## 当前行为

- 声明由模型 ID、Base URL、API 格式（OpenAI 兼容或 Anthropic）、完整 URL 模式和 image_input 布尔值组成。模型大小写和 URL 路径大小写有意义；规范化 URL 主机/默认端口，普通 Base URL 忽略尾斜杠，完整 URL 保留路径。
- 缺声明表示能力未知；显式 false 表示声明不支持；true 表示“声明支持（未实测）”。不根据名字、提供商 chat_modalities 或连通性测试升级为已验证。
- OpenAI 兼容与 Anthropic 原生适配器在组装和发送图片请求前检查该绑定，包括历史消息携带的图片。未知、不支持、不匹配及配置无效均返回明确 input/ 错误，不删除图片后悄悄重发文本。
- 文本请求无需图片声明。不支持图片不妨碍纯文本请求。模型覆盖必须匹配当前请求使用的声明，不能直接继承另一个 Worker/模型的支持状态。
- OpenAI 默认模型只解析一次，并将该快照同时用于能力检查和请求体，避免并发保存设置时校验模型与发送模型不同。地址和 API 格式来自实际 Provider 连接，不从页面预设猜测。
- 输入拒绝属于配置/输入错误，不触发 Provider 重试、备用连接或服务熔断；原有出境、权限、凭据绑定、取消和审计链路保留。此校验本身不授予任何工具权限。
- 当前校验位于原生 Provider 的实际发送边界。主 HTTP 回合可能已经被接受并写入输入检查点，再通过回合错误报告能力问题；本批不能宣称它总是在 HTTP 接收阶段返回 4xx。

## 配置和数据组织

共享 DTO 为 ModelInputCapabilityBinding。CustomModelConnection 可携带 input_capabilities，只影响本次连接，不改进程环境、共享模型或会话凭据。声明没有 verified 字段，服务端拒绝用此字段伪造实测状态。

默认宿主配置在 settings.json 的 model_input_capabilities 数组，沿用现有 Settings 保存与启动接线，CLI serve、兼容本地 REPL、Server 装配和设置更新均应用同一声明。字段缺失/null 时继承宿主环境；显式 [] 清除声明。实际请求读取 OWO_MODEL_INPUT_CAPABILITIES；宿主声明按连接身份匹配，不是全局“所有模型支持图片”开关。

示例（地址和名称均为占位，不代表远端服务能力）：

~~~json
{
  "model_input_capabilities": [
    {
      "model": "your-vision-model",
      "base_url": "https://example.com/v1",
      "api_format": "openai",
      "use_full_url": false,
      "image_input": true
    }
  ]
}
~~~

最多 64 个声明、序列化 JSON 总计 24 KiB，避免 Windows 单个环境变量长度问题。拒绝重复身份、无效协议、非法 URL、内嵌凭据、查询参数与 fragment。普通/加密 Settings 保存前都校验；无效的手工持久配置在应用时写入有界的无效标记，实际请求保持拒绝，不沿用旧的支持声明。错误不回显 URL 凭据或配置正文。

默认 OpenAI 兼容模型设置及自定义模型弹窗都有三态选择。切换模型/地址/协议/完整 URL 会失效旧声明；失焦再次触发同值 change 不清除用户刚选择的声明。连通性测试只测连接。自定义模型保险库保存规范化绑定，重开后恢复，并拒绝把旧声明随身份修改搬到新模型/端点。图片能力是公开配置，不含密钥；密钥仍经原保险库路径托管。

默认设置表单仍针对 OpenAI 兼容端点；原生 Anthropic 默认宿主可用上述声明数组/环境配置，独立自定义连接可在弹窗设置。chat/vision/STT 的命名连接分配、团队节点连接选择和媒体保险库适配仍需继续收敛。
