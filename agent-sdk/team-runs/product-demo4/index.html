开始使用

TypeScript SDK · 零网络依赖文档页

OwO Agent SDK 把 agent 循环从你的业务代码里挪出来

工具调用、多步推理、状态回填，这一整套循环由 SDK 托管：你只注册工具、写一句 prompt。 现有技术栈不用动——它就是一个可以 npm install 进你项目的库，不是云平台，也不是聊天应用。

开始使用 在 GitHub 上看源码
  • 工具在你的进程里执行，SDK 不接管你的数据和权限
  • 内置重试、超时与步骤 trace，失败能看到卡在哪一步
  • 无构建步骤依赖，Node 18+ 与任意支持 fetch 的运行时都能跑

装进来只需要一条命令

安装（包名为示例占位） npm install @owo/agent-sdk

兼容性：TypeScript 5+ 类型定义随包发布；Node.js 18+ 原生可用；其他运行时只要有 fetch 即可。 不支持的环境会在初始化时直接抛出明确错误，而不是运行到一半静默失败。

四个能力，对应你手写过的那四段胶水代码

每张卡片说的都是一个具体机制，不是形容词。

工具注册

用 tools 对象声明工具：名称、描述、参数 schema。SDK 负责把 schema 转成模型可读的工具清单，你只需保留自己的实现函数。

机制：参数进入执行前先按 schema 校验，类型不符直接返回结构化错误给模型，不会把脏参数传进你的代码。

多步循环

模型决定调用工具后，SDK 执行工具、把结果回填进对话、再次请求模型，直到模型给出最终答案。

机制：每一步都是一个可序列化的 step 对象，循环次数与终止原因都写在 run 结果里。

重试与超时

单次模型请求失败、或多个工具调用并发超时，SDK 按你配置的次数重试，并把已完成的步骤结果保留下来。

机制：长任务不会因为一次失败从零重来；重试日志与首次失败原因一起进入 trace。

步骤 trace

每次 run() 都返回一份步骤记录：哪一步、调了哪个工具、传了什么参数、耗时多久、返回了什么。

机制：trace 是普通对象，可以直接写进你自己的日志系统或断言进测试。

三步接进来

下面右侧是可以直接照着跑的最小示例，不含任何隐藏配置。

  1. 安装并初始化

    npm install @owo/agent-sdk，然后 new Agent({ model, tools })。模型标识用你已经在用的那个，不绑定厂商。

  2. 注册你自己的工具

    一个工具就是一个带 description 和 parameters 的普通对象。执行逻辑仍写在你的进程里，SDK 不代跑、不托管凭证。

  3. 调用 run 并读结果

    await agent.run("...") 返回 output 与 trace。把 trace 打进日志，出错时就能定位到具体步骤。

说明：复制按钮与平滑滚动由页面内联的一小段原生 JS 提供，脚本缺失时页面内容与代码块依旧完整可读。

一次 run 的四个步骤，全部由 SDK 串起来

重试与超时托管在第 2 步和第 4 步之间，你不必自己写 while 循环。

  1. 1

    prompt

    你传入的自然语言任务，加上系统提示与工具清单，组成第一次请求。

  2. 2

    模型决策

    模型要么直接回答，要么返回一个或多个工具调用及参数。

  3. 3

    工具执行

    SDK 校验参数后在你的进程内调用你注册的函数，捕获异常与耗时。

  4. 4

    结果回填

    工具结果写回对话上下文，再次请求模型，直到得出最终答案或达到步数上限。

托管部分：第 2、4 步的请求会按 retries 与 timeoutMs 重试；每次重试都记录进 trace， 因此失败时你能看到「哪一步、哪个工具、什么参数」出了问题，而不是只拿到一句超时。

工程上的常见追问

决定要不要引入之前，先看这几条。

我需要改现有技术栈吗？

不需要。SDK 是普通的 npm 包，在现有 Node 服务里 import 即可用；把 agent.run() 当成一个异步函数调用，路由、鉴权、数据库都留在原处。

我的数据会出网到哪里？

只有你显式发给模型的请求内容会离开你的进程，去往你自己配置的模型端点。工具的返回结果是否回填也由你决定——SDK 不额外上报、不带遥测。

可以自托管吗？

SDK 本身运行在你的服务器上，不依赖 OwO 提供的任何在线服务。只要模型端点是你能访问的（自建或第三方），整条链路就在你的网络边界内。

怎么接已有的内部工具？

把已有函数包一层 tool({ description, parameters, run })，描述写清楚什么时候该用它、参数写清类型即可。返回值会原样作为工具结果回填给模型。

工具执行失败会怎样？

异常会被捕获成结构化错误回填给模型，模型可以选择换一个参数重试或直接回答；超出 retries 后整次 run 以失败结束，已完成步骤的 trace 仍然保留。
