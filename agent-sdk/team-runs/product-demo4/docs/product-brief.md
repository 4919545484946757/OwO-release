# 产品简报（Product Brief）— OwO Agent SDK 落地页

> 状态：初稿（工作区为空，无既有源码，本简报为 designer 的唯一输入基线）
> 范围：单页静态站点 `index.html` + `styles.css`，交互用最小原生 JS（无构建、无框架、无外部依赖）。
> 本文件不包含 HTML/CSS，仅定义目标、范围与验收口径。

---

## 1. 一句话定位

把「OwO Agent SDK」讲清楚的一页式产品落地页：在一屏内让开发者看懂**它是什么、能替我省什么、怎么三行代码接进来**，并把「开始使用」引导到明确动作。

## 2. 目标用户

| 优先级 | 用户画像 | 当前状态 | 来这里想解决的问题 |
|---|---|---|---|
| P0 | 独立开发者 / 全栈工程师（1–5 人团队） | 已经在用某个 LLM API 手工写编排逻辑 | 我能不能不一堆胶水代码就得到一个可用的 agent？接入成本多大？ |
| P0 | 后端 / 平台工程师（中型团队） | 评估引入 agent 框架或 SDK | 权限、工具调用、可观测性怎么管？换掉成本高不高？ |
| P1 | 技术负责人 / CTO（决策者） | 只看落地页做初筛，不读文档 | 这玩意靠不靠谱、上手快不快、值不值得让团队试？ |
| P1 | AI 爱好者 / 学生 | 浅度浏览，被社交媒体或朋友带来 | 能拿它做什么酷东西？有没有 demo 看？ |

**共同特征**：习惯快速扫读、讨厌营销空话、要看到「代码」和「证据」才会继续往下。
**与他们无关的读者**：非技术采购、纯 C 端用户——页面不为他们做解释性妥协。

## 3. 核心信息（按必须传达的优先级排序）

1. **它是什么**：一个 SDK（不是云平台、不是聊天应用），用来在自己的应用里跑起 agent 循环——工具调用、多步推理、状态管理由 SDK 负责。
2. **为什么省事（核心价值）**：把你现在手写的「调模型 → 解析工具调用 → 执行 → 回填 → 再调」这套循环收敛成几行代码；内置重试、超时、流式与工具注册。
3. **接入成本**：三行可运行的最小示例（安装 → 初始化 → 一句 prompt），强调「不需要改现有技术栈」。
4. **可控性**：工具（tools）由你自己注册、执行边界在你的进程里，SDK 不接管你的数据和权限。
5. **可观测 / 可调试**：每次运行有可追踪的步骤记录（trace），出错能看到「卡在哪一步、哪个工具、什么参数」。
6. **可靠性**：内置重试与失败降级策略，长任务不会因为一次失败全丢。
7. **行动号召**：主 CTA「开始使用 / 查看文档」+ 次 CTA「在 GitHub 上看源码」。

**必须避免的表达**：模糊的「赋能 / 一站式 / 全链路」式营销语；任何未经证实的数字（如「10 倍提效」「10 万开发者」）；承诺具体定价或 SLA。
**需要的「证据感」**：一段真实可读的代码片段 + 一张流程/结构示意 + 一个具象的使用场景描述（如「自动整理客户邮件并生成工单草稿」）。占位数据必须明显标注为示例（如 `TODO/示例`），不得伪造成真实指标。

## 4. 页面层级（从上到下的信息秩序）

| 序 | 区块 | 目的 | 内容要点 | 优先级 |
|---|---|---|---|---|
| 0 | 顶部导航（sticky 细条） | 提供全局出口 | Wordmark + 3–4 个锚点（概览 / 快速开始 / 功能 / 文档）+ 右侧主 CTA 按钮 | P0 |
| 1 | Hero | 3 秒内说清是什么 | 一句 H1 定位（含 "OwO Agent SDK"）、2 行副文案（省什么、代价多少）、主 CTA + 次 CTA、一个视觉主体（代码块或循环流程图） | P0 |
| 2 | 信任/上下文条 | 降低陌生感 | 安装命令一条（`npm i` 形式，明确标注为示例）+「TypeScript / Node / 任意运行时」这类兼容性一句话 | P1 |
| 3 | 核心能力（3–4 卡） | 支撑 Hero 的主张 | 每卡：小标题 + 一句话 + 一个具体机制（工具注册 / 多步循环 / 重试 / trace），不用图标堆砌 | P0 |
| 4 | 快速开始（代码区） | 让「三行接进来」可验证 | 左侧 3 步说明，右侧可读代码块（真代码，语法高亮用手写 span 或纯文本样式，不引第三方库）；块右上角「复制」按钮 | P0 |
| 5 | 工作原理 / 流程图 | 解释循环而不是口号 | 4 步示意：`prompt → 模型决策 → 工具执行 → 结果回填`，标注「由 SDK 托管的重试 / 超时」 | P0 |
| 6 | 使用场景（2–3 个） | 让人代入 | 具体任务 + 输入 + 输出示例（明确写「示例」），例如邮件分诊、数据整理、内部问答 | P1 |
| 7 | 工程细节/FAQ（折叠） | 回答决策者疑问 | 4–6 条：换栈成本、数据是否出网、能否自托管、如何接已有工具、失败怎么处理、许可协议 | P1 |
| 8 | 收尾 CTA | 收口 | 复述一句价值 + 主 CTA 重复出现 | P0 |
| 9 | 页脚 | 最低合规与导航 | 版权行（可占位）、文档 / GitHub / 许可 / 联系 链接占位 | P2 |

**层级原则**：P0 区块必须在无滚动或一次滚动内可见；全页最多一个 H1；区块间用间距与背景色差区分，不靠大量分割线。移动端顺序保持不变，不重排信息逻辑。

## 5. 关键交互

1. **导航锚点**：点击平滑滚动到对应区块；sticky 导航不得遮挡区块标题（需要预留偏移）。
2. **代码复制按钮**：点击后复制代码块文本，按钮文案变为「已复制」并在约 2 秒后复原；无 JS 时按钮可隐藏或退化不影响阅读。
3. **FAQ 折叠**：使用原生 `<details>/<summary>` 或按钮 + `aria-expanded`，键盘 Enter/Space 可操作，展开区域有可见状态；默认仅展开第一条。
4. **悬停/聚焦反馈**：按钮、卡片、链接有明确 hover 与 `:focus-visible` 态；焦点环不得被 `outline: none` 抹掉。
5. **渐进增强**：JS 仅负责复制与平滑滚动，脚本缺失时页面内容与信息完整可用。
6. **滚动入场（可选，低优先级）**：如需淡入，必须尊重 `prefers-reduced-motion: reduce`（此时禁用动画）。

## 6. 视觉方向

**气质**：工程师信任感 > 炫技。像一份被认真排版的技术文档，而不是 SaaS 营销页。冷静、克制、密度适中、留白充足。

- **配色**：深色或浅色二者择一并贯穿全页（建议：深色主调 + 单一高饱和强调色用于 CTA 与代码高亮的关键 token）。
  - 中性底（背景 / 卡片 / 分隔）×3 阶；
  - 文本（主 / 次 / 弱）×3 阶，正文对比度 ≥ 4.5:1，大标题 ≥ 3:1；
  - 强调色 1 个，最多再加 1 个功能性语义色（成功/警示），不引入第三种彩虹色。
- **字体**：无衬线正文 + 等宽字体用于代码与安装命令。字体只允许系统字体栈或单一外部字体（若引外部字体必须给出回退栈且不阻塞首屏）。字阶控制在 5–6 级，H1 与正文拉开明显差距。
- **布局**：单列内容 + 最大内容宽度约束（约 1080–1200px），居中；卡片区用 CSS Grid（2 或 3 列，移动端 1 列）；代码块与流程图允许突破到更宽容器。
- **形状与质感**：小圆角（≤ 12px）、极轻阴影或 1px 描边二者选一为主；不使用玻璃拟态、超大渐变和装饰性插图。
- **图标**：优先内联 SVG 或字符，不引图标库；图标仅作辅助，不替代文字。
- **动效**：只允许 ≤ 200ms 的过渡（hover、复制反馈、折叠）；不做视差与循环动画。
- **响应式断点**：移动（< 640px，单列，代码块可横向滚动）/ 平板（640–1024px）/ 桌面（> 1024px）。代码块在任何宽度下都不得撑破视口导致横向滚动整页。

## 7. 验收标准（可被逐条核验）

**结构 / 信息**
1. `index.html` 存在且仅一个 `<h1>`，包含产品名 "OwO Agent SDK"。
2. 第 4 节列出的 P0 区块（导航、Hero、核心能力、快速开始、原理图、收尾 CTA）全部存在，且页面自上而下顺序与第 4 节一致。
3. 页面包含至少一处真实可读的代码示例，且安装命令被标注为示例/占位，无明显伪造的数字指标。
4. 所有 CTA 与导航链接都有可点击目标（`#anchor` 或占位 `#` 并标注 `TODO`），不存在空 `<a>` 无 href。

**语义 / 可访问性**
5. 语义标签正确使用：`header/nav/main/section/footer`、区块有可读标题层级（h1→h2→h3，不跳级）。
6. 所有 `<img>`（如有）带 `alt`；内联 SVG 带 `role="img"` 或 `aria-hidden="true"` 二者之一。
7. 键盘可完成：Tab 遍历所有交互元素、可见焦点、FAQ 可展开、复制按钮可触发。对比度满足第 6 节数值。
8. 尊重 `prefers-reduced-motion`（若实现了动画）。

**样式 / 实现**
9. 样式全部位于 `styles.css`，`index.html` 中不出现 `style="..."` 内联样式块与 `<style>` 标签（极少量动态值除外，需在注释说明）。
10. `styles.css` 中有明确的 CSS 变量定义（颜色、间距、字号、圆角），颜色不散落硬编码。
11. 不引入第三方 CDN / 框架 / 图标库；JS 若存在，内联或独立小文件均可，但不得依赖网络资源。
12. 响应式：在 375px、768px、1280px 三个宽度下无整页横向滚动，导航与卡片布局不重叠、不裁切文本。

**可测性 / 自动化**
13. 提供 `node:test` 用例（如 `test/page.test.mjs`）以零依赖方式读取 `index.html` / `styles.css` 文本并断言：存在 `<h1>`、关键区块 id/标题存在、CSS 变量已定义、无 `<style>` 内联块、无第三方 `http(s)://` 资源引用、锚点目标存在。
14. 用例可用 `node --test` 直接跑通（无需安装依赖、无需网络）。

## 8. 非目标（明确不做）

- 不做后端、真实 API 调用、SDK 的 mock 服务端或任何网络请求。
- 不做多页站点、路由、博客、文档中心、定价页、登录/注册。
- 不接入构建工具（webpack/vite/React/Vue/Tailwind 等），不使用包管理与第三方依赖。
- 不做国际化、暗/亮主题切换器、搜索、分析埋点、Cookie 弹窗。
- 不做真实品牌资产：logo、真实客户 logo 墙、真实用户评价、真实基准数据。占位内容必须显式标注。
- 不承诺性能预算之外的优化（如 SSR、图片 CDN、字体子集化）。
- 不做复杂滚动动画、WebGL、Canvas 特效。

## 9. 给 designer 的落地提示（非硬性）

- 先定 CSS 变量表，再写区块，避免逐处调色。
- 代码块用「等宽字体 + 单色背景 + 左侧强调色竖线」即可获得高质感，无需语法高亮引擎。
- 原理图用纯 CSS 盒 + 箭头（伪元素/字符 `→`），保证零依赖且可响应式折行。
- 每个区块只承担一个信息职责；若某区块写不出「一句话目的」，就删掉它。
