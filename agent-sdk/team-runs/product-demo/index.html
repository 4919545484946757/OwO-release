Agent orchestration layer · v0.9

让智能体能力，成为你应用里的一个函数调用。

OwO Agent SDK 是目标驱动的智能体编排层：统一接口、权限内建、调用可审计。 它只负责循环本身，业务逻辑与数据始终留在你自己的系统里。

Capabilities

四项能力，覆盖智能体循环的全部关键点

模型、工具、状态管理被抽象成统一接口；危险操作默认阻塞待审批；每一步工具调用都有结构化事件，可打日志、可回放。

  • 统一接口

    把模型、工具与状态管理抽象成同一套接口，更换模型供应商时业务代码不需要改动。

  • 权限与审批

    危险工具调用默认阻塞等待审批，可按工具名与参数配置白名单，审批结果写入调用记录。

  • 可观测事件

    规划、工具调用、结果校正各自发出结构化事件，便于接入现有日志系统并回放一次完整运行。

  • 轻量无重依赖

    零重型运行时依赖，Node 18 及以上即可启动，也可部署在你自己的服务器上离线运行。

Quickstart

三步接入：安装、初始化、一次调用

下面的示例是完整可运行的最小流程，全程不需要配置文件，也不需要额外的构建步骤。

  1. 01 安装

    在项目根目录执行一次安装命令，SDK 只有一个包，不引入重型传递依赖。

  2. 02 初始化

    创建 Agent 实例并传入你要暴露给智能体的工具，其余能力按需开启。

  3. 03 调用

    用一句自然语言目标启动循环，SDK 负责规划、调用工具并在结果偏离目标时自行校正。

Why OwO

自带编排循环，而不是让你再拼一套

三种常见做法与本 SDK 的差别，集中在循环、权限与可验证性上。

维度 自己拼装 OwO Agent SDK
编排循环 自己实现重试、规划与结果校正，边界情况分散在业务代码里 循环内建，一次 run() 完成规划、执行与校正
权限控制 事后补审批逻辑，容易漏掉某个工具入口 权限内建，默认拒绝，白名单在初始化时声明
可审计性 黑盒运行，出问题只能靠散落的自定义日志 每步工具调用发出结构化事件，可回放整次运行

Security

安全边界写在配置里，不写在注释里

SDK 只做编排：它不托管你的数据，也不替你决定可以做什么。每个工具调用都要先通过权限判定。

权限审批流程

  1. 工具调用

    智能体请求调用某个工具，SDK 先把请求与参数交给权限判定。

  2. 审批

    命中白名单则放行；未声明或涉及写操作时阻塞，等待人工或策略批准。

  3. 执行

    批准后才真正执行，结果与审批记录一并写入事件流。

默认拒绝，显式授权

未在 tools 里注册的工具不可调用；已注册但被标记为敏感的工具仍需审批。

数据不出域

SDK 只负责编排，文件、数据库与业务服务都留在你的基础设施内，可自托管部署离线运行。

可回放的调用记录

每次运行都会产出带时间顺序的事件，包含工具名、参数摘要与审批结果，便于审计与问题定位。
