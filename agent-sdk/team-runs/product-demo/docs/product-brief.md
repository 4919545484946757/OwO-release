# Product Brief — OwO Agent SDK 官网单页（Landing Page）

## 0. 一句话定位
为开发者提供 **OwO Agent SDK** 的产品官网单页（`index.html` + `styles.css`），用一屏讲清"它是什么、解决什么问题、三行代码怎么接入"，最终由一个 Node 内置测试（`node:test`）对产物做自动化验收。

## 1. 目标用户

| 优先级 | 人群 | 现状/痛点 | 期望从本页得到 |
| --- | --- | --- | --- |
| P0 | 应用开发者（前端/全栈，1–5 年经验） | 想给产品加智能体能力，但 SDK 生态碎片化、概念多、上手成本高 | 30 秒内判断"这是不是我要的 SDK"，并拿到可复制的接入代码 |
| P0 | 技术决策者 / 团队 Tech Lead | 需要评估依赖安全性、可控性与可维护性 | 安全边界、权限模型、运行时可预期性的明确说法 |
| P1 | 独立开发者 / 开源贡献者 | 想要轻量、无重型依赖的方案 | 包体积/依赖极少、可自托管、文档与仓库入口 |
| P2 | 已有 OwO 用户 | 想了解新版本能力 | 变更亮点与升级路径 |

**非目标用户**：非技术终端消费者、只看价格的采购角色——本页不做销售话术。

## 2. 核心信息（必须被访客记住的三件事）

1. **能力**：OwO Agent SDK 让开发者用统一接口把"理解目标 → 规划 → 调用工具 → 校正结果"的智能体循环嵌进自己的应用。
2. **省事**：接入成本极低——安装 + 初始化 + 一次调用即可跑通（示例控制在 3–5 行）。
3. **可控**：工具调用走权限审批、副作用可审计；SDK 只做编排，业务逻辑与数据始终留在开发者自己的系统里。

**价值支柱（按页面主次排列）**
- 统一接口：模型/工具/状态管理抽象掉，换供应商不改业务代码。
- 人在环上：危险操作默认阻塞待审批，可配置白名单。
- 可观测：每一步工具调用有结构化事件，便于打日志与回放。
- 轻量：零重型运行时依赖，Node 环境即可启动。

**一句话主标题方向（供 designer 参考，文案可再润色）**
> 让智能体能力，成为你应用里的一个函数调用。

**副标题方向**
> OwO Agent SDK — 目标驱动的智能体编排层：统一接口、权限内建、调用可审计。

## 3. 页面层级（信息架构，单页纵向滚动）

```
Header（吸顶）
├─ Logo / 产品名：OwO Agent SDK
├─ 导航：能力 Capabilities · 代码示例 Quickstart · 安全 Security · 文档 Docs
└─ 主 CTA：开始使用 / GitHub

1. Hero
   ├─ 主标题（一句话价值）
   ├─ 副标题（1–2 行，说明编排层定位）
   ├─ 双 CTA：主按钮「快速开始」+ 次按钮「查看文档」
   └─ 视觉：等宽字体的最小代码片段卡片（可选，但要为骨架）

2. 能力概览 Capabilities（3–4 个卡片）
   ├─ 统一接口
   ├─ 权限与审批
   ├─ 可观测事件
   └─ 轻量无重依赖

3. 快速开始 Quickstart（核心区块）
   ├─ 三步说明：安装 → 初始化 → 调用
   ├─ 代码块（带语言标签，可禁用高亮）
   └─ 复制按钮（可仅视觉，或复制纯文本）

4. 为什么是 OwO（对比/差异化，简版表格或三列）
   ├─ 自带编排循环 vs 自己拼装
   ├─ 权限内建 vs 后补
   └─ 事件可审计 vs 黑盒

5. 安全与可控 Security
   ├─ 权限审批流程说明（工具调用 → 审批 → 执行）
   ├─ 默认拒绝、显式授权
   └─ 数据不出域（自托管说明）

6. 页脚 Footer
   ├─ 文档 / 仓库 / 变更日志 链接
   ├─ 许可证说明
   └─ 版权行（当前年份可硬编码或占位）
```

**层级原则**：Hero 必须在首屏无滚动时完整可见（标题 + 副标题 + 双 CTA + 代码卡片顶部）；Quickstart 是第二视觉焦点；安全区块承担信任背书，不能折叠进页脚。

## 4. 关键交互

| 交互 | 触发 | 行为 | 备注 |
| --- | --- | --- | --- |
| 吸顶导航跳转 | 点击导航项 | 平滑滚动到对应 `id` 锚点 | 需 `scroll-behavior: smooth` + `scroll-margin-top` 偏移吸顶高度 |
| 主 CTA | 点击「快速开始」 | 滚动到 Quickstart 区块 | 静态站，无后端 |
| 复制代码 | 点击代码块复制按钮 | 复制纯文本代码，按钮短暂显示"已复制" | 至少要有按钮与可访问名称 |
| 卡片悬停 | hover/focus-visible | 轻微上浮 + 边框/阴影变化 | 只用 CSS，不依赖 JS 动画库 |
| 键盘可访问 | Tab | 所有链接/按钮有清晰 `:focus-visible` 焦点环 | 焦点环对比度必须达标 |
| 响应式折叠 | 视口 < 768px | 导航项收敛（横向滚动或窄间距），Hero 与卡片改单列 | 不要求 JS 汉堡菜单 |
| 减动效偏好 | `prefers-reduced-motion: reduce` | 关闭平滑滚动与位移动画 | 可访问性必需 |

**不做**：表单提交、账号体系、实时 demo 调用、暗色/亮色切换开关（可只提供暗色或亮色单一主题，若做切换则属额外范围）。

## 5. 视觉方向

- **风格**：开发者工具风格（technical / 克制的未来感），干净、重排版、少装饰；避免廉价渐变和营销式插画。
- **配色**：深色底为主（接近 `#0B0E14` 的深灰蓝），主要文本高亮为浅灰白；一个强调色（青绿或电光蓝）只用于 CTA 与关键数字/高亮，强调色面积 < 10%。
- **字体**：标题用现代无衬线（系统栈优先：`Inter` ⇢ `-apple-system` ⇢ `Segoe UI`）；代码用等宽栈（`JetBrains Mono` ⇢ `ui-monospace` ⇢ `Menlo`）。不引入外部字体文件时用系统栈即可。
- **排版**：正文行宽 ≤ 72 字符；标题层级差明显（H1 ≥ 2.5rem，H2 ≈ 1.75rem，正文 ≈ 1rem，行高 1.5–1.6）。
- **栅格与间距**：12 列/最大内容宽 1120px 居中，左右内边距 24px（移动）/ 32px（桌面）；垂直节奏用 8px 基数，区块间距 64–96px。
- **组件质感**：卡片圆角 12px、1px 低对比边框、极轻阴影；代码块用略深的底色与顶部标签栏，模拟编辑器观感。
- **动效**：仅 hover/focus 与一次轻量淡入；时长 150–200ms；尊重 reduced-motion。
- **文案语气**：陈述事实、给具体能力，不用感叹号与夸张形容词。

## 6. 验收标准（可被 `node:test` 机械化检查）

**A. 文件与结构**
1. 工作区存在 `index.html` 与 `styles.css` 两个文件，均非空。
2. `index.html` 引用 `styles.css`（`<link rel="stylesheet" href="styles.css">`）。
3. `index.html` 含 `<!doctype html>`、`<html lang="en">`（或明确的 `lang` 值）、`<head>` 内的 `<title>` 与 `<meta name="viewport" content="width=device-width, initial-scale=1">`。

**B. 必备区块（以 `id` 或语义标签存在）**
4. 存在 `header`/`nav`，导航含至少 3 个指向页内锚点的链接（`href="#..."`）。
5. 存在 `#hero`（或首屏 `h1`）、`#capabilities`、`#quickstart`、`#security`、`footer`。
6. 页面有且仅有一个 `<h1>`；标题层级不跳级（h1 → h2 → h3）。

**C. 内容要求**
7. Hero 含主标题与副标题，且含至少 2 个 CTA（链接或按钮）。
8. Capabilities 至少 3 个条目，每条含标题与一句描述。
9. Quickstart 含一段代码（`<pre><code>`），且代码里出现 `npm i`（或 `npm install`）与 `owo` 包名/导入语句。
10. Security 区块列出权限审批与"默认拒绝/显式授权"的说明文本。
11. footer 含文档与仓库链接（可为 `#` 占位但要有可读文本）与版权行。

**D. 可访问性与样式**
12. 所有 `<img>`（若有）有 `alt`；纯装饰 SVG 有 `aria-hidden="true"`。
13. 所有可交互元素（`a`、`button`）有可读文本或 `aria-label`。
14. 复制按钮存在时带 `type="button"` 与可读标签。
15. `styles.css` 含至少一处媒体查询（`@media`）与 CSS 自定义属性（`--`）定义的配色/间距 token。
16. `styles.css` 含 `:focus-visible` 规则与 `prefers-reduced-motion` 媒体查询。
17. 不引用任何外部 CDN 脚本/样式（测试可断言 HTML 中无 `http://`、`https://` 的资源引用，允许纯文本链接）。

**E. 测试本身**
18. 存在使用 `node:test` + `node:assert` 的测试文件（如 `test/page.test.js`），可通过 `node --test` 运行，逐条覆盖上述 A–D 断言，且全部通过。

## 7. 非目标（明确不做）

- 不做多页站点、路由、SPA 或构建工具链（无 bundler、无框架、无 npm 依赖用于页面本身）。
- 不做后端、真实 API 调用、账号/鉴权流程。
- 不写营销式长文案、不做客户 Logo 墙、不做价格表与表单收集。
- 不引入外部字体/CDN/分析脚本（离线可打开）。
- 不做多语言（单语即可）、不做暗色/亮色主题切换、不做复杂动画与粒子背景。
- 不追求完整 SEO/OG 图片生成，不接入 CI。

## 8. 给 designer 的交接要点

- 先搭 HTML 语义骨架（区块 `id` 与 B 组验收一一对应），再写 `styles.css`，保证 A–D 每条验收都能被静态断言命中。
- 内容优先：所有段落文案必须真实可读，禁止 `Lorem ipsum` 与"TODO"。
- 代码示例建议：
  ```js
  npm i owo-agent-sdk
  ```
  ```js
  import { Agent } from "owo-agent-sdk";
  const agent = new Agent({ tools: { readFile } });
  await agent.run("整理这份周报");
  ```
- 若时间有限，优先级：Hero + Quickstart + 验收条款 → 其余区块 → 视觉打磨。
