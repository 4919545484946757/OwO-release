# OwO Agent SDK — Product Brief（落地页产品简报）

> 本文件是交付链路的**唯一需求事实源**，供 designer / frontend / test 直接引用。任何页面结构、文案、交互或验收口径在实现中出现分歧时，以本文件为准。
> 状态：v2（researcher 产出，未经用户确认；v2 新增第 3.1 节“占位文档链接位”的可测试定义，并同步修订第 3、4、5、7 节相关条目，用于修复占位文档落点草率实现的问题）

## 1. 产品与交付物概述

- **产品**：OwO Agent SDK —— 一个 SDK 产品（开发者工具）。本简报不臆造未确认的商业细节；文案必须保持在"面向开发者的 SDK 能力"这一层面。
- **本次交付物**：一个**单页产品落地页（single-page product landing page）**，由三个文件构成：
  - `index.html` —— 页面结构与内容（唯一页面，不引入路由）。
  - `styles.css` —— 全部样式（响应式、可访问性视觉状态）。
  - `node:test` 测试文件 —— 覆盖页面结构与可访问性的自动化测试（具体文件名由实现者确定并在交付说明中声明）。
- **质量红线**：页面必须**可访问（accessible）**、**响应式（responsive）**、并且**可验证（verifiable tests）**。三者都是硬性验收项，不是加分项。

## 2. 目标用户

### 2.1 主要用户（必须服务好）
| 用户 | 场景 | 页面必须回答的问题 |
| --- | --- | --- |
| 评估中的开发者（backend / full-stack） | 在社区或搜索中听到 OwO Agent SDK，打开落地页快速判断是否值得接入 | 它是什么？解决什么问题？接入成本多大？怎么开始？ |
| 技术团队负责人 / 技术选型者 | 需要向团队解释为什么要选它 | 关键能力有哪些？边界在哪？是否有可靠文档与可运行的起步路径？ |

### 2.2 次要用户（必须不阻碍）
- **有辅助技术依赖的用户**（屏幕阅读器、键盘操作、低视力、动效敏感、认知负荷敏感）：必须能完整读取信息并完成所有操作。
- **移动端访客**：在窄屏上浏览，主要目标是"看懂 + 找到入门入口"。
- **非技术决策者**：只读首屏与能力概览，需在最少的滚动内获得结论。

### 2.3 反用户（不在目标范围）
- 需要多语言（i18n）内容、需要账号登录 / 仪表盘 / 定价计算器的访客 —— 见第 8 节非目标。

## 3. 核心信息（Message Hierarchy）

按优先级排列，**顺序不可调换**（首屏所及 = 第一 + 第二层）：

1. **一句话定位（what + for whom）**：OwO Agent SDK 让开发者用少量代码构建可编排、可观测的 agent 能力。—— 必须作为首屏 H1 的**可见文本**出现（H1 可以只承载这一句，也可以在此句之后追加短语；但该句必须完整、连续地出现在 H1 元素内，且**不得**仅出现在 `<title>` 或副标题里）。
2. **为什么值得试（value）**：3–4 条能力要点，每条一句话，动词开头，不堆砌形容词。
3. **可信度**：可验证的接入路径（安装 / 初始化 / 运行三段），以及指向文档的说明性链接位 —— 该链接位必须落在**第 3.1 节定义的唯一“占位文档落点”**上（本页不提供真实文档站，故以页内占位锚点承载）。
4. **行动召唤（CTA）**：一个主 CTA（"开始接入 / Get started"）+ 一个次 CTA（"阅读文档 / Read the docs"），全页至少出现一次，首屏必须出现。次 CTA 的 `href` 必须指向第 3.1 节的占位文档落点 id；主 CTA 指向 `#quickstart`。

### 3.1 占位文档链接位（Placeholder Docs Slot）—— 可测试定义

本页**不引入真实外部文档链接**（见第 8 节），但"阅读文档"这条信息路径必须存在且可被识别。为了让 designer / frontend / test 三方对"次 CTA 指向哪里"有唯一口径，定义如下**强制**形态：

| 项 | 规定值 / 要求 |
| --- | --- |
| 落点元素 | 一个块级元素（建议 `<p>` 或 `<div>`），位于 **Quickstart 区块**内、`<ol>` 步骤列表**之后**，属于 Quickstart `<section>` 的子内容 |
| 唯一 id | `id="docs-placeholder"` —— **全文档只能出现一次**，且仅由该落点元素持有 |
| 可见占位标注 | 落点元素自身的可见文本必须包含字面量 `占位链接位`（用于人工与测试双重识别），例如："文档说明位 · 占位链接位（真实文档站未在本次交付中提供）" |
| 链接目标 | 落点元素内至少 1 个链接（即"文档说明性链接"），其 `href` 指向**页内已存在且唯一**的锚点：`#docs-placeholder-note`，且文档中存在 `id="docs-placeholder-note"` 的元素承载"文档尚未发布"的说明文字 |
| 消费方 | 次 CTA（Hero 内的"阅读文档"）、Quickstart 内的文档说明链接、Footer 中的文档链接位，三者的 `href` **全部**等于 `#docs-placeholder` |
| 禁止形态 | ① 指向自身（`href` 与所在元素或最近祖先的 `id` 相同）；② `href="#"` 或空 `href`；③ 指向 `#quickstart`、`#features`、`#faq`、`#top` 等已有语义区块来"顶替"文档落点；④ 指向任何 `http(s)://` 外部地址 |
| 可访问名称 | 链接可见文案须可自解释（如"阅读文档（本页占位链接位）"）；若加 `aria-label`，不得弱化或推翻"占位"这一事实 |

**为什么这样定义**：占位文档位是"信息路径存在"的证据，而不是装饰。自指锚点（链接跳到它自己）会让键盘用户的焦点原地跳动、没有位移信息，等于假链接；把它指到已有功能区块则会让"阅读文档"的语义失真。因此本页采用 **一个独立 id + 一处可见占位标注 + 链接指向另一个说明性 id** 的最小可测形态，既不需要外部资源，也能被 `node:test` 静态断言。

### 3.2 文案纪律
- 不使用未经证实的数字（用户量、性能倍率、融资、客户 logo）—— 本简报未授权任何具体数字。
- 不使用"革命性 / 颠覆 / 最强"等不可验证的营销形容词。
- 中文为主文案，必要时可保留英文技术关键字（如 SDK、agent、API）；**同页不混排两套完整语言**。
- 代码示例必须是可读的最小片段（安装命令 + 一次调用），并且必须用语义化 `<code>`/`<pre>` 承载。

## 4. 页面层级（Sections，自上而下）

单页结构，必须包含以下 6 个区块，按此顺序；每个区块必须以可被测试识别的语义地标（`<header>`/`<main>`/`<section>`/`<footer>` + 可访问名称）呈现。

| # | 区块 | 语义角色与要求 | 必须包含内容 |
| --- | --- | --- | --- |
| 1 | **Site header / 导航** | `<header>` 内含 `<nav aria-label>` | 产品名（可回链到 `#top`）、指向主要区块的锚点链接（至少"能力""接入""FAQ"三项）、至少一个 CTA |
| 2 | **Hero 首屏** | `<main>` 内第一个 `<section>`，带可访问名称 | 唯一 `<h1>`（其可见文本含第 3 节第 1 条定位句）、短副文案（≤ 2 行）、主 CTA + 次 CTA（次 CTA `href="#docs-placeholder"`，见 3.1）、可选的纯装饰视觉（必须 `aria-hidden="true"` 或空 `alt`） |
| 3 | **核心能力 / Features** | `<section aria-labelledby="features-heading">` | `<h2>` + 3–4 个能力项；每项 = 标题 + 一句话说明；语义上使用列表结构（`<ul>/<li>` 或等价的卡片列表），**不要**只用裸 `<div>` 堆砌 |
| 4 | **如何开始 / Quickstart** | `<section aria-labelledby="quickstart-heading">` | 有序步骤（`<ol>`）3 步：安装 → 初始化 → 运行；含 1–2 个代码块；含**第 3.1 节定义的占位文档落点**（`id="docs-placeholder"`，位于 `<ol>` 之后，含可见"占位链接位"标注与 `#docs-placeholder-note` 链接） |
| 5 | **FAQ** | `<section aria-labelledby="faq-heading">` | 3–5 个问答；推荐 `<details>/<summary>` 原生折叠（天然键盘可达），否则必须手写 `aria-expanded` + `aria-controls` |
| 6 | **Footer** | `<footer>` | 产品名、版权行、文档 / 仓库等说明性链接位；文档链接位 `href="#docs-placeholder"`，仓库类链接位若保留则必须标注为占位或使用可识别占位值（不得指向外部真实站点） |

**层级规则**
- 标题层级严格：1 个 `<h1>`，各区块 `<h2>`，区块内子项 `<h3>`；**不得跳级**（禁止 h1 → h3）。
- 每个 `<section>` 必须有可访问名称（`aria-labelledby` 指向本区块标题），以便屏幕阅读器地标列表可导航。
- 页面根元素需有"跳到主内容"（skip link）作为第一个可聚焦元素，目标为 `<main>`。
- 不引入多页面路由、Tab 面板、轮播等重交互组件。

## 5. 关键交互

| 交互 | 触发方式 | 期望行为 | 可访问性约束 |
| --- | --- | --- | --- |
| Skip link | 首次 `Tab` | 显现并获得焦点，`Enter` 后焦点落到 `<main>` | 焦点样式可见；未聚焦时视觉隐藏但仍可聚焦（不用 `display:none`） |
| 导航锚点滚动 | 点击导航项 | 平滑滚动到目标区块 | 尊重 `prefers-reduced-motion: reduce` 时退化为瞬时跳转；目标区块需能接收焦点（`tabindex="-1"`） |
| 主 CTA 点击 | 点击主 CTA | 滚动到 Quickstart（`href="#quickstart"`） | 用 `<a>` 承载链接语义（不用 `<button>` 模拟跳转）；可见文案与可访问名称一致 |
| 次 CTA 点击（文档） | 点击次 CTA / Quickstart 文档链接 / Footer 文档链接位 | 焦点与视口移动到占位文档落点（`#docs-placeholder`），用户能看到"这是占位链接位"的显式说明 | 落点必须**不是**链接自身或其祖先（禁止自指）；落点元素获焦后需有可见焦点环（`target` 元素可给 `tabindex="-1"` 以便程序化聚焦）；`aria-label` 不得与可见文案矛盾 |
| 占位文档落点内链接 | 点击落点内"文档尚未发布"说明链接 | 跳到 `#docs-placeholder-note` 的说明文字 | 目标 id 存在且唯一；不得为空 `href` 或 `href="#"` |
| FAQ 展开/收起 | 点击 / `Enter` / `Space` | 展开对应答案；可多开 | `<details>/<summary>` 优先；自定义实现必须维护 `aria-expanded` 与焦点可见 |
| 移动端导航 | 窄屏 | 导航项可换行或收纳为"菜单"按钮 | 若用菜单按钮：必须 `aria-expanded` + `aria-controls`，且展开后焦点可见、Esc 可关闭 |
| Hover / Focus 反馈 | 鼠标悬停 / 键盘聚焦 | 卡片与链接给出明确反馈 | `:focus-visible` 必须比 `:hover` 更醒目；不得仅靠颜色传达状态 |
| 响应式重排 | 视口变窄 | 多列能力卡片 → 单列；导航 → 可换行/收纳 | 不得出现横向滚动条（任何断点下 `body` 宽度不溢出） |

**全页必须满足的交互底线**
- 全部操作可用键盘完成，无键盘陷阱，Tab 顺序符合视觉顺序。
- 触控目标最小 44×44 CSS px（按钮与导航链接）。
- 尊重 `prefers-reduced-motion` 与 `prefers-color-scheme`（暗色模式可选但推荐；若实现，对比度同样需达标）。

## 6. 视觉方向（Design Direction）

- **气质**：开发者工具的可信、克制、精确。避免闪亮的营销渐变堆叠。
- **布局**：单列流式阅读为主，内容最大宽度约 `1100–1200px`，正文行宽约 `60–75ch`；区块间留白充足，用间距而非分割线制造层级。
- **色彩**：一个主色（品牌）+ 中性灰阶 + 一个强调色（仅用于 CTA 与焦点环）。CTA 与背景对比度 ≥ 4.5:1（正文文本 ≥ 4.5:1，大字号 ≥ 3:1）。不得用低对比灰做正文。
- **字体**：系统字体栈或无外部依赖的字体；标题与正文最多两级字号体系 + 一个代码等宽字体；字号使用 `rem`，正文基准不小于 `1rem`。
- **形状与深度**：圆角与细边框为主，阴影克制；卡片用边框区分而非重阴影。
- **占位文档落点的视觉**：建议用一条左侧强调边或浅底 + 细边框的"说明条"呈现，使其在步骤列表之后明显是**注释性内容**而非第 4 个步骤；"占位链接位"字样必须以可读文本呈现（不得只放在 `title`/`data-*`/注释里），且其文本对比度 ≥ 4.5:1。
- **装饰图形**：允许纯装饰（如网格、渐变光斑），但必须 `aria-hidden="true"`，且不得降低文本对比度，且不得引发布局抖动（预留固定尺寸）。
- **动效**：仅限进场淡入/位移、悬停过渡，时长 ≤ 200ms；`prefers-reduced-motion: reduce` 下全部禁用。
- **禁止**：外部图片与外部字体 CDN（离线可渲染）；自动播放视频；仅用颜色区分状态的组件；`!important` 滥用。

## 7. 验收标准（Acceptance Criteria，逐条可测）

> 编号供 test 角色直接映射为测试用例；建议以 `node:test` 读取 `index.html`/`styles.css` 文本并做结构断言，无需浏览器环境。

**内容与结构**
- A1 `index.html` 是完整 HTML5 文档（含 `<!doctype html>`、`<html lang>`、`<meta charset>`、`<meta name="viewport">`、有意义的 `<title>`）。
- A2 存在恰好 1 个 `<h1>`；标题层级不跳级（h1 → h2 → h3）。
- A3 第 4 节所列 6 个区块全部存在，且每个 `<section>` 都有可访问名称（`aria-labelledby` 指向存在的 `id`）。
- A4 页面包含首个可聚焦的 skip link，其 `href` 指向 `<main>` 的 `id`。
- A5 页内所有 `href="#..."` 锚点都在文档中解析到已存在的 `id`；不存在空 `href` 或 `href="#"`。
- A6 主 CTA 与次 CTA 各至少出现一次，且首屏区块内各出现至少一次。
- A7 Quickstart 区块含 `<ol>` 且步骤数为 3，含至少一个 `<pre><code>`。
- A8 FAQ 含 3–5 个问答项（`<details>/<summary>` 或等价带 `aria-expanded` 的控件）。
- **A21 占位文档落点存在且唯一**：`index.html` 中 `id="docs-placeholder"` 恰好出现 1 次；该元素位于 Quickstart `<section>` 内、`<ol>` 之后（DOM 顺序断言：`docs-placeholder` 的出现位置在 `quickstart-heading` 之后、`</section>` 之前，且在 `<ol>` 闭合之后）。
- **A22 可见占位标注**：`docs-placeholder` 元素的可见文本（去掉标签与注释后）包含字面量 `占位链接位`。
- **A23 文档链接目标合法**：`docs-placeholder` 元素内含至少 1 个 `href="#docs-placeholder-note"` 的 `<a>`，且文档中存在唯一 `id="docs-placeholder-note"`。
- **A24 禁止自指/顶替**：任何 `href="#docs-placeholder"` 的 `<a>` 都不是 `docs-placeholder` 元素本身或其祖先；任何文档类链接/CTA（文案含"文档"或 `class` 含 `docs`/`btn--secondary` 的锚点）的 `href` 不等于 `#`、`""`、`#quickstart`、`#features`、`#faq`、`#top`。
- **A25 H1 承载定位句**：`<h1>` 的去标签可见文本中连续包含第 3 节第 1 条定位句（允许前后有附加短语，但该句不得被拆分到 H1 之外）。

**样式与响应式**
- A9 `index.html` 通过相对路径引用了 `styles.css`，且 `styles.css` 非空。
- A10 `styles.css` 含视口断点（至少一个 `@media`），窄屏下能力列表为单列（测试可断言存在窄屏断点规则）。
- A11 存在 `:focus-visible`（或等价的显式焦点样式）规则，且焦点样式不是仅改 `outline: none` 而无替代。
- A12 存在 `@media (prefers-reduced-motion: reduce)` 规则。
- A13 不引用任何外部域名资源（无 `http://` / `https://` 的 `src`/`href` 到第三方静态资源）。

**无障碍静态可检项**
- A14 每个 `<img>`（若存在）都有 `alt` 属性；纯装饰图为 `alt=""` 或 `aria-hidden="true"`。
- A15 每个表单控件（若存在）有关联 `<label>` 或 `aria-label`；本页不应有需要提交的表单。
- A16 语言属性已设置，`<title>` 非空且能描述产品与页面目的。
- A17 文本颜色对比度满足 WCAG 2.1 AA（实现者需在交付说明中记录对主文本色 / 背景色、CTA 前景 / 背景色，以及占位说明条文本/背景色的对比度数值）。

**工程与测试**
- A18 测试使用 `node:test`（`import { test } from 'node:test'` 或 `require('node:test')`），可通过 `node --test` 运行且全部通过、无跳过（`skip` 不用于覆盖 A1–A17 / A21–A25 的断言）。
- A19 测试断言覆盖 A1–A3、A5、A7、A8、A9、A11、A14、**A21–A25** 这些结构项（数量可合并为多条测试）。
- A20 无任何运行时外部依赖（不引入 CDN 脚本、不引入 npm 运行时依赖用于页面渲染）。

## 8. 非目标（Out of Scope，明确不做）

- 多语言 / i18n 切换、RTL 布局。
- 多页面站点、路由、客户端框架（React/Vue 等）、构建步骤、打包配置。
- 真实后端、表单提交、注册登录、支付、定价计算器。
- **真实文档站 / 真实仓库链接**：本次交付只用第 3.1 节定义的页内占位文档落点承载"文档"信息路径，不提供可用的外部文档或仓库地址。
- 真实外部链接与外部资源（字体、图片、分析脚本、cookie 横幅）。
- 动画库、图表库、图标字体。
- 暗色模式切换控件（若实现暗色，仅通过 `prefers-color-scheme` 自动适配，不加切换按钮）。
