OwO Agent SDK · 多成员智能体团队

把一次需求，拆给一支可核对的智能体团队

OwO Agent 由 SDK 驱动的研究员、设计师、实现者与评审者组成，围绕同一个项目空间协作。 每一步都留下版本化产物、证据来源与验收记录，你随时可以回到任意一版核对它到底做了什么。

Capabilities

六项能力，把「说得对」变成「验得过」

每一项都对应工程流里的一个具体环节，而不是演示用的效果图。

  • 01

    任务拆解与角色分工

    把一条目标拆成带验收条件的子任务，分配给研究员、设计师、实现者与评审者。

  • 02

    版本化共享产物

    每个产物带 revision 与内容哈希，下游读到的是确定的某一版，而不是「大概那份」。

  • 03

    源码级落盘与补丁

    变更以精确补丁或整文件写入真实文件系统，基线哈希不匹配就拒绝覆盖。

  • 04

    测试与验收登记

    先登记验证计划，再跑定向检查；计划本身不算通过证据，只有实际结果算。

  • 05

    人类审批闸口

    写文件、跑命令等敏感动作需要你点同意，拒绝之后不会用同样参数重试。

  • 06

    跨会话事实同步

    共享事实按 revision 发布与冲突检测，冲突时重读再写，不静默覆盖别人的结论。

Workflow

四步协作流程

从一句话目标到可交付结果，每一步都有明确的输入与输出。

  1. 1

    理解目标

    先把需求读成可执行的约束清单：输入、期望结果、不允许做的事项。

    产出 约束与目标陈述

  2. 2

    分工执行

    按角色分配任务，各成员只在自己被允许的路径里动手。

    产出 任务与写入白名单

  3. 3

    产物共享

    结论以版本化产物发布到项目空间，下游按 artifact 引用读取对应版本。

    产出 artifact v1 / v2 / …

  4. 4

    校验交付

    按验收条件跑定向检查，评审者给出结论，未验证部分显式标注。

    产出 证据与评审结论

Trust & Evidence

为什么可以核对

三条可验证性设计，对应三种常见的「看起来做完了」风险。

可验证性设计对照表
机制 解决的风险 你看到的东西
版本化产物 下游读到过期或被改写的内容 revision、内容哈希、发布者与时间
审批闸口 敏感操作未经确认就发生 待审批动作列表与拒绝后的收尾说明
证据留存 把计划当成已通过的验收结果 检查命令、实际输出与未验证项清单

Docs · Quick Start

三步接入

示例以 Node 环境的本地项目为基准，整个站点本身也无需联网即可打开。

  1. 1 · 初始化项目并安装 SDK

    npm init -y
npm install owo-agent-sdk

  2. 2 · 在项目空间注册角色

    const team = await owo.team.create({
  roles: ["researcher", "designer", "builder", "reviewer"]
});

  3. 3 · 提交目标并等待可核对产物

    const task = await team.dispatch({
  goal: "写一个可离线打开的静态介绍页",
  accept: ["index.html 非空", "无外部依赖"]
});

从一条目标开始

先跑通一个小需求：单页站点、无外部依赖、带验收断言。跑通之后再谈扩展。
