# OwO Agent 产品简报（Product Brief）

> 交付对象：designer（页面设计与视觉方向）、builder（index.html / styles.css 实现）、qa（node:test 验收用例）
> 状态：工作区当前为空（无既有 index.html / styles.css / 测试文件），本简报为从零搭建静态站点的唯一规格输入。

---

## 1. 产品定位与核心信息

**一句话定位**：OwO Agent 是一个「面向开发者的智能体编排与协作平台」的对外介绍站点——用一页式官网讲清它是什么、解决什么问题、如何开始。

**核心信息（按优先级）**
1. **是什么**：OwO Agent SDK 驱动的多成员智能体团队，围绕共享项目空间协作，把"一个需求"拆给研究员、设计师、实现者、评审者并行推进。
2. **解决什么问题**：单模型一次性输出难以交付可验证的工程结果；OwO Agent 用「版本化共享产物 + 宿主校验 + 定向验证」让每一步产出可追溯、可核对。
3. **关键能力（3–6 条）**：任务拆解与角色分工、版本化共享产物（artifact）、源码级文件落盘与补丁、测试与验收登记、人类审批闸口、跨会话事实同步。
4. **为什么可信**：每个结论都带证据来源（source / note），未验证的部分显式标注，不把"计划"说成"已通过"。
5. **行动召唤（CTA）**：主 CTA「查看文档 / Get Started」，次 CTA「浏览示例工作流」。

**目标用户**
- 主要：需要把 LLM 能力接入真实工程流程的开发者 / 技术负责人。
- 次要：评估智能体平台的技术决策者（关注可审计性、权限边界、失败可观测性）。
- 非目标：纯 C 端消费者、低代码零代码小白用户（首版不做引导式向导）。

## 2. 页面层级（单页 index.html 结构）

```
Header（固定顶栏）
 ├─ Logo / 产品名 "OwO Agent"
 ├─ 导航：Overview · Capabilities · Workflow · Docs
 └─ 右侧 CTA 按钮 "Get Started"
Hero（首屏）
 ├─ H1 主标题 + 一行副标题
 ├─ 双 CTA（主/次）
 └─ 右侧产品可视化（工作流节点图 / 任务卡片流，可用纯 CSS/SVG 绘制）
Capabilities（能力网格）
 └─ 3 列 × 2 行卡片，每卡：图标位 + 标题 + 一句说明
Workflow（协作流程）
 └─ 4 步横向时间线：理解目标 → 分工执行 → 产物共享 → 校验交付
Trust / Evidence（可验证性）
 └─ 三段：版本化产物 · 审批闸口 · 证据留存（可配对比小表）
Quick Start（上手段）
 └─ 3 行代码/步骤块 + 复制按钮位置（复制功能为可选增强，非首版必须）
Footer
 └─ 链接组（Docs / GitHub / Status）+ 版权行
```

**层级规则**
- 单页锚点导航，锚点 ID：`#overview`、`#capabilities`、`#workflow`、`#docs`。
- DOM 语义化：`header / main / section / footer`，每个 section 有 `aria-labelledby` 指向其标题。
- 页面只允许一个 `h1`，section 标题用 `h2`，卡片标题用 `h3`。

## 3. 关键交互

| 交互 | 行为 | 优先级 |
|---|---|---|
| 顶栏导航锚点 | 平滑滚动到对应 section；当前 section 高亮（可用 `:target` 或 JS 观察器） | P0 |
| 主 CTA | 跳转 `#docs`（首版不接外链） | P0 |
| 卡片 hover | 轻微上浮 + 边框高亮，transition ≤ 200ms | P0 |
| 移动端汉堡菜单 | 视口 < 768px 显示，展开为纵向列表，可点击外部关闭 | P0 |
| 键盘可达性 | 所有可点击元素可 Tab 聚焦，`:focus-visible` 有清晰轮廓 | P0 |
| 复制按钮 | 复制快速开始代码块到剪贴板 | P1（可延后） |
| 轻量滚动进入动画 | `prefers-reduced-motion` 下必须禁用 | P2 |

**明确的交互边界**：首版无登录、无后端请求、无表单提交；所有 CTA 均为页内锚点或占位链接。

## 4. 视觉方向

- **气质**：工程师取向的克制、精确、有技术密度；避免营销感的夸张渐变和大插图。
- **色彩**：深色优先（深底 `#0e1116` 一类中性冷灰），单一强调色（建议青绿或电蓝）用于 CTA、链接、关键数据；语义色仅用于状态标记。
- **对比度**：正文文字与背景对比度 ≥ 4.5:1，大标题 ≥ 3:1（WCAG AA）。
- **字体**：无衬线系统字体栈优先（`-apple-system, "Segoe UI", Roboto, sans-serif`），代码块用等宽栈；不使用需要联网加载的网络字体（站点必须可离线打开）。
- **排版节奏**：Hero 标题 48–64px（桌面）/ 32–40px（移动）；正文 16px / 行高 1.6；间距使用 8px 基准刻度。
- **布局**：内容最大宽度约 1100–1200px 居中，最小内边距 20px；能力网格桌面 3 列 → 平板 2 列 → 移动 1 列。
- **图形语言**：用 CSS/SVG 绘制抽象节点图、网格线、等宽小标签（如 `v0.1`、`artifact`），体现"版本化产物"的产品气质。
- **禁止**：外部图片/CDN 资源、自动播放视频、纯色块堆砌式大图。

## 5. 验收标准（供 qa 用 node:test 断言）

以 node:test 对生成的 `index.html` / `styles.css` 做静态断言（读文件 + 字符串/结构匹配，或 JSDOM，如无依赖则用字符串断言）：

1. **文件存在且非空**：`index.html`、`styles.css` 均存在，字节数 > 0。
2. **文档骨架**：`index.html` 含 `<!DOCTYPE html>`、`<html lang="zh-CN">` 或 `lang="en"`、`<head>` 内含 `<meta name="viewport">` 与 `<title>`。
3. **结构与语义**：恰好一个 `<h1>`；存在 `header`、`main`、`footer`；两个 CTA 按钮文本匹配 `/Get Started/i` 与 `/文档|Docs/i`。
4. **层级完整**：四个 section 锚点 `id="overview|capabilities|workflow|docs"` 全部存在，且导航区链接 `href="#..."` 与之对应。
5. **样式外链**：`index.html` 通过 `<link rel="stylesheet" href="styles.css">` 引用样式，不内联大段 `<style>`；`styles.css` 中无 `@import url(http` 且不含 `http://` / `https://` 外链资源。
6. **响应式**：`styles.css` 至少包含 1 个 `@media` 查询，断点含 `768px`（或 `48rem`）。
7. **可访问性基线**：`styles.css` 含 `:focus-visible` 规则；存在 `prefers-reduced-motion` 媒体查询；所有 `<img>`（若出现）有 `alt` 属性。
8. **能力卡片数量**：能力网格卡片数量 ≥ 6（或明确 ≥ 3 且不超 9）。
9. **无外部依赖**：`index.html` 中不出现 `<script src="http`、`<img src="http`、`@import` 指向远程资源。
10. **无占位残留**：文件内不含 `lorem ipsum`、`TODO`、`FIXME`、`{placeholder}` 等未完成标记。

**完成定义（DoD）**：以上 10 条全部通过，且页面在无网络的本地直接打开 `index.html` 时结构与样式正常呈现。

## 6. 非目标（本期明确不做）

- 不做多页面路由、不做 React/Vue 等框架或构建工具链（纯静态 HTML + CSS，JS 仅在必要时以极小内联/单文件形式出现）。
- 不做后端接口、鉴权、登录、数据持久化。
- 不做多语言切换（先固定单语言）。
- 不做真实产品截图或品牌素材设计（图形以 CSS/SVG 抽象表达）。
- 不做 SEO 深度优化、分析埋点、A/B 测试。
- 不引入第三方 UI 库、图标库、网络字体或任何 CDN 资源。
