Three things the skeleton does for you

OwO only owns the agent skeleton: model calls, tools and context. Your UI and business logic stay yours.

  • Tool calling

    Describe a tool with name, argument schema and a run function. The SDK validates the arguments the model produces and feeds the result back into the conversation.

  • Context management

    Session history, system prompt and tool output are trimmed against a token budget, with a summarisation strategy you can replace, so long runs do not silently drop key context.

  • Approval & permissions

    Any side-effect tool can be marked as requiring approval. The runtime pauses for a request, waits for your decision, then executes, and the permission boundary lives in your code.

  • Test harness

    A deterministic execution entry point: fix the random seed and the clock, stub model responses, and assert agent behaviour in CI with plain node:test.

How it works

From an empty directory to an approval-gated agent in three steps.

  1. 1

    Install

    Run npm i owo-agent-sdk. The package is plain ESM with no build step and runs directly on Node 20 or newer.

  2. 2

    Define tools and an agent

    Register your tools, write the system prompt and pick a model. A single createAgent() call returns a reusable agent.

  3. 3

    Ship it with approvals

    Call the agent from your HTTP handler or job queue, add an approval callback for write tools, and forward the emitted events to the audit store you already run.

Quickstart

A complete minimal example: create an agent, register a file-writing tool, and run one request that has to pass an approval gate.

  • requiresApproval routes every write through the approval gate instead of trusting the caller.
  • agent.run() resolves with events that you can forward to your logs or assert on directly in tests.
  • The sample makes no network request; swap model for any compatible adapter to point it elsewhere.

Questions developers actually ask

Do I need a hosted service to run OwO?

No. The SDK runs inside your own process and calls the model provider you configure. There is no control plane, no account and no telemetry; you can run it fully offline against a local model adapter.

How are permissions handled for risky tools?

Mark a tool with requiresApproval: true and the runtime pauses before execution, emits a request event and waits for your onApproval callback. Denials are returned to the model as a tool error, so the agent can reason about the refusal instead of crashing.

Is the SDK TypeScript-only?

No. The package ships typed declarations, but it runs as plain ESM JavaScript. You can use it from .mjs files, from CommonJS through dynamic import(), or inside a TypeScript project without extra setup.

How do I test an agent deterministically?

Use the shipped harness: pass a fixed seed, a fake clock and stub model responses, then assert on the returned events array with node:test. No network, no sleeps and no flaky retries in CI.

Can I adopt OwO incrementally?

Yes. Agents are created per call site, so you can migrate one workflow at a time while your existing framework keeps running elsewhere. Visual orchestration UIs, hosted dashboards and zero-code builders are deliberate non-goals.
