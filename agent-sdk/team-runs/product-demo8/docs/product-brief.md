# OwO Agent SDK — Product Brief（落地页产品简报）

状态：v1（首版，供 designer / builder / qa 直接使用）
范围：单页产品落地页（`index.html` + `styles.css` + `node:test` 测试）
本文件为「需求与验收」的唯一事实来源；不含 HTML/CSS 实现细节。

---

## 1. 产品背景与一句话定位

OwO Agent SDK 是给开发者用来自建「智能体（Agent）」的 SDK：轻量、可组合、默认安全可控，支持工具调用、上下文管理与审批式权限。

一句话定位（Hero 主标题候选，需一字不差落地）：

> Build agents that ship — 面向开发者的轻量 Agent SDK

副标题（可直接实现）：

> OwO Agent SDK 提供工具调用、上下文编排与审批式权限，几行代码即可把智能体接入你的产品。

---

## 2. 目标用户（Primary / Secondary）

| 优先级 | 用户画像 | 真实诉求 | 落地页必须给他的证明 |
|---|---|---|---|
| P0 | 独立开发者 / 小团队全栈工程师 | 一小时内跑通 demo，不被框架绑架 | 可复制的最小代码片段、0 配置上手路径 |
| P0 | 平台/基础设施工程师 | 可控权限、可审计、可观测 | 审批式权限说明、失败与重试语义、工具体集成 |
| P1 | 技术决策者（TL / 架构师） | 降低集成风险与迁移成本 | 架构示意、能力边界、与替代方案的差异 |
| P2 | 已在用其他 Agent 框架的团队 | 增量接入而非重写 | 明确「非目标」与迁移说明链接 |

非目标用户（页面不做适配）：零代码业务用户、需要可视化拖拽编排的运营人员、需要托管式 SaaS 面板的客户。

---

## 3. 核心信息（Three Messages，按优先级）

1. **轻量可组合**：SDK 只做智能体的骨架（模型调用、工具、上下文），UI 与业务逻辑留给你；无运行时框架锁定。
2. **默认安全可控**：每一个副作用工具调用都可走「请求—审批—执行」路径，权限边界显式声明，事件可审计。
3. **可测试**：SDK 自带 `node:test` 友好的确定性执行入口，智能体行为可在 CI 中断言。

每条核心信息都必须对应页面上的一个可见区块，不允许只写在文案里而没有区块承载。

---

## 4. 页面层级（单页信息架构，从上到下）

顺序固定，区块 ID 供 builder 用作锚点，导航与之 1:1 对应：

1. **Header / 顶部导航**（`#top`）
   - 左侧品牌名 OwO Agent SDK；中部导航：Features、How it works、Code、FAQ；右侧主 CTA「Get started」。
   - 移动端折叠为汉堡菜单（可用原生 `details`/`summary` 或 checkbox 方案，不要求 JS 框架）。
2. **Hero**（`#hero`）
   - 主标题、副标题、双 CTA（主「Get started」、次「Read the docs」）、1 行信任信息（如 license / 版本号占位）。
3. **Features**（`#features`，3–4 张卡片）
   - 卡片标题须覆盖：Tool calling、Context management、Approval & permissions、Test harness。
4. **How it works**（`#how-it-works`）
   - 3 步编号流程：安装 → 定义工具与智能体 → 接入产品并加审批。
5. **Code / Quickstart**（`#quickstart`）
   - 一段最小可运行示例（`npm i owo-agent-sdk`、创建 agent、注册工具、`run()`），含等宽字体与可读行宽。
6. **Capabilities / 对比表**（`#capabilities`，可选但推荐）
   - 语义化 `<table>`：特性 ×（OwO Agent SDK / 手写循环 / 重型编排框架），行数 4–6，必须有 `<caption>` 或关联标题。
7. **FAQ**（`#faq`，4–6 条）
   - 使用原生 `<details>`/`<summary>`，覆盖：是否需要托管服务、如何处理权限、是否只有 TS、如何测试确定性。
8. **Final CTA + Footer**（`#footer`）
   - 结尾 CTA 复用主按钮文案；Footer 含文档、GitHub、License、可访问性声明。

标题层级硬性要求：全页仅一个 `<h1>`（Hero 主标题）；区块标题用 `<h2>`；卡片标题用 `<h3>`；不得跳级。

## 5. 关键交互

| 交互 | 行为 | 约束 |
|---|---|---|
| 主导航锚点 | 点击滚动到对应区块 | 平滑滚动需尊重 `prefers-reduced-motion`（关闭动画） |
| 移动端菜单 | `<768px` 折叠，可键盘展开/收起 | 键盘可达、焦点可见、展开状态可被读屏感知（`aria-expanded` 或原生语义） |
| CTA 按钮 | 主 CTA 指向 quickstart 锚点或占位外链 | 必须有可见 `:focus-visible` 样式；hover 与 focus 均可辨识 |
| FAQ 折叠 | 点击/回车展开答案 | 原生 `details` 优先，避免自造不可达 accordion |
| 代码复制（可选） | 复制按钮 | 若实现必须为真实 `<button>`，并有成功反馈文本（`aria-live`） |
| 跳过导航 | 首个可聚焦元素为「跳到主内容」 | 目标为 `#hero` 或 `<main>`，聚焦后可被读屏读到 |

不做的事：不做轮播、不做自动播放视频、不做需要 JS 才能看到核心内容的区块（核心内容必须无 JS 也可见）。

## 6. 视觉方向

- **调性**：开发者工具的专业感 + 一点俏皮（OwO 命名本身是钩子），避免企业级厚重渐变。
- **色彩**：深色优先的单一主视觉（`prefers-color-scheme` 支持浅色作为可选增强，不作为验收项）。主色 1 个强调色用于 CTA 与链接，语义色（成功/警告）仅用于说明权限与状态，不用于装饰。
- **字体**：系统字体栈（`system-ui` 等）+ 等宽栈用于代码；正文 16–18px，行高 ≥1.5，代码块字号 ≥14px。
- **布局**：12 列网格思路，最大内容宽约 1120px，区块垂直节奏统一（如 64/96px）。断点：`<768px` 单列，`768–1024px` 双列，`≥1024px` 三列卡片。
- **图形**：以 CSS 绘制的简单示意图与代码卡片为主，不依赖外部图片资源（页面必须离线可打开、无网络请求即可完整渲染）。
- **动效**：仅做 ≤200ms 的进入淡入与按钮反馈，必须在 `prefers-reduced-motion: reduce` 下关闭。

## 7. 验收标准（可勾选、可被测试脚本断言）

### 7.1 结构
- [ ] 工作区根存在 `index.html`、`styles.css`，且 `index.html` 通过 `<link rel="stylesheet" href="styles.css">` 引用样式。
- [ ] 页面含全部区块 ID：`top`、`hero`、`features`、`how-it-works`、`quickstart`、`faq`、`footer`（`capabilities` 若实现则同样存在）。
- [ ] 恰好一个 `<h1>`，且无标题层级跳级（h1→h2→h3）。
- [ ] 存在 `<main>`、`<header>`、`<footer>`、`<nav>` 等语义化地标元素。
- [ ] 所有图片/图示有替代文本；无图片也可（纯 CSS 方案优先）。

### 7.2 可访问性
- [ ] `<html lang>` 已声明；`<title>` 非空且含产品名。
- [ ] 「跳到主内容」链接存在，且默认视觉隐藏、聚焦后可见。
- [ ] 所有交互元素可仅用键盘完成（Tab / Enter / Space），焦点可见。
- [ ] 表单/按钮若无可见文本，必须有 `aria-label`。
- [ ] 对比度：正文与背景 ≥4.5:1，大字号与图标 ≥3:1。
- [ ] `prefers-reduced-motion: reduce` 下无位移动画。
- [ ] FAQ 使用原生 `details`/`summary`（或等价的 `aria-expanded` 语义）。

### 7.3 响应式
- [ ] 无横向滚动（在 320px / 375px / 768px / 1024px / 1440px 视口下）。
- [ ] 320px 宽度下正文与代码块可读，代码块自身横向滚动而非撑破布局。
- [ ] 导航在 `<768px` 折叠且可键盘操作。

### 7.4 自动化测试（`node:test`）
- [ ] 测试文件放在 `test/`（建议 `test/landing.test.js`），用 `node --test` 运行，**零第三方依赖**（仅 `node:test`、`node:assert`、`node:fs`）。
- [ ] 至少覆盖以下断言：
  1. `index.html` 与 `styles.css` 存在且非空；
  2. HTML 引用 `styles.css`；
  3. 每个必需区块 ID 在 HTML 中出现一次；
  4. 恰有一个 `<h1>`；
  5. 存在 `lang` 属性、非空 `<title>`、`main`/`header`/`footer` 地标；
  6. 存在 skip link（含 `#main` 或 `#hero` 的 href）；
  7. 所有 `href="#..."` 锚点都能在页面中找到对应 `id`（无死链）；
  8. CSS 中包含至少一个媒体查询，且包含 `prefers-reduced-motion` 处理；
  9. 无远程资源引用（无 `http://`/`https://` 的 `src`/`href` 资源依赖，外链导航允许但需在测试白名单中显式列出）。
- [ ] 测试失败信息需指明具体缺失项（断言消息可读）。
- [ ] `npm test` 或 `node --test` 可直接运行且全绿（执行环境有 node 时）。

### 7.5 内容
- [ ] 核心信息 3 条各有承载区块（见 §3）。
- [ ] 主 CTA 文案与 Footer 结尾 CTA 文案一致。
- [ ] 无占位乱码（`lorem ipsum`、`TODO`、`xxx`）出现在可见文案中。

## 8. 非目标（本版明确不做）

- 不做后端、不做真实 API 调用与账号体系；所有 CTA 指向页内锚点或明确占位链接。
- 不做构建流程（无 webpack/vite/tailwind）；纯静态 HTML + CSS，原生语义优先。
- 不做多语言 i18n、不做暗色/亮色手动切换控件。
- 不做第三方字体、图标库、分析脚本等任何外部网络资源。
- 不做交互式 playground、真实代码执行、动画框架。
- 不做博客/文档站/定价页；单页即可，最多一个页内 FAQ。

## 9. 交接说明

- **designer**：按 §4 区块顺序与 §6 视觉方向出栅格与断点方案；每区块需给出「标题 + 正文层级 + CTA 位置」三要素，且能映射到 §7.1 的结构断言。
- **builder**：§4 的区块 ID、§7 的断言即实现的验收清单；代码需满足 §7.4 全部测试项后才能算完成。
- **qa/reviewer**：以 §7 逐条验收，任一 `[ ]` 未勾选即视为未通过；不得以「看起来没问题」替代测试运行结果。
- 变更本简报需同步更新 §3、§4、§7 三处，避免三者不一致。
