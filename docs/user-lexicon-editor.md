# 用户词库管理

入口：设置中心侧栏「用户词库」。设置搜索也可查找“词库 / 编辑 / 清空 / 导入 / 导出”。需要最新版 Core 正在运行，不支持绕过 Core 离线直接改写正在使用的词频文件。

## 功能与范围

- 搜索编码或词语，每页 50 条；新增、编辑编码/文本/权重，或删除选中词条。
- 权重范围 1–128。手动保存和导入代表明确确认；即使权重为 1，也不当作误选型单次记录快速衰减。普通输入产生的学习仍遵循单次衰减规则。
- 删除会去掉该编码和词语的用户绑定及关联上下文学习；有其他编码绑定的同名词仍可保留。基础词典不会修改，因此删除后仍可能自然生成同名候选。
- 清空必须单独输入“清空”确认：删除全部用户绑定、全局词频和语言上下文学习，不删除基础词典、设置或插件。之后继续输入仍会重新学习。
- 管理的是内置输入方案共享的用户学习库。第三方输入方案自己的词库由插件管理，不会越权改写其文件。
- 词库操作采用显式保存，不受设置自动保存或“重置本页”影响。

## 导入 / 导出

导出为 UTF-8 JSON 或 TSV，包含当前库的所有词条，不仅是当前搜索页。内容只有编码、词语、权重，不包含应用名、窗口信息、语言上下文或单次观察时间。文件仍会暴露个人用词，请不要上传真实私密词库用于调试。

JSON 格式：

```json
{
  "schema_version": 1,
  "kind": "OwO.UserLexicon",
  "entries": [
    {"input": "zidingyici", "text": "自定义词", "count": 10}
  ]
}
```

TSV 格式（实际文件使用制表符，首行可省略）：

```text
input	text	count
zidingyici	自定义词	10
```

编码支持英文字母及撇号；大小写和撇号差异视为同一绑定。词语不能含换行、制表符或其他控制字符。导入拒绝未知/重复 JSON 字段、重复绑定、坏编码及非法权重，不静默跳过坏行。

每批最多 5000 条、512 KiB 管理请求，读取文件上限 4 MiB。大型完整导出超过这些限制时需拆分为多批导入，不会静默截断导出。权重按指定值更新，不把导入模拟成多次候选选择。

导入先校验和预览新增/更新数量，再单独确认：

- 合并（默认）：保留其他条目，同编码同词语以文件权重更新。
- 替换：明确警告后，清空现有用户词库及全部学习，再导入。本身不包含上下文的导出不能恢复原来的上下文学习。

## 一致性、备份和权限

所有数据操作由 Core 所有者线程串行执行。编辑采用副本暂存，先校验整批、备份包含尚未落盘的学习数据，再原子保存；失败不部分提交到内存。保存成功后刷新学习代数、取消过期模型映射，使后续候选查询使用新数据。

版本标记同时绑定 Core 会话及学习代数。编辑前重新核对原条目，导入预览与导出分页使用相同版本；并发学习、其他设置窗口或 Core 重启造成变化时拒绝覆盖，要求刷新，不自动重复提交。文件导出使用临时文件后原子替换。

操作前的数据保留在用户词频文件的 `.bak` 备份中。清空不是安全抹除，备份仍可能包含历史学习及上下文；后续写入可能更新该备份。如需长期保留，请另行复制备份。正常使用不自动删除备份或上传数据。

管理请求仅走本机、当前账户受限的命名管道；服务端读取管道客户端实际令牌，拒绝 AppContainer 和低完整性客户端。它不是插件服务，开发模式不会绕过权限检查。中/高完整性同账户程序本来就可访问该账户文件，确认弹窗是防误操作措施，不是同账户恶意软件隔离边界。

专项覆盖事务失败、合并/替换、改名、删除、清空确认、未落盘记录备份、并发版本冲突、候选缓存失效、低完整性读取拒绝及 JSON/TSV 往返；真实文件选择器和响应式页面仍可手动验收。
