# 拼音候选搜索性能与超时治理

本轮基线：`27f1879`，日期：2026-10-22。仅优化计算与取消方式，不提高 IPC 超时、不修改用户配置、不降低路径数量、Beam 宽度或候选分区配额。

## 按优先级实施

| 优先级 | 本轮改动 | 作用 |
| --- | --- | --- |
| P0 | 用有界最差优先堆保存搜索目标节点；先算分再复制状态 | 避免为最终被淘汰的组合反复复制文字、音节、片段，并避免整批组合全排序 |
| P0 | 在候选扩展、路径评估、纠错状态与模型备选生成内部检查取消 | 新输入到达后，旧请求更快退出；取消结果不作为部分候选返回 |
| P0 | Core 检测客户端断线并取消旧请求 | 即使没有新按键产生取消事件，已超时关闭的连接也不会继续占用串行服务 |
| P1 | 缓存纠错状态的排序键，预计算每组词条的静态分数 | 消除比较器中的重复字符串分配，避免每个状态重复计算相同词频对数 |
| P1 | 增加搜索资源计数与可重复基准选项 | 区分“查词慢”和“组合状态复制多”，便于低配电脑对照 |

目标节点按原来的“分数降序、文字升序”选择；节点被消费前恢复有序遍历。跨片段 Bigram 分数先完整计算，再判断是否淘汰，不能按单个词条频率提前跳过。普通拼音和纯声母组合均使用有界搜索。

连接检测最多每 8 毫秒检查一次管道状态，只检查本次请求连接；保留现有取消事件。该周期不是硬实时承诺：单次磁盘缺页、词典调用或系统调度仍可能延迟取消。不会执行或取消第三方 Agent 指令。

## 回归范围与诊断

- 29 个普通、歧义、缩写、错拼及手动分隔输入 × 8/18/48 三种预算，共 87 组新旧输出对照：候选文字、分数、类型、片段数、消耗长度和源片段均一致。
- `owo.engine.candidate_search_budget`：用独立的全展开排序算法比较密集同音字搜索，包含 Bigram 反转场景；验证实际状态扩展中的取消和复制数量。
- `owo.ipc.candidate_abandonment`：模拟词典调用暂停，验证超时断开及显式取消事件均阻止后续查词，下一条正常候选请求成功。
- 复核 full_pinyin、ambiguous_boundaries、dictionary_bridges、local_corrections、candidate_scheduler、contextual_candidate_order、core_service_contract、core_config_contract；共 10 项专项，不代表全量自检。

现有 `candidate_generated` 日志增加 `beam_transitions`、`beam_materialized`、`client_disconnected`，纠错阶段计数合并到请求总计。仅记录计数、耗时和状态，不新增原始输入或上下文日志。基准 JSON 增加平均搜索转移/构造次数，支持 `--samples` 和 `--warmup`。

## 第二批：查词复用与辅助路径（基线 f1a2d08）

剩余 P1 已实施：

- 精确查词、最大词频、跨边界词片段评分在一次 `generate` 内复用，包括“不存在”的结果；结构化读音键不混淆 `a+bc` 与 `ab+c`。命中查询不创建临时字符串键。
- 原始查词行保持完整，Beam 剪裁只作用于副本。缓存不跨请求，不会因词典、用户词频、配置或候选预算变化而复用旧结果。设置行数/条目上限，超出后正常查词，不削减候选。
- 固定解析路径的读音不在每个中间搜索状态重复保存；仅为最终候选物化。可变声母读音仍保留各状态独立信息。构造状态/解析路径时预留一次容量，避免复制后立即扩容再复制。
- 混合缩写以失败状态记忆化替代重复回溯；严格保留原有最长前缀优先成功路径。纯声母等长匹配走线性路径，只有成功时才创建源片段字符串；稠密记忆表上限 256 KiB，超大输入使用有界稀疏表。
- 辅助解析在同一偏移预计算可用音节；路径排序复用读音键，保留原分组配额、多样性和字典覆盖，不缩小路径数量或 Beam。

## 额外修复：无候选长输入的伪超时

私有小词典重现了另一类故障：长输入暂时无候选时，原文被作为一个预览片段返回；超过协议每片段 16 字节的限制后，整个回复编码为空，Core 没发送回复，客户端最终显示超时。

现在此时不附带不可表示的分割信息，TSF 继续保有原始输入和编辑预览，不硬拆原文、不扩大协议边界。若其他响应无法编码，则记录 `response_encoding_failed` 并返回关联原 request/generation 的错误，不再无声丢弃。协议版本和字段格式均不变，兼容当前 TSF。私有服务测试覆盖纠错开启/关闭和后续请求。

## P2：低配电脑采样入口与边界

新增原生、静态运行库工具 `build/windows-release/Release/owo_candidate_ipc_benchmark.exe`，可单独复制到已运行 OwO 的 Windows x64 电脑。默认只显示帮助，显式 `--run` 才连接本机 Core。请停止打字后采样；它只发送固定测试拼音，不采集应用、剪贴板、屏幕或用户上下文，不发送词频学习反馈，不写配置/词库，也不启动或终止 Core。

```powershell
.\build\windows-release\Release\owo_candidate_ipc_benchmark.exe --run --samples 15
# 若要观察真实 ModelHost 异步排序等待：
.\build\windows-release\Release\owo_candidate_ipc_benchmark.exe --run --samples 15 --wait-model
```

每行 JSON 分开报告首轮连接及响应、后台精修响应、结果缓存命中往返、可选排序等待、空响应和失败数量。首轮响应不保证已有候选；空响应计数可帮助发现这一情况。排序等待仅记录实际取得排序结果的样本，`null` 不等于零延迟。采样会正常填充运行期候选缓存，因此多数重复样本是热运行，不能把它们当作冷启动。

真正的低配机冷启动、磁盘缺页/Defender、UI 渲染仍需在目标机器实测；没有清空 OS 缓存、强制重启机器或添加 Defender 排除。应结合既有 Core 启动日志、TSF `candidate_response_received` 的排队/IPC/转换耗时和候选渲染日志定位，再决定预热或调度措施；本轮不修改 UI/动画。无需为了采样改动用户学习与智能排序配置。
