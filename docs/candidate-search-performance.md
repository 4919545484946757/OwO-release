# 拼音候选搜索性能与超时治理

本轮基线：`27f1879`，日期：2026-10-22。仅优化计算与取消方式，不提高 IPC 超时、不修改用户配置、不降低路径数量、Beam 宽度或候选分区配额。

## 按优先级实施

| 优先级 | 本轮改动 | 作用 |
| --- | --- | --- |
| P0 | 用有界最差优先堆保存搜索目标节点；先算分再复制状态 | 避免为最终被淘汰的组合反复复制文字、音节、片段，并避免整批组合全排序 |
| P0 | 在候选扩展、路径评估、纠错状态与模型备选生成内部检查取消 | 新输入到达后，旧请求更快退出；取消结果不作为部分候选返回 |
| P0 | Core 检测客户端断线并取消旧请求 | 即使没有新按键产生取消事件，已超时关闭的连接也不会继续占用串行服务 |
| P1 | 缓存纠错状态的排序键，预计算每组词条的静态分数 | 消除比较器中的重复字符串分配，避免每个状态重复计算相同词频对数 |
| P1 | 增加搜索资源计数与可重复基准选项 | 区分“查词慢”和“组合状态复制多”，便于低配电脑对照 |

目标节点按原来的“分数降序、文字升序”选择；节点被消费前恢复有序遍历。跨片段 Bigram 分数先完整计算，再判断是否淘汰，不能按单个词条频率提前跳过。普通拼音和纯声母组合均使用有界搜索。

连接检测最多每 8 毫秒检查一次管道状态，只检查本次请求连接；保留现有取消事件。该周期不是硬实时承诺：单次磁盘缺页、词典调用或系统调度仍可能延迟取消。不会执行或取消第三方 Agent 指令。

## 回归范围与诊断

- 29 个普通、歧义、缩写、错拼及手动分隔输入 × 8/18/48 三种预算，共 87 组新旧输出对照：候选文字、分数、类型、片段数、消耗长度和源片段均一致。
- `owo.engine.candidate_search_budget`：用独立的全展开排序算法比较密集同音字搜索，包含 Bigram 反转场景；验证实际状态扩展中的取消和复制数量。
- `owo.ipc.candidate_abandonment`：模拟词典调用暂停，验证超时断开及显式取消事件均阻止后续查词，下一条正常候选请求成功。
- 复核 full_pinyin、ambiguous_boundaries、dictionary_bridges、local_corrections、candidate_scheduler、contextual_candidate_order、core_service_contract、core_config_contract；共 10 项专项，不代表全量自检。

现有 `candidate_generated` 日志增加 `beam_transitions`、`beam_materialized`、`client_disconnected`，纠错阶段计数合并到请求总计。仅记录计数、耗时和状态，不新增原始输入或上下文日志。基准 JSON 增加平均搜索转移/构造次数，支持 `--samples` 和 `--warmup`。

## 后续优先级

1. P1：请求内复用重复的精确查词和跨边界评分结果；先看资源计数，避免缓存开销拖累短输入。
2. P1：继续缩短长缩写/长错拼的路径构造与词典匹配；保证原分割族、纠错覆盖及分区不丢失。
3. P2：在目标低配电脑分离冷启动、磁盘/安全软件影响、IPC 和渲染测量，再决定是否预热或调整后台精修调度。不默认添加 Defender 排除规则。
