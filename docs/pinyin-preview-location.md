# 拼音预览显示位置

设置中心 → 候选与输入 → 拼音预览显示位置：

- 候选栏（默认）：保留原拼音预览、光标和鼠标点击操作。
- 输入位置：在当前应用的 TSF 组合区显示预览；它是未确认文本，不是先上屏再回删。
  候选框收起拼音预览行，候选选择、分页、展开仍保留；Unicode 入口移至候选操作区。

应用未提供 TSF 组合能力、拒绝写锁或已有应用文字被选中时，回退到候选栏显示，
不会为了显示预览覆盖选中的应用文字。Agent、Alt 数字预览、Unicode 面板及插件输入方案
继续使用各自原有界面，不把 Agent 请求预览写入文档。

## 交互与安全

- 选择候选替换组合区，不重复追加拼音。短候选即时上屏后，为剩余拼音建立新组合。
- 关闭即时上屏时，暂存文字与剩余拼音仍处于组合态，最终确认才正式写入。
- Enter 按原样输出原始输入，不把自动显示的音节分隔符当作用户输入。
- Escape、清空和默认失焦行为只清除本输入法未确认的组合，不删除前文；失焦保护开启时
  继续按原有设置保留原始输入。外部修改过的组合文本不会被取消逻辑盲目删除。
- 异步更新使用版本号丢弃过期操作；确认或取消后，旧排队更新不能重建组合。
- 已上屏文字仍走现有学习流程，预编辑文本本身不发送候选确认反馈。

配置：schema 19，`pinyin_preview_location=candidate|input`；旧配置迁移默认 `candidate`。
支持自动保存、搜索、页面重置及配置导入/导出。表码及插件方案保留配置但不启用此拼音功能。

## 定向验证与手测

配置迁移/校验、设置模块原生往返与重置、TSF 组合接口测试替身验证了确认替换、取消、
异步去重、原样输入、读光标、原生组合范围/布局变化、短词分段上屏及拒绝预编辑时的回退。
这不等同于所有应用兼容性测试，未执行全量自检。

部署后保存并重开测试应用以加载新 TSF。建议在记事本切换两种模式，输入 `nihaoshijie`：
先选“你好”，再选“世界”，确认最后只有“你好世界”；再测试方向键、Backspace、Enter、
Escape、失焦及展开。WPS、浏览器、Windows 搜索等宿主需分别人工确认组合支持情况。
