# 用户学习优先级与候选分区

## 已确认的问题

学习记录可以成功写入且重复计数增长，但短候选在更长输入中缺少
源编码对应的学习标记。候选生成器和 Core 分页整理又会把整词/句子
首字提前，覆盖短候选的学习顺序，表现为“选了多次仍无法升序”。

例如单独确认 `ke → 克` 后，在 `keyi` 的单字区中，不应强行把
整词“可以”或“刻意”的首字放到已确认的“克”前面。
示例只用于回归夹具，生产逻辑不包含词语或拼音特判。

## 修复边界

- `UserFrequencyModel::preferred(input, text)` 提供独立的源编码优先级证据。
  持久化实现用现有用户词哈希索引查询，不扫描或改写词库。
- 普通、首字母和双首字母候选按实际消费的编码查询该证据，不能把
  整个输入的学习错误套到未消费的后缀，也不能仅因同字全局次数较高
  就把其他编码的强优先一起打开。
- 标记现有候选，不改变其拼音、消费字节、分区配额或生成数量。
  单字区先保留已确认的源编码学习顺序，首字提示只整理其余候选。
- 基础、展开和异步模型更新共享此顺序；关闭外部智能排序不抹除已有学习。
  关闭学习开关仍停止新增记录。
- 单次记录约 10 秒撤销强优先、60 秒撤销学习加分，重复确认及手动
  编辑的规则保持不变。词频文件格式不变，不清空或迁移日常数据。

## 专项回归

`owo.ipc.user_learning_contract` 使用私有命名管道、模拟反向排序模型、
独立配置、可控时钟与临时学习文件，覆盖整词、短候选、缩写、普通/展开、
模型回填、关闭开关及正常关停后重载。修复前可稳定复现单字区优先级被覆盖。

另复测用户词频、单次衰减、源编码匹配、用户词库编辑、配置热加载、
模型置信度及联合分区，不修改用户日常词库。
