# 完整输入的最短分割软权重

同一拼音输入的原始总字节数相同，因此这里的“最短”按精确分割后的音节数
（字音一一对应时即输出字数）衡量，不按拼音串长度、UTF-8 字节数或词语片段数衡量。
例如 `yao'quan'bu` 为三个音节，`yao'qu'an'bu` 为四个音节；两者均可由两个词语片段组成。

## 规则

- 只比较当前已生成、完整消耗相同输入的精确候选，正文字符数必须与音节数一致。
- 当确实存在不同音节数的精确候选时，最少音节的候选统一增加固定 `1000` 分。
  同为最短的候选公平获得同一加分；只有一种长度时不增加。
- 整段输入只获得这一笔加分。不按每字、每词或长度差累加；短一字和短三字均只加一次。
- 记录 `shortest_segmentation_bonus`。再次评估时先撤回旧值再计算，防止重复调用叠加；
  新候选池不再存在长度差时撤回旧加分。普通复制、缓存和重排不再计算奖励。
- 部分消费、补全、简拼及纠错候选不参与比较或领取奖励；非拼音方案不调用此规则。
- 不增加词典查询、解析路径、Beam、模型请求、可见句子配额；不写入用户词频。
  用户明确学习、整词保护和现有连贯性优先规则保留，因此它不是“更短必然优先”。

## 当前效果与边界

真实只读词典、无用户学习和上下文加权时：

| 候选 | 原分 | 新增权重 | 新分 |
| --- | ---: | ---: | ---: |
| 要全部 | 23012 | 1000 | 24012 |
| 要去按不 | 23887 | 0 | 23887 |

在默认候选分区的最终同组评分中，“要全部”由第二项升到首项，
未改动连贯性评分或比较规则。关闭分区时，两条候选仍按原有连贯性优先规则排定，
“要全部”在本轮 5/7/9 页长的基础与模型评测中均为第三项，不宣称该模式也成为首选。

此项可能在本来合理的长短歧义中轻微偏向较短解读；固定上限可限制但不能消除该风险。
短音节方案若缺乏词典或语义支持，也不会因这 1000 分就自动获得有效候选资格。
