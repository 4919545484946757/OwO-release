# 设置中心配置导入与导出

入口：设置中心 → 通用设置 → 配置导入与导出。搜索“导入”“导出”“备份”或“迁移”也可以定位。

## 使用范围

- 包含当前输入方案、候选与输入、学习与排序、全部快捷键绑定、中文标点逐项设置，以及自动保存开关。
- 导出的是当前界面的配置，包括尚未保存的调整；先使用原生配置后端校验，不会因为导出而保存到日常配置。
- 不包含用户词库、词频记录、上下文、模型/词典文件、安装路径、插件安装状态、插件配置及权限授权。词库请使用独立的“用户词库”导入/导出。
- 插件输入方案只保留方案 ID；在另一台电脑上仍需安装并独立授权插件，不能借助导入绕过权限检查。
- 不支持当前输入方案的宿主配置也会保留在文件中；导入不会为该方案启用未接线的能力。界面按当前方案禁用相关控件，切回受支持方案后可继续使用原偏好。

## 导入与恢复

选择 `.json` 文件后，设置中心先完成格式、数值范围和快捷键冲突校验，再显示覆盖确认。取消或校验失败不会应用该文件。导入覆盖上述范围及其未保存的修改，不是局部合并。

确认后先备份原 `owo.conf` 和存在的 `settings-ui.json`，然后立即保存并刷新界面；不受自动保存开关限制。Core Service 按现有机制热加载，运行中的应用按已有配置刷新机制应用按键等设置，无需重启整个输入法。

备份位于当前配置目录的 `backups/import-日期时间-唯一编号/`，成功信息显示具体路径。配置目录默认是 `%LOCALAPPDATA%\OwO\InputMethod\config`，开发模式可以通过 `OWO_CONFIG_PATH` 隔离。备份保留在本机，不自动清理。

若保存自动保存偏好失败，已写入的主配置会从备份原子恢复；回滚也失败时，错误提示会给出备份路径。手动恢复时先关闭设置中心，将备份中的文件复制回原配置目录，再打开设置中心。不要把权限文件或用户词库替换为配置文件。

导入不更改插件配置；已排队的插件自动保存修改会在主配置导入前正常保存，失败则停止导入。

## 文件格式与安全

当前导出格式为本地 UTF-8 JSON，根结构如下（`settings` 为完整设置快照，不支持省略字段）：

```json
{
  "formatVersion": 1,
  "kind": "OwO.Settings",
  "settings": { "...": "完整设置快照" },
  "uiPreferences": { "autoSaveEnabled": true }
}
```

不直接接收原始 `.conf`，避免配置后端的损坏恢复/默认值机制掩盖导入文件错误。单文件上限 64 KiB、嵌套深度上限 8；拒绝未知版本、未知或重复字段、字段缺失、非法 UTF-8、空值、非规范快捷键、快捷键冲突及超出范围的设置。快捷键的多绑定为数组，每个元素只表示一个组合键。

待导入设置先通过独立临时配置调用同一原生后端验证，不能在确认前修改日常配置。文件不含代码、资源路径或授权指令；只通过系统文件选择器读取/写入用户选择的文件，导出使用临时文件原子替换。配置后端超时有界，失败显示具体原因。今后格式扩展需增加兼容迁移，不能将缺失字段静默解释为默认设置。

## 定向验证

```powershell
dotnet run --project tests/settings_center/configuration_transfer_tests.csproj -c Release -- build/windows-release/Release/owo_config_shell.exe
dotnet build apps/settings_center/OwO.Settings.csproj -c Release -r win-x64 --no-restore -p:Platform=x64 -p:NuGetAudit=false
```

测试只在随机临时目录工作：完整字段/多快捷键往返、原生校验隔离、无效文件拒绝、备份原文一致、关闭自动保存时应用、偏好写入失败回滚，以及词库/插件数据不受影响。界面手动验收：进入通用设置导出、取消导入、确认导入，检查提示与原配置备份；以自动保存开启/关闭分别验证。
