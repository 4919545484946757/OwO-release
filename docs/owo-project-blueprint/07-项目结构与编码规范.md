# 07 · 项目结构与编码规范

## 已有结构

| 目录                                                                | 主要职责                                        |
| ----------------------------------------------------------------- | ------------------------------------------- |
| `apps/`                                                           | Core、ModelHost、启动器、WinUI 设置/安装和开发 CLI 的进程入口 |
| `include/owo/`                                                    | C++20 模块头文件与协议声明                            |
| `src/engine/`、`src/tsf/`                                          | 输入方案、解析、候选、学习；TSF 组合态与候选渲染                  |
| `src/ipc/`、`src/protocol/`                                        | 本机管道、消息封装、严格解析与请求身份验证                       |
| `src/model/`、`src/config/`、`src/plugin/`、`src/agent/`、`src/core/` | 模型、配置、插件、Agent 契约及 Core 适配                  |
| `plugins/`                                                        | 官方资源插件和进程插件示例                               |
| `tests/`、`benchmarks/`                                            | 功能、契约、集成测试和性能基准                             |
| `scripts/`、`packaging/`、`tools/`                                  | 构建、注册、测试、发行和词典编译工具                          |
| `docs/`、`build/`、`artifacts/`                                     | 文档、本地构建中间物、发行输出；后两者不作为源码目录                  |

## 责任边界

```text
应用输入事件 → src/tsf/ → 本机 IPC → Core / src/engine/
可选排序   → src/model/ + ModelHost
插件扩展   → src/plugin/ + 独立插件进程
用户设置   → apps/settings_center/ + src/config/
新增协议   → include/owo/<module>/ + src/<module>/ + tests/
```

## 编码与提交规范

1. C++ 使用 C++20；沿用 `snake_case` 文件名、`PascalCase` 类型名。新增原生接口放 `include/owo/<module>/`，实现放 `src/<module>/`。
2. API/IPC 变更需给出版本、请求 ID、长度上限、超时、取消、错误码和旧结果丢弃规则；对外接口须明确稳定性等级。
3. 新配置给默认值、校验、迁移和回退；持久数据使用备份与原子替换。不得因配置损坏静默覆盖用户原数据。
4. 修复补最小复现测试，覆盖空值、超长、非法 UTF-8、焦点变化、连续请求和取消；性能报告记录机器、词典、模型与配置。
5. 插件权限按最小必要声明；新增权限同步更新风险文案、授权验证、宿主测试和开发文档。
6. 提交仅包含本次范围；发布核对版本、许可证、SHA-256。不得提交用户词库、凭据、个人配置或 `build/` 产物。

## 未来可加入的结构（规划）

- `src/platform/<os>/`：平台特有的焦点、组合态、窗口和上屏适配。只有跨平台实施时才建立，不先移动现有 TSF 代码。
- `src/schemes/<scheme>/`：真实仓颉、五笔、外文等方案实现和独立词典加载；方案私有学习需带命名空间。
- `src/resources/`：词典/模型资源的版本、兼容性、哈希、许可证和回滚管理。
- `tests/quality/<scheme>/`：按输入方案拆分的数据集与基准，避免用拼音指标衡量全部方案。
- `docs/migrations/`：当文件格式或对外插件契约改变时记录迁移与回退脚本。

新增目录前须先明确责任所有者、可复用边界、测试位置和迁移方案；不为了“看起来模块化”而拆分目录。具体构建条件以[根 README](../../README.md)和 `CMakeLists.txt` 为准。
