# 长句第二候选与分词结构保护

长输入曾在存在多个精确分割路径时默认保留两条整句，跳过短输入使用的评分门槛。
现在同样检查第二条的评分差、连贯性差和片段数量：长输入本身不再是保留理由。
近分且同样简洁的合法词汇变体仍可保留，整词和用户词保留原有专用规则。

基础排名还有一项针对纯字符替换的模型置信度保护。
此前它只检查拼音路径相同，却不检查词边界相同；
长前缀的局部覆盖加分可能因此锁住错误的后半句结构。
现在只有音节路径及词典片段边界都相同，才沿用此项保护。
不同分词结构可以交给模型比较，不因基础评分较低被预先分到劣后置信度层。
此项改动不移除用户学习、候选分区或同结构低质量替换的保护。

这些规则不包含具体拼音或中文词句。纯词频无法判断所有语义歧义；
“降雨/将于”“重试/充实”等全拼同音表达的最终选择需要语言模型或用户上下文。
五个真实词典复现案例见 `tests/data/phrase-boundary-ranking-regression.jsonl`；
合成模型合同另检查长前缀后的不同词边界能否被模型纠正。

发行脚本的运行时选择与开发启动、运行时暂存脚本同步为 `runtime-x86_64`。
旧 `runtime-p1-x86_64` 按整个候选作为单词打分，不具备新版的多字词分词评分；
ABI 相同不代表长句能力相同。旧资产不删除，历史评测证据不改写。

模型结果也会重新检查第二条整句的片段数量和近重复关系。
长句中仅替换开头/中间同音片段、主体和结尾重复的项不再占第二整句位；
四字组合只过滤“相同两字结尾、前半仅一字替换”的低多样性变体，
不把“将与/降雨”这种两字都不同的歧义直接排除。
模型首选未变时，同前半词而不同后半词的基础优质替代会保留，避免“重试”被隐藏变体挤出。
删减后从同一快照尾部补位；扩大搜索不能重新加入已淘汰的整句。

2026-10-30 的隔离真实词典与新版 libime 专项结果：
“家里的牛奶已经喝完了”“十点前”“明天上午十点前”为首选；
牛奶句不保留弱第二整句；“稍后重试”“降雨概率”为首页第二项。
后者尚未达到用户要求的首选，现有模型仍偏好“将与概率”。
试验句末评分和有界词间关联加分均未改善，源码已撤回这些试验，未作词句特判。
