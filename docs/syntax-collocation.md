# 全拼句法搭配实验

在设置中心选择「全拼」，搜索「句法搭配（实验）」即可切换。默认关闭；开启后，普通候选在本机搜索期间对相邻词的方向性依存搭配小幅加分，未收录的连接不降权。此实验不读取应用内容，不访问模型 API，不替代现有智能排序，不新增或上屏 0 号候选。模型管理器中的自动 0 号候选暂停，保留授权、设置及模型调试能力。

首版只比对输入范围内解码路径的**相邻词**，使用训练集的依存边作为句法证据，而不是在每次按键时构造整棵依存树。单词对最多加 360 分，整条路径最多加 900 分，单次生成最多查询 4,096 次。句法信号不会跨过标点段或读取上屏前文。依存数据来源、生成过程和授权见 [`data/syntax/README.md`](../data/syntax/README.md)。

## A/B 测试

用开发模式 CLI 创建一个空测试会话，使用同一个真实词典分别运行：

```powershell
owo_dev_cli --dev --root <会话绝对路径> init
owo_dev_cli --dev --root <会话绝对路径> input batch --file tests/engine/syntax_collocation_ab.jsonl --lexicon <真实词典文件> --syntax-collocation off --report syntax-off --allow-misses
owo_dev_cli --dev --root <会话绝对路径> input batch --file tests/engine/syntax_collocation_ab.jsonl --lexicon <真实词典文件> --syntax-collocation on  --report syntax-on  --allow-misses
```

比较 `summary.json` 的首选正确率、首屏覆盖率与基础请求 P50/P95，再逐条比较 `cases.jsonl` 的退步和改善。这组小样本用于冒烟测试，不代表整体验证；决定是否替代 0 号候选前，应增加更均衡的独立样本（同音分歧、混拼、长句、专业词和已有首选回归），并在中低端电脑上交替多轮运行。设置中心「调试与性能」另提供句法搭配查询时间，原始诊断只记录耗时、查询数和命中数，不记录输入文本。

### 首轮结果

同一个 Rime Ice v3 词典、关闭模型与学习，按「关 → 开 → 开 → 关」各跑 16 条输入。两组首选均为 14/16，首屏均为 15/16；`提出这个想法` 在两组均为第二，`继续处理` 在两组均未进入 Top 10。关闭时基础请求 P50 为 1.38–1.48 ms、P95 为 29.99–30.49 ms；开启时分别为 1.56–1.63 ms、30.63–30.85 ms。这些是本机完整基础请求耗时，不是纯句法查询耗时，也不是可泛化的性能上限。独立的合成词典合同确认了加分能够改变近分候选的首选。首轮没有观察到真实词典的质量净收益，先不替代 0 号候选。
