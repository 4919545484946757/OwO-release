# 03 · 服务清单

编号与[技术架构图](owo-technical-archify.html)、[业务调用关系](04-business-calls.html)一致。这里的“服务”包括应用进程内组件、后台进程和本地数据资源，不表示八个网络服务。

| 编号 | 组件与形态 | 职责及调用 | 运行边界 |
| --- | --- | --- | --- |
| ① | `OwO.TSF.dll`，应用进程内，必需 | 接收按键、维护组合态与焦点、显示候选和上屏；调用 ② | 不加载第三方插件代码 |
| ② | `owo_core_service.exe`，当前用户后台，必需 | 输入方案调度、基础候选、纠错、词库查询、分区、学习和插件调用；访问 ③④⑤ | 候选处理主控 |
| ③ | `owo_model_host.exe`，可选 | libime 上下文排序，响应 ② | 未就绪或失败时保留基础候选 |
| ④ | PluginHost / 资源插件，按需 | 候选主题、符号、实验性输入方案与 Agent IPC；按清单和版本授权 | 第三方代码不进入 ①② |
| ⑤ | 本地文件资源 | 词典、配置、用户学习、插件数据和模型 | 不是关系型数据库服务 |
| ⑥ | `OwO.Settings.exe`，按需 | WinUI 3 设置、词库与插件管理；安装助手展示选择、确认和进度 | 安装授权与插件运行授权分开 |
| ⑦ | `owo_runtime_launcher.exe`，启动阶段 | 启动 ②；条件满足时启动 ③ | 不参与候选评分 |
| ⑧ | 第三方 Agent，用户自选 | 经已授权的 ④ Agent IPC 插件交换结构化请求、状态和命令 | 高风险操作仍需宿主确认 |

## 主要依赖

- ① → ②：本机 IPC 候选请求，包含请求 ID 和焦点代数；返回候选快照。
- ② → ⑤：基础词典只读查询，用户学习由 Core 串行更新。
- ② → ③：可选模型排序；不能让模型不可用阻断基础候选。
- ② → ④ → ⑧：仅在插件已安装、启用并授权时成立。
- ⑥ → 配置/管理后端：设置、词库与插件管理；不直接改写运行中的 `.owuf`。

## 故障与退化

| 条件 | 预期行为 | 验收重点 |
| --- | --- | --- |
| ③ 未启动或超时 | ② 提供基础候选 | 首屏不等待模型才显示 |
| ④ 未授权、崩溃或超时 | 拒绝插件结果，内置拼音继续使用 | 不执行旧命令，不丢失原输入 |
| ⑤ 基础词典缺失或损坏 | 报明确错误 | 停用候选来源不等于可删除启动依赖 |
| 焦点或请求代数变化 | ① 丢弃旧结果 | 分页、展开和首屏使用对应快照 |

源码入口：`apps/core_service/`、`apps/runtime_launcher/`、`src/tsf/`、`src/engine/`、`src/plugin/`。
