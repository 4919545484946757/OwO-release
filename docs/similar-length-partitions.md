# 字数相等的字典/句子候选联合排序

启用“候选分区”时，先保留现有句子生成数量上限、字典组合词配额及
单字区域槽位，再对可比较的多字候选联合排序。

## 合并条件

- “字数”是每个候选的 Unicode 字符数，不是整个区域候选文字的累加值。
- 以当前首个可见句子候选的长度为固定参照；只有字数完全相等、匹配类型
  相同的字典词/前缀与句子进入同一排序区。例如 4 字句子只与 4 字词
  联合排序，3 字、5 字词和单字不受影响。
- 必须实际存在可见字典候选才合并；仅隐藏模型候选不会触发。
- 单音节优先/整音节纠错的特殊布局、关闭候选分区时的旧规则保持不变。
- 即使只相差 1 字，也保留原分区规则，不再作近似长度合并。

## 评分与分页

合并后不再按“句子来源优先”或“字典来源优先”硬排。使用已有综合分数
（匹配代价、词频、词链连贯性、启用时的学习/上下文得分），同分时优先
消费更多输入、其余稳定保序；明确确认的用户学习仍保留优先权。

联合候选只在原多字候选槽位间交换，单字位置和分页槽位不变。不会额外
生成句子、扩大搜索预算或修改短候选的拼音消费范围。

Core 对联合区复用现有短语区标识（协议 group=0），避免渲染分割线或
模型回传重新分开二者；原始 segment_count 和 consumed 字节仍保留。
内部标记不进入配置或词库文件，无协议版本升级、无需重新注册 TSF。

模型更新也将联合前缀与完整句子视为同一排序层，保留置信度差距保护和
明确学习位置。隐藏候选不能将词语槽位变成额外长句：显示的组合句子数量
不超过基础列表原有数量（最多两项），完整字典词不算组合句子。
关闭分区时不采用此例外。

## 专项验证

- `owo.engine.candidate_partition`：等字数跨源排序、正负 1 字排除、
  学习优先、隐藏尾部/单字不动、模型层与消费字节映射。
- `owo.ipc.joint_partition_contract`：真实私有 Core + 模拟 ModelHost，
  覆盖每页 5/7/9 项、逐页与展开逐项一致、模型返回、关闭分区的旧规则。
- 开发 CLI 的 `test --suite engine` 已包含联合分区单元测试。
- 13 项相关专项回归通过；本机 Core 已更新。真实词典中
  `zidongzhankai` 的普通/展开列表及模型更新均保持“自动展开”为首选，
  3 字“自动站”不再与 4 字句子合并，短词“自动”与单字区仍保留原区域。

没有任何按具体拼音或词语触发的生产代码特判。测试不修改日常配置、
词库或学习记录。
