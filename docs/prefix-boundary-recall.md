# 短词前缀与词典支撑分割（2026-11-01）

## 原因

- `cuobiezimu` 有“错别字”词条，但词典没有“错别”整词。长输入只查原生前缀词，
  所以直接输入 `cuobie` 时的组合回退，在长输入的词语区反而缺失。
- `houxuanzhi` 的常规解析只保留 `hou'xuan'zhi`，丢弃较多音节的
  `hou'xu'an'zhi`。字典里的“后续”“安置”无法参与搜索。
- 即使恢复该分割，模型也可能把完整词链全部换成另一读法的零连贯性拼接。

## 有界修复

1. 候选分区开启时，允许现有三字及以上词典前缀提供一个两字截断候选。
   仅在该两音节没有原生词条时回退，标记为组合项，不冒充原生词典词；
   仍遵守原词语区组合配额和不完整输入的两页非单字总配额。
   关闭分区保留旧规则，不启用此回退。
2. 对最长32字节、至少三音节的精确拼音，检查单个音节内部已有的合法元音边界。
   只有整串可由真实的二至四字词完整覆盖时，才补充最多两条路径。
   不扩大已有精确路径及 Beam 上限，不用单字填充验证分割，不改输入或加入专门答案。
   显式撇号输入不增加新边界路径。
3. 正确裁剪短前缀的源片段；补充分割的拼音预览必须与原输入逐字相等，
   不把字典补全读音写回用户输入。
4. 基础首句由完整多字词链支撑时，对另一精确读法中没有连贯性证据的组合保留
   最低置信度差；仍允许词典整词、用户偏好和同读法的模型排序。
5. “长词+单字”布局允许末尾真实二字词跨越该边界，作为完整词典覆盖的衔接证据。
   不泛化到所有二字重叠；后者实验曾使“十点前”“列表未展开”退化，已撤销。

## 定向结果与限制

默认七项、分区开启、真实词典与本地 libime：

- `cuobiezimu` 首页同时保留“错别字母”“错别字”“错别”；后两项分别消耗8、6字节。
- `houxuanzhi` 能保留“后续安置”，预览为 `hou'xu'an'zhi`，并同时保留“候选”“后续”短词。
- “继续安置”“继续安装”“陆续安装”同类样例正常。
- 新数据集12例，模型后首页命中11例；“候选值”虽进入内部模型比较，仍未进入可见长候选，
  不能宣称该同音词选择已解决。目前可选择“候选”后再选择“值”。
- 五项页或关闭分区时，还有部分短前缀首页未命中；不承诺所有短词都占据首页。
- 5/7/9页长、分区开/关、逐字输入三次回放的运行错误、模型失败和分页/展开差异均为零。
- 既有78条控制样例目标排名未变化；9项相关 CTest 通过，未执行全量自检。
