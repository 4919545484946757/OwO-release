# 歧义分割的召回与手动边界

`bingewai` 的合法分割包括 `bin'ge'wai` 和 `bing'e'wai`。
原模型隐藏池按全局评分截取，可能被第一种分割的同音组合占满，
导致“并额外”已生成却没有机会参与模型排序。
现在在原有总预算内先保留每个精确分割的一条代表，再填充其余同音词。
不增加可见长句配额，也不允许模型跨越解析器保留的手动边界。

用户词频的紧凑查询键不包含撇号。此前召回学习词后仅核对字数，
可能把 `bing'e'wai` 的词错误绑定到 `bin'ge'wai` 路径。
现在针对歧义全拼或显式边界，使用请求内词典缓存验证整词/片段的读音。
已知词优先采用有词典证据的合法路径；若只能在去除撇号后的另一条路径匹配，
则不在该手动分割请求中召回。不会删除或重写用户记录。
没有词典证据的私有学习词保留既有回退，导入编码映射保持原契约。

验证只对存在学习记录的相关歧义请求运行；先查整词，再按最多四音节的词典片段对齐，
复用请求缓存，不扫描整个词库。测试包含强词频干扰的合成学习记录与真实模型样例。
