# 分割方案与句子候选配额

## 规则

句子候选上限为当前已有高质量拼音分割方案数 × 2，每个方案最多两条。
这是上限，不强行补足候选，也不增加解析路径、Beam、线程或模型请求数量。
无额外合格分割时保留原来最多两条的基线。

- 用原始输入片段的边界标识方案，而不是汉字、同音词或补全后的读音。
  `xi'an'jie'dao` 与 `xian'jie'dao` 分开计数，同一读法的同音词不重复计数。
- 基础最优方案保持原有质量筛选；其他方案须完整覆盖输入、字音数量对应、
  匹配类型相同，且在既有替代分割评分容差内。
- 额外方案必须有真实整词、用户偏好、多字首词或足够覆盖度的跨词连贯性证据，
  不以任意单字排列组合增加配额。第二句仍受评分差、碎片化与重复变体过滤。
- 不完整拼音所有非单字候选合计仍不得超过配置页长的两倍；新句子配额不豁免该限制。
- 每页为现有词语源、单字源各保留至少一项位置；句子放不下时在后续页继续，
  不扩张每页长度。其余位置沿用已有词语/单字配额和同字数共同评分规则。
- 基础生成、缓存扩充、分页、展开和模型筛选使用相同来源标识。
  模型只在同一分割内比较第二句的碎片化，不用另一分割的词数误删它。
  关闭分区时也保留多方案候选；模型过滤后扩充候选池的预算同步按新配额预留，
  防止被拒绝的句子占满搜索预算、错误宣告最后一页。

例如 `xianjiedao` 原先已生成“衔接到”，但 `xi'an'jie'dao` 的
“西安街道／西安接到”占满全局两条句子槽位，导致它被隐藏。
现在这两种有词典证据的读法分别拥有最多两条槽位，不写入特定拼音答案。

内部 Candidate 新增来源资格元数据；未改变公开协议、插件权限、词典文件、
模型文件、用户词库或词频学习记录。

## 验证范围

合成词库检查页长 5/7/9、分区开关、模型备选开关、不同搜索预算，
并检查模型更新、分页与展开的统一快照。弱长句质量门槛维持原有测试。
真实词典回放数据集：`tests/data/segmentation-sentence-quota.jsonl`。

这项修改解决配额导致的隐藏，不等于解决全部语义排序：探索数据里的
“候选值”“衔接口”以及“衔接到了”的模型后首页命中仍有不足，不能将
`--allow-misses` 的正常退出解释为全部质量样例通过。

2026-11-02 定向回放结果：

- 真实词典与 libime、逐字输入，页长 5/7/9 × 分区开关六组中，
  “衔接到”均位于首页第三项，运行错误、模型失败、分页/展开差异为零。
- 八条探索样例仍有三至四条模型后首页未命中（随页长/分区而异），不宣称全部解决。
- 既有 78 条句首、句尾、句中单字、上下文与词边界控制样例目标排名未变，
  分页/展开差异为零。
- 候选、词链、分区、预算、复用、用户词对齐/保留、模型次序、快照、
  引擎符号及 IPC 符号共 11 项相关 CTest 通过；未运行全量自检。
