# 句中独立单字的局部模型校准

`liebiaoweizhankai` 的解析和“列表未展开”候选原本均存在，基础分差约 2265，
没有跨过 Core 的 16000 分词汇置信度层。问题不是上次句首放行遗漏：
libime 原始模型确实更偏好“列表为展开”（-11.429）而非“列表未展开”（-12.092）。
两条最优分词均是“列表 / 单字 / 展开”，并非把单字误合入词。

候选中，较低频单字“未”的后续搭配得分更高，但被前置先验压过。
此次只在批量排序中做一次有界比较：

1. 选择原模型得分最高、长度 5–32 字的文本作为参照；查找与其前后正文完全相同、
   仅一处句中单字不同的候选族。替换位置左右至少各有两字。
2. 仅比较族内原模型的前两名，原始分差不得超过 1.0；不让所有低频同音字共同提权。
3. 重新检查两条最优模型分词，替换字都必须是独立 token；词内替换不适用。
4. 使用 `nullState()` 得到无上下文单字先验，比较
   `整句分 - 0.75 × 单字先验`，且替代项在最优路径中的后续累计分必须更高。
5. 满足条件只交换这两条原来的评分槽位；其他分数不变，一批最多交换一对。

后续分来自实际最优路径中“单字之后至句末”的模型转移，不是额外字符串规则。
两条短句的复核不扩大 Beam，不增加 IPC、模型线程或候选搜索；分组扫描不分配字符数组。
没有“未/为”白名单，也不把自然语言文本作为控制命令。Core 的词汇、用户学习、
整词保护和可见句子限额不变。单项原始评分接口及桥接 ABI v1 保持原样；
批量评分仍属于校准后的排序证据，而不是原始概率。

## 定向结果（2026-10-31）

隔离 CLI、真实只读词典与现有 libime，无个人学习记录：

- `medial-character-regression.jsonl` 13 条，最终首选从 5/13 提高到 9/13，
  首屏从 8/13 提高到 12/13。改善项为“列表未展开”（含手动分隔）、
  “窗口未打开”“操作未成功”。“任务未完成”“结果皆为零”“众人皆无言”保持首选。
- “文件未保存”仍未命中；“列表为空”“数据链接”“任务交接”仍在第二位。
  保留失败样例，不把 `--allow-misses` 解释为全部准确。
- 5/7/9 页长逐字输入均保持 9/13 首选及 12/13 首屏，示例均首选；
  模型失败、运行错误与分页/展开不一致均为零。
- 先前句首、问句尾缀、名词、日常副词、上下文及词边界共 59 条目标排名无变化。
  不扩大之前未解决项的修复范围。
- 新增介词/词语对照 6 条前后目标排名相同，5/6 首选；
  “工作为生活服务”“活动为学生举办”仍首选；“任务由系统执行”原有召回问题仍存在。
- `owo.model.backend` 数值门槛测试通过；`owo_libime_context_tests` 使用新桥接通过，
  覆盖正反候选顺序、正常介词、末字校准及词语对照。

报告：`build/medial-character/reports/medial-before`、`medial-null-prior`、
`final-*`；早期 `medial-calibrated` 和 `medial-model-anchor` 为实验，不是最终实现。
仅运行定向测试，未进行全量自检或打包。模型不可用或关闭智能排序时仍使用原基础结果。

## 局限与代价

这不是语法模型，仍可能在原模型近分的单字歧义中误判。未进入比较池、相差多字、
词内分词、超过长度限制或不在该批优胜候选族的情况均不保证改善。
每个命中范围的批次至多额外复核两条短句；不能宣称完全零计算开销。
可见句子数量、用户词库、基础分割和评分规则均未改动。
