# 拼音的局部纠错

## 单音节换位纠错

`chnag` 虽然已保留 `chang` 的解析路径，但 Core 会把 `ch'na'g` 的缩写组合视为充分证据，跳过纠错；纠错候选生成器还会重新查询原始输入的缩写，以同字的高分前缀覆盖完整修复结果。

处理规则不绑定具体输入或词语：

- 对 4–6 个小写字母的无分隔输入，至多交换五次相邻字母，检查是否能恢复一个合法完整音节。合法原音节、已有完整精确解析、短声母缩写和手动分隔不进入此优先策略。
- 有限预检命中时，缩写候选不能阻止纠错；纠错源只查询完整单音节修复，再与原始分割候选合并。内部候选池按现有预算为两种来源预留容量，去重后用剩余纠错项补位，避免常用单字占满预算而丢失 `ch'na'g` 等原分割候选。词典没有修复结果则保留原基础候选。
- 合并时保留各项原始消耗区间及来源，不把缩写候选伪装成纠错候选。分区开启时，纠正后的完整单音节也服从“完整单字拼音时单字区优先”开关；开启时单字区优先，原始组合句保留但不抢走首位。关闭候选分区时，先列纠错候选，再保留原分割备选。
- 仅包含纠错路径的候选池不再附带原输入缩写、声母或用户词直接查询；正常输入的相关来源不变。纠错候选仍使用正常词频及上下文评分。
- 保留原输入拼音及消耗范围；关闭纠错时不执行优先策略。保留基础结果先显示、随后请求纠错补全的流程。

新增解析及 Core 专项覆盖 `chnag/shnag/zhogn/chneg/jnig`、8/16/32 路径预算、纠错关闭、基础候选填满首页后的延迟补全与展开缓存；候选生成专项验证纠错源内部不混入缩写来源。合并测试额外构造超过普通搜索预算的 80 个修复字，确认原始完整及短候选仍保留、消耗范围正确、标识不重复、翻页与展开一致；配置测试覆盖 4/5/7/9 项及两种分区顺序、原始组合句和关闭候选分区。此处是相邻换位的有限修复策略，不宣称任意错拼或歧义缩写都能唯一恢复。

## 长拼音的局部纠错

`gongnnegkaiguan` 原先会得到“功能开干／功能开挂”，而不是“功能开关”。原因是长输入允许两处纠错，但路径裁剪优先输出两次编辑的结果；有限的纠错配额被改动正确后缀的路径占满，遗漏了只修复中间 `nneg` 的路径。

修复采用通用规则，不绑定具体拼音或汉字：

- 优先保留一次编辑的修复，同时交替分配一次／两次编辑的路径预算，避免任一类完全占满名额。
- 在同等音节长度的两次编辑路径中，先覆盖不同的首个纠错位置，再补充同一位置的变体；保留长输入两处真实错误的恢复能力。
- 在分区候选链路中，同一原始分割和同一纠正后读音已有完整字典词时，抑制其非用户词的逐字／短词组合，避免组合句分区重新把完整字典词挤到后面。精确匹配、其他读音和用户词不受这条规则影响。
- 不修改用户输入的拼音文本，候选保留原始来源区间和消耗长度；纠错关闭时不注入修复路径。不增加编辑距离、Beam 宽度或返回路径上限。

专项覆盖中间音节换位 `nneg`、`negn`，不同前后缀，8/16/32 条解析预算，8/48 条候选预算和模型备选开关。原有 `wangwangshituobukuaigauanxi` 两处纠错、短拼音纠错与歧义边界回归保留。Core 独立管道测试覆盖基础结果后的纠错补全、原始拼音预览、完整消耗 15 字节以及关闭纠错。
