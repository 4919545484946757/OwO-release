# 分页、展开与上下文整词证据

本次修复复用了真实 Core/ModelHost 链路，没有修改词典、模型、句子候选上限或用户学习数据。

## 已确认的原因

- 普通页候选预算随页码增长，旧逻辑只在展开时尝试保序。翻到后页扩容后，
  首页可能重排；扫描中可出现重复或漏项。
- 缓存使用“可见候选＋隐藏模型候选”的总数判断是否足够翻页。
  隐藏尾部不属于可见页，却让系统误以为已有足够结果。
- 扩容保序时把旧隐藏项也放到新池前方。可见列表以第一个隐藏项为终点，
  因而之后的新可见项被截断。
- 缓存里已排好的上下文候选又在命中缓存时被提权一次，执行阶段与首次生成不同。
- 模型细化只返回给当前窗口，没有统一更新后续分页/展开使用的展示快照。
- 关闭分区后仍向空分组数组追加隐藏项分组，造成模型回传映射长度不齐；
  模型名额保护原本又仅在合并区触发，旧模式可能暴露额外组合句。
- 跨边界上下文适应只命中当前候选的首字，也能给整个多字词置顶。
  “展开”后的“开解”不能证明“解过”比“结果”更合适；“不在”后的“在手”
  也不能证明“手癣”比“首选”更合适。对照中 libime 本来就把“结果”“首选”排在前面。

## 修复规则

1. 缓存可用页数只按可见候选计数，隐藏项保持连续尾部。
2. 普通翻页与展开扩容都保留同一输入/上下文/配置/学习代数下的旧可见前缀，
   包括正文、消耗字节及分区元数据；不靠统一扩大首次搜索预算修复。
3. 扩容不额外开放句子排列组合，仍最多两个可见组合句。
   展开可见项与隐藏尾部的模型请求合计仍遵守256项协议上限，不把隐藏项作为额外额度。
4. 模型成功应用后，将其展示前缀原子发布到同一个候选缓存，后续页、返回首页和
   展开复用该快照，不因显示模式再进行一轮独立重排。输入、上下文、配置或学习变化
   仍使用不同缓存键/代数，重新计算，不永久固定候选。
5. 缓存命中不重复执行上下文提权。跨词边界词典证据须覆盖当前候选的完整文字与读音，
   而不是只覆盖其首字；总连接长度仍有四音节上限。单字“狂＋妄”等适应保留，
   模型对合理同音整词的选择与明确用户学习优先级不被硬编码取消。

## 定向验证

- `owo.ipc.candidate_snapshot_contract`：5/7/9 页长，分区开/关，先翻页/先展开，
  候选池增长，跨页去重，隐藏模型项提升，模型更新后返回首页/展开一致，
  以及整词上下文保护、单字适应和合理同音模型选择。
- `tests/data/context-ranking-regression.jsonl`：真实词典下两组用户前文，含无上下文、
  有上下文及附上一段编码的六种输入；基础与 libime 分别复核首选。
- 批量 CLI 仍保留原始首次响应与最终首页两种质量数据。若首页已发生模型细化，
  展开一致性检查以实际展示的最终首页为准；差异证据的 `basis` 标出比较来源，
  不把一次正常模型替换误判为分页错误。

这些检查不等同于完整 TSF、快捷键、渲染或所有应用焦点自检。本次不生成发行包。

## 冷请求的空占位响应

TSF 收到 `candidate_refinement_pending=true` 且候选为空的有效响应时，若已有候选画面，
保留该画面的候选、消耗映射、分区、拼音预览及几何，不发布状态栏占位帧。
新按键的拼音仍由原即时编辑流程显示；等待标志保持开启，数字、空格和鼠标选择
仍走现有延迟确认路径，不能提交旧输入的候选。完整候选到达后一次替换；最终空结果
及失败响应不受保留规则影响。过期 request ID / context generation 仍先行拒绝。

`owo.tsf.expanded_candidate_service` 增加 `nipingchang` 后逐字 `y/o/n/g` 的空细化响应回归，
验证候选与尺寸不清空、旧候选提交返回 `E_PENDING`、最终响应解除等待及真实空结果可清空。
这不是对实际桌面所有材质/显示器的视觉无闪烁保证；需新开测试应用载入新 TSF 后人工观察。
