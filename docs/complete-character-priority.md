# 分段选词后完整单字被前缀挤占

`fengeqian` 选择“分隔”后正确保留 `qian`，但首候选曾变成只消耗 `qi` 的“奇”。
隔离直接查询 `qian` 也能复现，因此不是剩余输入删除或旧请求 ID 的问题。

词典区中的 `qi'an` 候选会把首字“奇/起”提升到单字区顶部。
原逻辑没有比较该单字的输入消耗范围，导致局部匹配压过完整 `qian` 候选。

现在，在引擎单字池截取之前和 Core 分区提示头提升之后，
都稳定地将精确匹配全部输入的单音节单字放在单字区前部。
各匹配层内部的词频/上下文顺序保留，其他拼音分割与多字候选不删除。
没有完整单字匹配时，不改变原有排列。

回归包括合成词典的强 `qi'an` 词频干扰、模型/上下文合同、
真实词典 JSONL 样例及“选中分隔—保留 qian—展开—选择前”的隔离回放。
回放使用默认七项分页，不向应用或日常用户词库写入内容。
