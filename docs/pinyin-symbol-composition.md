# 拼音分割快捷键与符号兼容

## 配置

- 设置中心 → 快捷键 → 拼音分割：默认 `Quote`（不按 Shift 的单引号键），支持开关、组合键及多种绑定。
- 设置中心 → 候选 → 拼音符号兼容：默认开启，仅适用于全拼方案。标点保留在预编辑和候选中，随选中的内容上屏；已明确保存为关闭的配置仍保留原值。
- 中文标点总开关和逐项配置仍决定按键输出中文还是英文标点；它们不决定是否保留标点。
- 普通单引号仍绑定拼音分割时，`ni'hao` 中的 `'` 是语法，不上屏。移除该绑定或关闭分割快捷键后，开启符号兼容即可把普通 `'` 当作弱引号。中文 `‘’`、`“”` 和双引号属于弱引号。
- 自定义分割快捷键插入的边界会单独标记。因此，即使普通单引号已作为引号，同一组合态内仍可使用新的分割快捷键。

新配置参与自动保存、搜索、当前页重置和配置导入/导出。迁移旧配置时，如果单引号已经被另一个启用的动作占用，不抢占该按键。

## 组合规则

逗号、句号、分号、冒号、问号、叹号及其中文形式是强分隔符。第一段是唯一的可操作候选段；后续段在下方显示只读预览。数字键、翻页和展开始终操作第一段。完整选完第一段时，其后的分隔符一并上屏，下一段自动提级；选择短候选时不消耗后续拼音。

强分隔符仅在每页/每行的第一位候选中显示（该候选完整消耗当前段时）；其余候选隐藏尾部重复的强分隔符。下拉预览行和展开列表使用同一规则，宽度与换行按实际显示文字计算。此规则仅影响展示，不改动候选顺序、消费范围和上屏文字：选择其他完整候选仍会带上原分隔符。弱引号及其他符号不受影响。

展开模式仅显示当前段的预览与候选，收起后恢复后续段预览。辅助预览最多显示 16 行，各段的拼音同样显示自动分割后的 `'`。每行保留从 1 开始的候选数字序号，但数字键仍只操作第一段。

新增行位于主候选区下方的独立圆角下拉容器内，沿用 `6857f88` 主候选框的 10 DIP 圆角、1 DIP 主题边框与背景材质；容器在同一候选窗口中绘制，不额外叠加半透明背景。文字和序号使用适配深浅主题的中性灰色，保留分区线，宽度与长词换行参与整个浮框的响应式尺寸计算。展开主候选表时隐藏该容器，收起后恢复。

辅助行与正常首页共用同一请求计算流程，包括配置的每页数量、分区、纠错、用户词频和模型排序，不再使用独立的三项严格查询。相同输入、配置和上下文下，两者内容、顺序、分组与数量一致，并复用同一候选缓存。真正上屏导致上下文或学习记录改变时，重新评分属于正常上下文更新。

连续多段查询按时间片补齐；慢页完成后保留其快照，后续页在下一次细化响应继续计算，不在单次 IPC 中叠加多个模型超时。未完成的行不伪造少量临时候选，完成后一次替换整行。新按键可取消过期组合，辅助查询不会替换当前行的最新排序任务。

弱引号先保留完整候选，再对成对引号内的拼音进行局部查询，只替换对应文字范围，不对多个引号的候选做排列组合。局部替换有独立预算，不无条件置顶。其他符号按原位置保留。

小键盘 `0–9`：有拼音组合且启用符号兼容时，以字面数字插入当前光标位置，
保留在拼音预览、候选投影及最终上屏内容中。主键盘数字仍用于选择候选；
英文、无组合内容、关闭兼容、命令组合键及 Alt 小键盘符号输入保持原行为。
NumLock 关闭后由 Windows 发送的导航键仍按导航处理，不强制变成数字。

待办：数字对具体候选生成的语义影响（如数字读音、数值与日期词组合等）暂不实现；
本次继续使用既有字面符号投影，不把数字交给拼音解析器或模型。
非逗号/句号强分隔符的动态换行，尚需确认“6”的单位和换行对象后再落地；
现有中英文 `; : ! ?` 及 `；：！？、` 均保持强分隔识别，不限制为中文符号。

符号装饰后的内容不会被误记为带标点的拼音词条。普通无符号候选的词频学习不变。英文直接输入、Agent 模式及插件输入方案不使用此拼音适配层。

## 手动验收

1. 默认设置输入 `ni'hao`，应正常生成“你好”，不输出单引号。
2. 开启符号兼容，输入 `nihao,shijie`。开启中文标点时，首行候选应包含“你好，”，下一行预览“世界”等；数字选择仍作用于首行。选完后仅剩 `shijie`，继续选择得到“你好，世界”。
3. 在上述多段状态展开/翻页，确认不会选择后续段的预览，也不会消耗它。
4. 将拼音分割改为 `Ctrl+F7`，关闭中文标点转换以便测试 ASCII 引号，输入 `'nihao'`，应出现 `'你好'`。输入 `ni`、按 `Ctrl+F7`、再输入 `hao`，应出现不带引号的“你好”。
5. 在自定义分割符前后点击移动光标、插字和 Backspace；暂存候选后撤销恢复，边界与文字应保持对应。
6. 关闭符号兼容，确认恢复原有标点确认首候选的行为；切到英文时仍直接输入字符。

## 实现边界

`engine/symbol_composition` 是独立的 UTF-8 源位置映射与候选投影模块，不把标点交给拼音解析器。Core 在原始候选缓存、分区和模型排序之后投影到最终 IPC 响应；模型只接收原生文字候选。弱引号局部变体的缓存身份与普通拼音分开。

内部候选协议更新为 v15：请求使用 `symbol_composition` 和 `manual_breaks`（UTF-8 字节偏移）；响应的 `symbol_preview` 包含各段的自动分割，`following_previews` 为逐行候选字符串数组，`following_groups` 为对应分组数组，禁止用拼接文本反向解析候选。每行最多 9 项、最多 16 行；各行分组必须为空或与该行候选数相同。TSF 在响应边界将消费字节数转换为 UTF-16 编辑单位，避免中文标点导致过度消耗。第三方插件 Agent 公共协议不受影响。
