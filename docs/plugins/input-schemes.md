# 插件化输入方案：分阶段接入

当前完成第一阶段：可运行、可测试的宿主侧实验接口。它不是稳定 SDK、二进制 ABI 或 IPC 格式；安装普通插件后，设置中心还不能选择仓颉、五笔或外文输入方案。现有 `full_pinyin`、`exact_code` 的行为和配置兼容性不变。

## 阶段启动单：输入方案 S1

目标：把方案描述、原始编码、候选文本和消耗范围分离，避免用拼音音节模拟所有输入方案。

范围：`input_method_provider.h/.cpp` 提供描述与验证接口、提供者注册/移除、请求派发和响应校验；专用测试覆盖仓颉、五笔、外文转写模拟提供者。模拟提供者只验证协议边界，不包含真实词典。

明确不做：不改现有拼音算法；不引入词典依赖；不加载第三方 DLL；不修改插件清单或权限；不开放 UI 中的第三方方案选择。

数据流：宿主工作线程 → 注册的提供者适配器 → 身份/范围/容量校验 → 宿主候选结果。提供者不直接上屏。

验收：三类方案可注册及派发；非法 UTF-8、错误身份、越界范围和候选数量超限被拒绝；取消和停用后返回的旧结果不发布；提供者异常不外泄详细信息。

风险及回滚：接口仍需结合真实方案修订；撤销本阶段提交即可移除，不涉及配置或用户词库迁移。公共命名、权限和线协议在 S2 前确认，当前不冻结。

## 宿主侧实验接口

头文件：`include/owo/engine/input_method_provider.h`。接口为 C++20，`InputMethodProvider` 是宿主适配器，不是要求第三方导出虚函数的 DLL 接口。未来由隔离 IPC 适配器实现该接口。

### 描述与输入

- `id`：`<plugin_id>/<local_scheme_id>`，注册时拒绝跨命名空间方案 ID。正式接入时宿主还须验证 `plugin_id` 与已授权清单一致，不能只信描述中的声明。
- `kind`：`phonetic`、`table`、`transliteration`，分别适用于音码、形码/表码和外文转写；不会根据类型调用拼音解析器。
- `language_tag`：语言标识，当前仅做字符和长度校验，完整 BCP 47 校验留到配置接入。
- `alphabet`：Unicode 标量集合，明确包含支持的大小写、分隔符及非 ASCII 字符；宿主校验原始输入，不隐式转小写或补音节。
- `max_input_bytes`、`max_candidates`：输入字节限长与每次响应候选上限；硬上限分别为 16384 字节和 256 条。

请求包含 `request_id`、`session_id`、`scheme_id`、`action`、`input`、`caret_byte`、`page`、`page_size` 和 `selected_candidate_id`。动作包括组合输入、选择和取消。选择必须携带候选 ID，其他动作不能携带该 ID；只有后续宿主会话层保存的有效候选才可被选择，字符串合法不等于获得执行权限。

### 候选与范围

响应携带相同的请求/会话/方案/页身份、状态、显示预览、候选、`has_more` 和简短诊断。每条候选具有独立 ID、文本、注释及 `consumed_ranges`。

范围是原始 UTF-8 输入的半开字节区间 `[begin, end)`，必须非空、有序、不重叠、不越界且落在字符边界。不能基于预览字符串、音节数或候选文字长度推算消耗范围。例如输入 `éa` 的字节长为 3，`é` 的范围为 `[0, 2)`，不是 `[0, 1)`。TSF 的 UTF-16/UI 光标位置需由适配层显式转换。

`preview` 仅用于显示，不解释为命令。候选可消耗一段或多段原始编码；剩余编码继续组合。是否暂存、上屏或学习由宿主策略决定，而非提供者直接写入应用。

每条文本最多 4096 字节；显示预览最多 16384 字节；诊断最多 1024 字节；响应内容计数预算为 128 KiB（非最终序列化包长）。S2 需对实际 IPC 包长另设边界。

### 注册、取消与错误

注册表只持有描述与适配器生命周期，不授予权限、不加载插件代码。相同方案 ID 不允许重复注册。移除插件后，即使原提供者仍在运行，旧注册代数的结果也被丢弃。

派发时不持有注册表锁调用提供者；提供者负责自身状态的同步。`stop_token` 为协作式取消：调用前/后检查，不能强制终止卡死的提供者。超时、进程终止和最新请求仲裁由 S2 的隔离执行层完成，不能在 TSF 按键回调中同步执行本接口。

不可用、取消、异常或非法响应均不返回可选择候选。原始输入由宿主保留；不得以出错为理由清空或上屏用户输入。身份校验只保证与当前传入请求一致，跨请求的新旧优先仍需宿主调度层处理。

## 后续解耦与安全清单

S2/S3 必须逐项处理现有拼音专用路径，不能只扩大配置的方案 ID 白名单：

- 把 TSF 字符接收、预览分隔和音节光标移动改为方案能力驱动；Agent 的首字符 `v`、拼音纠错和缩写不能强加到形码或外文方案。
- 分区、模型排序、局部提交、标点转换和词预测按方案能力启用；不支持的功能明确禁用或回退。
- 词典、用户词频及学习编码带方案命名空间，避免五笔编码和拼音键冲突；迁移旧拼音数据保持兼容。
- 用户启用、停用、切换方案时明确生命周期，旧会话结果不能覆盖新方案候选。
- 提供者默认只获得本次编码及必要配置，不获得跨应用上下文、剪贴板、文件访问或网络权限。词典只读资源访问单独授权，密码/安全输入框不外发组合文本。
- 独立进程插件不进入 TSF/Core 地址空间；输入方案权限不隐含执行程序、删除文件或 Agent 权限。
- S2 先定义清单扩展、权限与 IPC 版本协商，再添加第三方安装支持。此文档中的结构不能直接填入现有封闭的 API v1 清单。
