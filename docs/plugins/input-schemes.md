# 插件化输入方案：分阶段接入

当前完成 S1 及 S2a：宿主侧实验接口、隔离进程通信和 Core 组件级后台路由。它不是稳定 SDK、二进制 ABI 或 IPC 格式；安装普通插件后，设置中心还不能选择仓颉、五笔或外文输入方案，实际 Core 候选入口尚未接通方案发现/选择。现有 `full_pinyin`、`exact_code` 的行为和配置兼容性不变。

## 阶段启动单：输入方案 S1

目标：把方案描述、原始编码、候选文本和消耗范围分离，避免用拼音音节模拟所有输入方案。

范围：`input_method_provider.h/.cpp` 提供描述与验证接口、提供者注册/移除、请求派发和响应校验；专用测试覆盖仓颉、五笔、外文转写模拟提供者。模拟提供者只验证协议边界，不包含真实词典。

明确不做：不改现有拼音算法；不引入词典依赖；不加载第三方 DLL；不修改插件清单或权限；不开放 UI 中的第三方方案选择。

数据流：宿主工作线程 → 注册的提供者适配器 → 身份/范围/容量校验 → 宿主候选结果。提供者不直接上屏。

验收：三类方案可注册及派发；非法 UTF-8、错误身份、越界范围和候选数量超限被拒绝；取消和停用后返回的旧结果不发布；提供者异常不外泄详细信息。

风险及回滚：接口仍需结合真实方案修订；撤销本阶段提交即可移除，不涉及配置或用户词库迁移。公共命名、权限和线协议在 S2 前确认，当前不冻结。

## 路线与验收点

| 阶段 | 工作 | 完成标志 |
| --- | --- | --- |
| S1：通用契约（已实现） | 方案描述、候选消耗范围、注册表、验证、取消 | 专用接口测试通过 |
| S2a：隔离通信（已实现） | 已授权 PluginHost 进程、实验线协议、Core 后台组件、超时、最新请求优先、异常及停用结果失效 | 真实 AppContainer 表码示例可返回候选及分页，异常恢复测试通过 |
| S2b：运行时接线（待实现） | 正式方案权限与发现机制、Core 候选入口路由、方案会话授权和安全输入场景检查 | 主服务可以枚举方案、绑定会话并路由；停用或故障保留输入 |
| S3：输入与配置（待实现） | TSF 按方案接收 Unicode/大小写/分隔符，方案选择与专属配置，候选分区与学习规则按能力适配 | 仓颉/五笔/外文示例可安装、选择、输入、翻页与上屏 |

每阶段验收后再进入下一阶段。S2 优先用一个小型表码插件贯通，不同时引入多个大型词典。

## 宿主侧实验接口

头文件：`include/owo/engine/input_method_provider.h`。接口为 C++20，`InputMethodProvider` 是宿主适配器，不是要求第三方导出虚函数的 DLL 接口。S2a 的进程适配器实现该接口。

### 描述与输入

- `id`：`<plugin_id>/<local_scheme_id>`，注册时拒绝跨命名空间方案 ID。正式接入时宿主还须验证 `plugin_id` 与已授权清单一致，不能只信描述中的声明。
- `kind`：`phonetic`、`table`、`transliteration`，分别适用于音码、形码/表码和外文转写；不会根据类型调用拼音解析器。
- `language_tag`：语言标识，当前仅做字符和长度校验，完整 BCP 47 校验留到配置接入。
- `alphabet`：Unicode 标量集合，明确包含支持的大小写、分隔符及非 ASCII 字符；宿主校验原始输入，不隐式转小写或补音节。
- `max_input_bytes`、`max_candidates`：输入字节限长与每次响应候选上限；硬上限分别为 16384 字节和 256 条。

请求包含 `request_id`、`session_id`、`scheme_id`、`action`、`input`、`caret_byte`、`page`、`page_size` 和 `selected_candidate_id`。动作包括组合输入、选择和取消。选择必须携带候选 ID，其他动作不能携带该 ID；只有后续宿主会话层保存的有效候选才可被选择，字符串合法不等于获得执行权限。

### 候选与范围

响应携带相同的请求/会话/方案/页身份、状态、显示预览、候选、`has_more` 和简短诊断。每条候选具有独立 ID、文本、注释及 `consumed_ranges`。

范围是原始 UTF-8 输入的半开字节区间 `[begin, end)`，必须非空、有序、不重叠、不越界且落在字符边界。不能基于预览字符串、音节数或候选文字长度推算消耗范围。例如输入 `éa` 的字节长为 3，`é` 的范围为 `[0, 2)`，不是 `[0, 1)`。TSF 的 UTF-16/UI 光标位置需由适配层显式转换。

`preview` 仅用于显示，不解释为命令。候选可消耗一段或多段原始编码；剩余编码继续组合。是否暂存、上屏或学习由宿主策略决定，而非提供者直接写入应用。

每条文本最多 4096 字节；显示预览最多 16384 字节；诊断最多 1024 字节；响应内容计数预算为 128 KiB（非最终序列化包长）。S2 需对实际 IPC 包长另设边界。

### 注册、取消与错误

注册表只持有描述与适配器生命周期，不授予权限、不加载插件代码。相同方案 ID 不允许重复注册。移除插件后，即使原提供者仍在运行，旧注册代数的结果也被丢弃。

派发时不持有注册表锁调用提供者；提供者负责自身状态的同步。基础注册表的 `stop_token` 为协作式取消：调用前/后检查，不能强制终止卡死的本地提供者。S2a 的进程适配器使用 PluginHost 超时与 Job 终止，后台工作线程处理最新请求仲裁；不能在 TSF 按键回调中同步等待本接口。

不可用、取消、异常或非法响应均不返回可选择候选。原始输入由宿主保留；不得以出错为理由清空或上屏用户输入。身份校验只保证与当前传入请求一致，跨请求的新旧优先仍需宿主调度层处理。

## 后续解耦与安全清单

S2/S3 必须逐项处理现有拼音专用路径，不能只扩大配置的方案 ID 白名单：

- 把 TSF 字符接收、预览分隔和音节光标移动改为方案能力驱动；Agent 的首字符 `v`、拼音纠错和缩写不能强加到形码或外文方案。
- 分区、模型排序、局部提交、标点转换和词预测按方案能力启用；不支持的功能明确禁用或回退。
- 词典、用户词频及学习编码带方案命名空间，避免五笔编码和拼音键冲突；迁移旧拼音数据保持兼容。
- 用户启用、停用、切换方案时明确生命周期，旧会话结果不能覆盖新方案候选。
- 提供者默认只获得本次编码及必要配置，不获得跨应用上下文、剪贴板、文件访问或网络权限。词典只读资源访问单独授权，密码/安全输入框不外发组合文本。
- 独立进程插件不进入 TSF/Core 地址空间；输入方案权限不隐含执行程序、删除文件或 Agent 权限。
- S2 先定义清单扩展、权限与 IPC 版本协商，再添加第三方安装支持。此文档中的结构不能直接填入现有封闭的 API v1 清单。

## 阶段启动单：输入方案 S2a

目标与范围：使用现有 PluginHost v1 AppContainer/Job/命名管道基础设施，增加实验输入方案载荷、授权绑定的进程提供者和一个独立的 Core 后台输入方案工作线程，贯通小型表码示例。

明确不做：不改变插件清单格式，不新增权限，不自动扫描/启用插件，不修改 Core 对 TSF 的正式候选请求入口，不开放方案选择，不修改拼音词典、学习和配置。

核心数据流：宿主批准的描述 → `register_plugin_input_method` 验证 active 安装绑定与授权 → 注册表 → `InputMethodWorker` → `ProcessProvider` → PluginHost → 独立插件 → 严格解码及候选校验 → 后台结果。

验收标准：真实沙箱进程返回候选及下一页；格式错误、进程崩溃、超时可恢复；新输入取消旧请求；撤销授权或停用后无候选输出；失败不修改原始输入。

主要风险：当前 `input.context` 比最终方案权限更宽，只用于实验门禁；最终权限仍待确认。后台路由尚未与正式输入会话、安全输入框检测绑定，因此不能接入现有按键链路。

回滚：撤销 S2a 提交，保留 S1 接口与测试；没有用户数据迁移。线协议、服务名均显式标记 experimental，可替换，不冻结。

### 进程适配与后台路由

`include/owo/core/input_method_runtime.h` 提供授权注册与 `InputMethodWorker`。注册只接受已安装且 active 的 `process` 插件，不安装、不授权、不启用。输入方案描述由宿主提供，插件不能自行注册他人的方案。

每次调用前/后交叉验证安装路径、版本、内容摘要、发布者摘要及现有 `input.context` 授权。缺少授权不得发送编码；撤销、停用或更新使旧结果失效。停用被下一次请求检测到时终止保留的进程会话；立即主动通知生命周期、自动发现和切换仍为 S2b 工作。

选择请求必须属于提供者最后一次有效候选响应的同一会话、原始编码与候选页，并引用实际返回的候选 ID。未知、过期选择在进程调用前被拒绝；错误、取消和新的请求会使旧选择快照失效。宿主负责消费编码和上屏，插件不能通过选择响应直接执行系统操作。

适配器仅发送本次请求字段，不获取应用信息或局部上下文。`user_initiated` 由宿主选定方案的适配器设置，不从外部载荷反序列化；正式 Core 接线前必须补上方案选择许可、会话绑定和密码/安全场景阻断，不能拿该内部函数当通用插件执行入口。

后台组件只有一个线程和一个待处理槽；提交不等待插件。新提交取消运行中的旧调用，并以取消结果替换尚未派发的请求。发布前再比较提交代数，避免忽略取消的旧结果覆盖新输入。调用方应在 Core 回调中消费 future，不能在 TSF 按键回调 `.get()`。

注册超时参数为 1–5000 ms，默认 1000 ms，包含启动与请求；不配合取消的进程最多还有 PluginHost 的 500 ms 取消宽限。实际注册表中的任意本地提供者仍只有协作取消；正式第三方方案必须走进程适配器。

### 实验载荷格式

服务：`owo.input-method.experimental.v1`，外层仍是现有 PluginHost v1 消息。它使用 `input.context` 门禁，既在后台执行器的标准服务表中注入，也在输入方案适配器调用 PluginHost 时明确要求。未新增输入权限或放宽授权检查。

载荷为小端二进制，不是 JSON。数字宽度固定，不序列化 `size_t`、指针、虚函数或编译器布局；字符串为 `u32` 字节长度加 UTF-8 内容。

- 请求：`OWIQ`（4 字节）、`u32 version=1`、`u64 request_id`、session 字符串、scheme 字符串、`u8 action`、input 字符串、`u32 caret_byte`、`u32 page`、`u32 page_size`、selected ID 字符串。
- 响应：`OWIR`、版本、request ID、session、scheme、`u8 status`、preview 字符串、`u32 page`、`u8 has_more`、diagnostic 字符串、`u32 candidate_count`；每条候选为 ID/text/annotation 字符串、`u32 range_count`，随后每段的 `u32 begin/end`。
- 动作值为 compose=0、select=1、cancel=2；状态值为 success=0、cancelled=1、unavailable=2、error=3；布尔值只能为 0/1。

最终载荷最多 128 KiB；解码在分配前限制字符串、候选数和区间数，拒绝截断、尾随字节、未知版本及身份不一致。失败时输出对象清空，不允许使用半解码的候选。候选编号和展示文本不能作为控制指令执行。

示例源代码位于 `plugins/input-method-example`，只有四条演示表码，无完整仓颉/五笔词典。故障注入只编译进测试探针，不存在于示例发行目标。
