# 尾缀引起的句子误排

## 原因与修复

`biandeyouyisi` 可以生成“变得有意思”，追加 `ma` 后却优先显示“变得有一司马”。
解析路径和“变得有意思吗”候选实际都存在；问题主要在句子连贯性评分，而不是缺词。

原评分给每个词典片段至多 12000 分。`2+2+2` 的短词链可累计 36000 分，
而更完整的 `2+4` 词链只有约 24000 分。基础搜索已经计算词频和分词代价，
连贯性阶段再次按片段频率加分，抵消了对不必要拆词的约束。

现在将词典证据按覆盖音节数计算：每两个已覆盖音节保持 12000 分尺度，
相同覆盖长度获得相同证据，不在这一阶段再次累计词频。
基础词频、分词代价、用户学习、模型排序仍保留。
没有匹配词的跳跃仍付出未覆盖字符代价，重叠片段也不会反复累加。

不同解析路径可能输出不同字数，例如 `bian` 与 `bi'an`。
比较连贯性时先按长度归一化，避免较长路径仅因字数更多而压过完整音节路径。
等字数候选沿用原比较尺度和阈值。

修复不识别特定尾字、词语或句式，不新增词典条目、不放宽长句候选数量。
候选仍遵守现有可见长句最多约两项的规则；不保证所有自然语言输入均能准确生成。

## 定向回归

- `tests/engine/candidate_generator_tests.cpp`：30 个组合覆盖分区开/关、不同搜索预算、
  无尾缀、多个尾缀、显式分割、不同字数路径及可见长句上限。
- `tests/data/suffix-ranking-regression.jsonl`：真实词典的 8 个尾缀/前缀/纠错开关样例，
  可通过开发 CLI 分别检查基础模式、libime 模式和增量输入。
- 相关 IPC 候选快照与联合分区合同测试：防止改动破坏分页/展开一致性。

这些都是定向检查，不代替全量自检。真实词典和模型为本地显式只读资产，
运行报告保存在隔离开发会话中，不给日常用户词库写入测试记录。

## 句尾重叠奖励与模型候选保留（2026-10-31）

`youleisidezhuanlima` 的正确拼音路径一直存在，但“专利马”能借“利马”等局部词获得
额外桥接奖励，超过“专利吗”。现在仅在末音节单字频率高度集中、且不含末字的前文
已有独立词典覆盖时，禁止该额外桥接奖励。原有词链评分、整词优先和显式分隔保留；
没有特定拼音/汉字白名单。

同前文的常用尾字候选，在原有第二句的评分/连贯性门槛内可占第二个句子槽，
不增加可见句子上限。模型若偏向同前文的另一尾字，也会保留基础结果中的合理
尾字选项；不强行推翻模型首选，不把所有同音词尾改成语气词。

定向结果（私有 CLI 会话 `build/question-suffix`）：

- 新增 8 组问句/前文/显式分隔：智能排序首屏覆盖从 4/8 提高到 8/8；最终首选 6/8。
  “有类似的专利吗”首选；“价值大吗”第二。单独调用 libime 仍偏向“价值大妈”，
  这是未解决的模型语义限制，不宣称两例都达到首选。
- 原有 `suffix-ranking-regression.jsonl`：基础、libime 首选均 8/8。
- 增加 4 组正常名词对照：“联系大妈”“购买芝麻”“这应该是代码”在 libime 下仍首选；
  “一匹大马”仍未命中，原生成器基线同样未命中（首选“一匹大骂”），本次未扩大修复范围。
- 候选生成、词链与模型次序单元回归通过；相关 CLI 分页/展开核对未出现失败。
- `owo.ipc.candidate_snapshot_contract` 通过。`owo.ipc.model_confidence_contract` 未通过：
  其断言要求展开再次触发 `model_pending`，而已细化缓存不会重新请求模型；对照原代码
  同样失败。本次未修改该断言，也不将此失败报告为通过。

比较过句尾结束概率与额外末字评分路线，未解决模型偏好，因此未采纳这些实验，
生产 libime 桥接与运行时不变。可用 `question-suffix-model.txt` 经开发 CLI `model rank`
独立复核模型偏好。本次不执行全量自检，也不生成发行包。

## 模型局部尾字校准（后续优化，2026-10-31）

后续实验在桥接批量评分中加入局部校准：只比较宿主传入的前两个候选，且要求两者至少
三字、前文完全相同、仅末字不同，并包含该同前文候选组的原模型优胜者。
使用“整词路线 2 份 + 末字独立路线 1 份”的 log 评分判断两者是否交换优先级。
末字路线复用原分词图倒数第二格的状态，不重跑完整解析，也不增加 Beam。

若交换，只交换两者原本的评分槽位，其他候选的评分不变。曾尝试整体降权，结果
使“大骂”等隐藏项意外上升，故未采用。此版本不指定某个拼音、词语或尾字，
不增加句子数量，不修改用户学习优先级，不改 Core/ModelHost 协议或桥接 ABI。
单项评分仍是原 LM 评分；批量结果是校准后的排序证据，不应解释为原始概率。

同一 CLI/词典/模型、无日常学习记录的 43 条对照，首选由 37/43 提高至 41/43：

- “价值大吗”（含手动分隔）、“成本大吗”“声音大吗”从第二升至第一。
- 其余标注目标排名未退步；“联系大妈”“购买芝麻”“打印机”“使用计算机”
  “打开文件夹”“保存代码”等对照保留原有结果。
- “一匹大马”仍未召回，“工作量大吗”仍为第二，不代表全部句法问题已解决。
- 5/7/9 页长逐字输入均保持上述问句集结果，分页/展开一致性无新增失败；
  独立 libime 上下文/名词对照及评分校准单元通过。

报告：`build/question-suffix/reports/algorithm-*-baseline` 与 `family-calibrated-*`。
模型改善仅在启用智能排序且加载新版桥接时生效；基础排序规则保持上一版。
