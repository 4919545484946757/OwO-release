07 / ENGINEERING

项目结构与编码规范

目录部分描述已存在的仓库；规范部分是后续改动应遵守的约定，不表示历史代码已逐条完全符合。

目录职责

apps/

Core、ModelHost、启动器、WinUI 设置/安装与开发 CLI 的进程入口。

include/owo/

C++20 模块头文件和内部协议契约，按 engine、ipc、plugin、model 等子域组织。

src/engine/ · src/tsf/

输入方案、解析、候选、学习；TSF 组合态和 Direct2D/DirectWrite 渲染。

src/ipc/ · src/protocol/

本机命名管道、消息封装、严格解析与请求身份验证。

src/model/ · src/config/ · src/plugin/ · src/agent/ · src/core/

模型、配置、插件、Agent 协议及 Core 适配。

plugins/ · tests/ · benchmarks/

官方/示例插件、功能与契约测试、性能基准。

scripts/ · packaging/ · tools/

构建、注册、测试、发行脚本和词典编译工具。

docs/ · build/ · artifacts/

文档；本地构建中间物；发行输出。后两者不作为源码目录。

新功能放置原则

应用输入事件 → src/tsf/ → 本机 IPC → Core / src/engine/
可选排序 → src/model/ + ModelHost
插件扩展 → src/plugin/ + 独立插件进程
用户设置 → apps/settings_center/ + src/config/
新增协议 → include/owo/<module>/ + src/<module>/ + tests/

编码规范

  1. C++ 使用 C++20；沿用现有 snake_case 文件名、PascalCase 类型名。新头文件放 include/owo/<module>/。
  2. TSF 负责交互与上屏，Core 负责候选与学习；第三方 DLL 不加载到 TSF/Core。
  3. 进程间协议写明版本、请求 ID、长度上限、超时、取消、错误与旧结果丢弃规则。
  4. 配置新增字段有默认值、校验、迁移和回退；持久数据采用可恢复、原子化保存。
  5. 修复时补最小复现测试，覆盖空值、超长、非法输入、焦点变化与连续请求；性能报告记录机器和配置。
  6. 插件按最小权限声明；新增权限同步改风险文案、授权验证、协议测试和开发文档。
  7. 提交仅包含任务范围；发布时核对版本、许可证、SHA-256。不要提交用户词库、凭据、个人配置或 build 产物。

构建命令、平台前置条件和发行流程仍以根 README及 CMakeLists.txt 为准。
