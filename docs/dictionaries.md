# 词库管理器

设置中心 → 词库管理器。顶部搜索字典名称、格式或来源文件，下面以响应式卡片排列。
点击卡片进入详情，返回按钮回到目录。
卡片底部开关即时保存启用状态；右上角 `…` 菜单提供导出、重命名、删除。点击开关或菜单不会进入详情。
刷新、切换开关及重命名采用按字典标识增量更新：保留未变化的卡片、开关与菜单实例，不清空重建整个网格；仅在新增、删除或搜索筛选时增删对应项，并保持原有焦点和滚动位置。
操作期间通过内部忙碌状态防止重复执行，不临时禁用、再恢复导入/刷新等工具栏按钮，避免无关按钮触发颜色过渡。

## 字典类型

- 用户词库：原有学习与手工词条，数据位置不迁移、不清空，保留新增、编辑、删除、清除学习及导入/出。
- 基础中文词典：正文只读、随软件维护；可停用、重命名、从目录移除，并导出当前 Core 使用的原始 `.owolx` 文件（不展开 188 万条词条到内存）。该原始文件用于备份，当前多格式导入入口不将其转为独立字典；再分发须遵守原词典许可。
- 独立导入字典：每本单独命名、启停、搜索、分页、编辑词条、合并导入、导出和删除。
  当前接入宿主完整拼音方案；插件方案的私有词典仍由插件自行管理。

独立字典不冒充输入学习记录，也不修改基础词典。用户实际选择词条后，仍可能按原有规则
产生用户学习记录；所以停用/删除来源字典后，已学习的同名词仍可能出现在用户词库。

用户词库同样支持卡片开关、重命名、导出、移除。停用后不读取其候选、上下文评分和词频提权，也不新增自动学习；管理页仍能查看和编辑已有数据。用户词库总开关与设置中的“词频学习”不同：后者控制学习行为，前者控制整个用户来源是否参与输入。

删除内置项须确认，语义是移除目录项并停用该来源，不擦除基础安装文件或个人词频文件；需要清空个人学习时进入用户词库另行确认。目录工具栏的“恢复内置词库”可恢复被移除的项，恢复后默认停用。名称只改变目录显示，不移动实际数据。停用基础词典后，用户词库和独立字典继续工作；全部来源停用时可能无候选。智能排序模型不等同于基础词典开关。

### 仅使用第三方词库的能力边界

目前支持停用基础中文词典后，继续通过已启用的第三方词库查询候选；同时停用用户词库也不会禁用这些导入词条。条件是使用宿主完整拼音方案、词条含有效编码、完成导入且手动启用。

有完整读音的中文词条已接入宿主 `Lexicon` 候选检索，而不再只是编码到文本的映射：

- 支持完整拼音、不完整音节、自动简拼/混拼、纠错和多个启用词条的跨词组合；支持基础词典与导入词库混合组合，也可在基础和用户词库全部停用时独立工作。
- 复用宿主的拼音路径、纠错开关、候选数量上限、分区、分页与展开规则，不另建无界排列组合流程；组合只能使用启用来源中实际存在的词条。
- 音节数须与中文正文的汉字数一致。来源提供 `xi'an` 这样的边界时严格保留；旧版紧凑编码依据合法音节和字数最多保留 4 种精确读音分割，不利用纠错或缩写来猜词库读音。歧义较大时建议在编辑页明确注音。
- 快捷短码或非纯中文扩展仍保留精确映射能力，不强行拆为拼音；例如 `cs → 测试词库`、`iirc → if I remember correctly` 不自动派生读音、纠错或参与拼音组合。
- THUOCL 等没有编码的来源必须先补编码，仅启用无法生成候选；覆盖不足的第三方词库也不能自动补齐常用字。
- “停用基础词典”是运行时候选来源开关，不是卸载依赖。常规启动仍会加载启动参数指定的 `.owolx` 文件，文件损坏或缺失会启动失败，不能据此删除安装内的基础词典文件。
- 智能排序模型独立于词库开关，可能另外提供模型候选；检查纯第三方召回时应关闭智能排序，避免将模型结果当作词库结果。

隔离测试 `owo.engine.managed_dictionary` 关闭基础与用户来源、无模型：验证全拼、显式分隔、单字、快捷编码、`csck / ceshick → 测试词库`、`ceshifangaf → 测试方法`、`ciku → 词库`；纠错关闭后不能通过错误拼写召回。`owo.ipc.managed_dictionary_contract` 进一步走真实 Core 管道，验证来源停用后的缓存清理、分页和展开一致性。测试不更改本机词库开关或个人记录。

手动测试可导入 [phonetic-demo.tsv](../examples/dictionaries/phonetic-demo.tsv) 并启用；关闭基础、用户词库和智能排序后尝试上述编码，测试后可恢复开关并删除示例词库。示例未收录整词“词库”，它由独立的“词”“库”组合生成。恢复基础词典后排序可能变化，这是来源及评分证据变化，不承诺第三方词条始终首选。

## 支持的导入格式

| 格式 | 范围 |
| --- | --- |
| Gboard | 个人词典 TXT、包含唯一 `dictionary.txt` 的 ZIP，版本 1/2；保留快捷编码、正文、语言及词性标签 |
| OwO | `OwO.UserLexicon` JSON、`OwO.Dictionary` JSON、带表头 TSV |
| Rime | UTF-8/带 BOM UTF-16 文本 `.dict.yaml`，支持标准 `text/code/weight` 列及 `columns` 行内/列表定义 |
| CSV | 表头声明 `input/code/pinyin/reading`、`text/word`，可带 `count/weight/frequency`、语言和标签；支持逗号、双引号转义，不支持跨行词条 |
| 普通文本 | 制表符分列；仅有词语的一列文本作为待补编码词条保存 |

Gboard 格式参照 [PersonalDictionary 项目的公开格式与样例](https://github.com/NatoBoram/PersonalDictionary#format)。
这是导出格式兼容实现，不读取 Gboard 内部数据库、自动学习模型，也不声称兼容其专有二进制字典。
不支持直接导入搜狗 SCEL、SQLite、APK 或可执行插件；不会联网转换或执行文件内容。
Rime `import_tables` 不会自动展开或访问其他文件，只读取当前文件的数据行。

导入前显示格式、数量、待补编码、合并重复项及权重调整数，并要求明确确认。
没有编码或包含当前方案不支持字符的原编码，会保留为“待补编码”，不猜测多音字读音，
也不直接塞进候选。详情页补好编码后可启用。
宿主编码当前支持 ASCII 英文字母及 `'`；空格分开的编码规范化为 `'` 分段，
同时保留改变前的原编码。前端保留按键及 `v` Agent 模式规则不会被字典覆盖。

原始频率保留为元数据，供运行时使用的权重限制为 1–128，超范围时预览会提示调整。
重复的编码、正文、语言及词性组合取较高权重；无编码词按原快捷编码区分，不丢弃不同词性。
导出 JSON/TSV 保留待补编码、来源语言、标签与原始编码/频率，不含应用上下文或权限授权。
用户学习库的兼容导入只保留编码、正文、权重，并单独提示元数据限制；含待补编码的文件不静默跳过。

## 存储和生效

默认目录：`%LOCALAPPDATA%/OwO/InputMethod/data/dictionaries`。
`snapshots/<随机标识>/` 含目录 JSON、有效词条 `active.tsv` 和内置来源开关 `sources.tsv`；最后原子替换 `current` 指针，
避免目录已写入、候选尚未写入的半成品。并发窗口通过文件锁与修订号防止覆盖。
失败或取消不发布新快照，删除字典保留历史快照用于恢复，故不属于安全抹除；历史副本会占用磁盘空间。

Core 最多每 250 毫秒检查轻量指针，仅在标识变化时重载并使候选缓存失效。
有读音的中文词条在快照载入时构造整数音节、共享文本、精确读音二分索引、首字母及混拼桶索引，输入时不重新遍历或分词整个词库。每次混拼查询最多检查 16384 个索引项，极大同桶中低权重词条的召回可能受预算影响；这是有界搜索，不保证穷尽所有缩写。重复词条取较高权重，不累加频率。无第三方注音词条时保留原基础词典直通路径；有注音词条时只合并查询结果，不复制或重新索引基础内存映射词典。
坏快照或索引超限会隔离独立字典来源，不擦除基础候选及用户学习数据；内置来源沿用最近有效状态。旧快照缺少 `sources.tsv` 时默认启用两项内置来源。来源切换更新候选代数并丢弃过期模型请求，导入的正规词条不再作为用户学习别名重复注入，避免丢失读音与边界。

新版快照保留上游音节分隔符，旧快照仍能读取并推导有界精确分割；若旧快照曾丢弃明确边界，在新版设置中心保存该字典即可重新写入。运行时索引尚未预生成到磁盘，首次载入/修改大型词库仍有索引构建开销。

本地单文件最多 128 MiB，目录快照与运行时候选快照各最多 256 MiB，合计最多 500000 条，最多 128 本独立字典。在线来源下载和解压各最多 256 MiB，选取范围、自动刷新和回退注意事项见[发现词库](dictionary-discovery.md)。
旧快照不会自动擦除；备份、迁移或清理前请确认个人词语隐私。
开发环境可通过 `OWO_DICTIONARY_STORE_PATH` 同时指定设置中心与 Core 的隔离字典目录。
