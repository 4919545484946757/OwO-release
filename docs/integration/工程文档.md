### 3.1 关键设计决定

- **表达通道的工具约束**：新增受 bearer/限流保护的 `POST /expression`，直接使用现有 Provider，不进入 Agent loop，不读取会话/工作区、不挂载工具/MCP/hooks。请求仅允许 `prompt`，上限 8192 字符；OpenAI 兼容 Provider 固定 1024 输出 tokens、返回最多 4096 字符、模型响应正文最多 64 KiB、总耗时最多 60 秒。Deferred/Resilient Provider 转发该入口，表达请求不做重试或跨 Provider 回退；未实现该入口的 Provider 显式失败。实现和验收状态分开，见 §5.2。
- **会话工作区**：网关为输入法会话使用独立的空工作区目录（`<data_root>/gateway/workspace`），不指向用户项目，减少只读工具可见范围。
- **token 来源**：不再调用公开的 `GET /auth/token`；读取 Daemon 写入的 `<data_root>/auth/token`（用户级 ACL）。401 时重读文件一次。
- **v4 协商**：响应中的 `effect` 只在请求 `capabilities` 含 `output.effects` 时出现；旧客户端仍得到 v3 形状。依赖 `effect` 的写入在缺能力时不降级执行，只展示预览。
- **回写安全**：`replace_selection` 绑定请求时的 `context_id`、选区文本的 SHA-256；TSF 在写入的同一 `TF_ES_READWRITE` 编辑会话里复核焦点上下文、`inspect_input_method_context == allowed`、当前选区文本摘要。任一不符只显示预览，不写入。

## 4.1 步骤 3 人工验收（TSF 原位回写）

用模拟 Agent（`ime/apps/agent_mock`）验收，不需要真实模型和网关。mock 在请求声明 `output.effects` 时，会在首页最前面加三个候选：

| 候选 | effect | 期望 |
|---|---|---|
| 回写验收：上屏测试文字 | `commit_text`，绑定当前 `context_id` | 文档光标处出现 `【OwO 回写验收】<请求原文>`，组合态清空，Ctrl+Z 一次能撤销 |
| 回写验收：错投目标（应只预览） | `commit_text`，绑定 `ctx-wrong-target` | 文档无变化；候选框提示“输入位置已变化或不可写，未写入”并显示内容 |
| 回写验收：复制到剪贴板 | `copy_text` | 文档无变化；剪贴板为 `【OwO 剪贴板验收】<请求原文>` |

准备（一次）：

1. 构建 Release 并启动开发环境：双击 `ime/start-owo-dev.cmd`（会构建、注册当前用户的 TSF、重启 Core、打开记事本）。
2. 连接器版本已升到 `1.3.0`，需要重新授权：运行 `ime/start-agent-mock.cmd`，它检测到版本不符时会打包并给出 `.owopkg` 路径；在设置中心“插件”里安装、阅读权限并同意，再运行一次 `start-owo-dev.cmd` 和 `start-agent-mock.cmd`。
3. 保持 mock 控制台开着；它会打印每个请求的 `capabilities` 和 `context_id`，用来确认 `output.effects` 已经发出。

每个应用的步骤：

1. 在输入框里先打一些普通文字，把光标放在中间。
2. 切到 OwO，输入 `vceshi`，选“测试”，候选框出现上面三个候选。
3. 依次验证三个候选（每次重新输入 `vceshi`）。
4. 额外两项：在使用合成内容的密码框/未知输入框里输入 `vceshi`，期望不采集、不外发、无写入，不能以“只预览”代替零采集门禁；在候选出现后用鼠标点到另一个窗口再回来选，应只预览、不写入（焦点切换会结束会话，候选消失也算通过）。

应用矩阵（方案 7.3，记录“成功 / 错投 / 备注”）：记事本、Word、WPS、Chrome 或 Edge 文本框、VS Code、QQ、微信、飞书、钉钉、一款 Electron 应用。通过标准：所有应用中第 2 项（错投目标）和密码框都不写入（错投数 = 0）；第 1 项的成功率记录实际值，失败要写清现象。结果追加到第 5 节。
