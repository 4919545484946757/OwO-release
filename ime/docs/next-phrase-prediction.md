# 下一词联想（L2）

在候选栏末尾给出一条“你自己常接的下文”。它完全在本机用本地统计算出，不调用模型，也不改变普通候选的排序和快捷键。前置条件是 L1 的授权语料（见 [authorized-corpus-learning.md](authorized-corpus-learning.md)）；同一份语料还用于风格档案（见 [style-profile.md](style-profile.md)）。

## 从语料里学什么

`UserCollocationModel`（`engine/collocation.*`）只做字符级搭配统计：

- 对语料里每句已授权的本人文字，记录每个 1–3 字上下文后面紧跟的一个字符；
- 句末标点（`。！？…!?`）和换行之后的字符不进入统计，所以联想不会把句号带出来，也不会跨句预测；
- 同一个下文至少出现 2 次才算稳定；只出现一次的说法可能只是笔误，不参与联想；
- 查询时优先匹配最长的 3 字上下文，命中后沿着同一条链继续取下一个字，最多 48 字节（UTF-8）；不足 2 个字的“预测”没有意义，直接返回空。

统计只存在于内存里，**每次语料文件变化都从文件重新构建**。因此删掉语料里的句子，联想也会相应消失；没有第二份可以“忘不掉”的副本。构建只取最新 6000 条语料，避免语料很大时在按键路径上出现可见停顿。

## 什么时候出现

Core 在生成完一页候选后计算联想，只有这些都满足才追加：

- 语料学习总开关打开且没有暂停（`corpus_learning_enabled`、`corpus_learning_paused`）；
- 下一词联想开关打开（`corpus_prediction_enabled`，schema 18，默认 `true`）；
- 请求是第一页、非展开视图，输入非空且不是 Agent 组合（首字母为 `v`）；
- 请求带最近上屏的上下文（`context`），且上下文通过 PII 过滤（含密码、验证码形态的内容不参与）；
- 预测结果非空，且没有和本页普通候选重复。

联想**排在一页普通候选之后**，不会挤占数字键的位置：

- 空格和 `1`–`9` 仍然选择本页普通候选，不会选中联想；
- 联想用“续”徽标代替编号，只能点选；
- 如果这一页只有联想、没有普通候选（例如输入的字母组不出候选），空格不会吞掉按键，标点输入也不会被联想吸收，而是按原样上屏已输入的字母。

点选联想后，整段已输入的拼音被替换成学到的下文；它会作为一次正常上屏记入语言上下文，并触发普通的选词反馈。

## 显示与数据

- 协议复用已有的 `candidate_groups` 字段，新增 `CandidateGroup::continuation = 3`，没有改变字段顺序或协议版本。
- 只要这一页带联想，`candidate_groups` 就会与候选等长；关闭候选分区时普通候选记为 0，联想仍单独标记。
- 联想候选的 `candidate_consumed` 等于已输入字符数，因此消费者可以用它准确移除预编辑串。
- 候选缓存把语料文件修订号（`last_write_time`）计入缓存键，删除或新增语料后不会返回旧联想。
- 语料文件读不出来时，联想按空处理，并输出一次 `corpus_prediction_unreadable` 诊断日志，普通输入不受影响。

## 用户可以做什么

设置 → 输入法 → 学习与排序 →“下一词联想”：可单独关闭联想而继续保留语料（例如只想留着语料做按语气起草）。关闭后立即不再出现；重新打开后立刻恢复。

命令行对应字段：

```bash
owo_config_shell <config> set corpus_prediction_enabled false
```

## 已知边界

- 联合统计是字符级、无词性、无语言的；它只模仿“你以前怎么写”，不理解语义，因此不会用来改写普通候选的排序。
- 一段上下文如果只出现过一次，就不会联想；冷启动需要先积累一点语料。
- 联想目前只处理中文句子；短于 3 个字符的句子不参与统计。

## 验证

- `owo.engine.collocation`：出现阈值、句末不跨句、最长上下文优先、长度与 UTF-8 边界、清空、语料重建、最新 6000 条上限。
- `owo.protocol.messages`：`CandidateGroup::continuation` 往返，越界分组值被拒绝。
- `owo.config.store` / `owo.config.shell_integration`：schema 18 新增字段的保存、读取与 `set-all` 传参。
- `owo.ipc.core_config_contract`：预置授权语料后，普通拼音请求的最后一个候选是学到的下文且分组为 `continuation`、`candidate_consumed` 等于输入长度；上下文没有语料时不出现；关闭联想后消失、重新打开后恢复；删除对应语料后消失。
