# 反馈学习（L5）

L5 把“用户如何使用草稿”变成下一次起草的依据：采纳、在预览中修改、拒绝、撤销各记一条，由记录推导出少量可读的说法偏好，进入后续请求并调整候选顺序。全部在本机完成，**不需要新增配置字段**。

当前交付包括反馈存储、命令行显式记录、提示与排序接线、设置中心查看/删除/清空，以及输入法草稿操作的自动反馈入口。模型生成、预览修改与确认上屏已接入源码，详见 [tone-input-flow.md](tone-input-flow.md)；真实应用 TSF 人工验收仍待完成。

记录与授权语料是两套数据：反馈不写入语料库，不影响普通输入、下一词联想和 L3 档案的统计；关闭语料学习也不会删除已有反馈，删除反馈也不会删除语料。

## 四种反馈各是什么意思

| 反馈 | 何时记录 | 学到什么 |
| --- | --- | --- |
| 采纳 `adopted` | 预览的草稿原样上屏 | 这个说法值得再用（`from` = 整条草稿，`to` 为空） |
| 修改 `edited` | 用户在上屏前改了草稿 | 强反馈：`把“好的”写成“好呀”`，取改动中间那一段 |
| 拒绝 `rejected` | 用户放弃某条草稿 | 降低这种说法的权重 |
| 撤销 `undone` | 上屏后又撤回 | 比拒绝更重地降低权重（多半是学了不该学的） |

`final_text` 只对采纳和修改有意义。修改必须真的不同，采纳的最终文字必须与草稿一致；未知类型、非法 UTF-8 或超长内容返回 0。命令行新增反馈要求授权语料学习开启、未暂停、至少一个起草开关开启，且该场景已启用；不满足返回 7。查看与回滚在关闭学习后仍然可用。

### 只学“局部改动”

`tone_feedback_correction` 取两段文字**最长的不同中间段**；两侧相同的前后缀不参与。用户只换一个字（`好的` → `好呀`）时，优先向左扩一个相同码点，无左侧上下文时向右扩一个码点，得到 `好的` → `好呀`，这样学到的短语才可能再次出现。以下情况不学：

- 两段完全相同；
- 纯插入或纯删除（那是增删内容，不是“换个说法”）；
- 改动段超过 16 个码点——整句重写说明不了具体偏好。

整条草稿超过 12 个码点的采纳 / 拒绝 / 撤销只记**曝光**，不生成偏好：拒绝一整个长句不等于“别用这个词”。

### 权重有上限并会衰减

每条偏好带 `weight`、`observations`、`newest_id`：

- 采纳 +1，拒绝 −1，撤销 −2，修改给替换关系 +2，排序时旧说法扣该权重、新说法加该权重；
- 权重上限 ±6；达到上限后新证据按 3/4 衰减再加，与用户词频学习同一套方案，因此反复出现的一次性表达会饱和而不会无限放大；
- 偏好总条数上限 64，超出时最弱的先淘汰；
- 记录总量上限 500，超出时最旧的先丢弃。

## 场景与开关

记录携带当时的应用名，推导偏好时按与 L3 相同的规则归入聊天 / 工作 / 其他，并遵守 `style_scene_mask`。关掉的场景既不出现在提示里，也不影响排序。`build_tone_feedback_profile(entries, scene, mask)` 的 `entry_count` 是参与计算的记录数。

## 进入请求与排序

`describe_tone_feedback_hints` 最多给 3 条完整句子，插在同场景例句之后、当前消息之前：

```
【用户对此前草稿的修改（请照做）】
- 把“好的”写成“好呀”
- 避免类似“行吧”的说法
```

`apply_tone_feedback` 按 `tone_feedback_adjustment` 稳定重排候选：偏好里的说法加分，被避免的说法减分，**同分保持模型给出的顺序**。反馈可能改变模型候选的先后；清空反馈后顺序回到过滤后的原始顺序。

## 存储

`data/tone-feedback.owtf`，与语料同一套保护：

- 文件头 `OWTF`、版本、条数、校验和；
- Windows 上正文经 DPAPI 加密（当前用户），文件在别处或换用户无法解开；
- 保存用 `.tmp` + `MoveFileExW` 原子替换，保留 `.bak`；
- 主文件损坏时自动从备份恢复（`recovered_from_backup`）；
- 跨进程写入用命名互斥量 `Local\OwO.InputMethod.ToneFeedback.v1`，避免输入法与设置中心同时写坏文件；
- 文件权限继承目标目录；默认目录位于当前用户 LocalAppData，内容解密受 DPAPI 用户身份保护。这里不额外重写目录 ACL。

## 命令与设置界面

```bash
owo_corpus_shell feedback list
```

```bash
owo_corpus_shell --app WeChat.exe feedback add edited "好的，明天见" "好呀，明天见"
```

```bash
owo_corpus_shell feedback delete 3
```

```bash
owo_corpus_shell feedback clear
```

```bash
owo_corpus_shell --app WeChat.exe feedback profile
```

```bash
owo_corpus_shell feedback summary
```

`profile` 给出该场景的 `records=`、`preferences=`、每条 `preference=<权重>\t<次数>\t<原说法>\t<新说法>` 与 `hint=`；`summary` 给出各类型计数与三个场景的开关状态，**不输出草稿正文**，供设置界面使用。`metadata` 只输出 id、时间、类型与应用；设置中心通过它列出记录，草稿与最终文字不会传入界面进程。

设置中心“学习与排序 → 语气反馈”页：显示计数与按场景学到的说法数、逐条列出（只显示类型、应用与时间，不显示草稿）、可删除单条或全部清空，两个操作都要确认。

退出码：`2` 用法错误，`3` 反馈文件不可读，`4` 参数错误或被拒绝的记录，`5` 保存失败，`7` 新增反馈未授权、已暂停或场景关闭。

## 回滚

- 删一条：`feedback delete <id>` 或设置页“删除”；删除后重新推导所有偏好，并在写锁内移除包含旧记录的备份，防止备份恢复复活已删内容；
- 全清：`feedback clear` 或“全部清空”，同时删除 `.bak`；
- 清空后 `describe_tone_feedback_hints` 返回空，`apply_tone_feedback` 不改顺序。

回滚只影响**以后**：已经发送给模型的请求无法撤回，和 L4 的说明一致。

## 边界

- 输入法中只在草稿确认写入并验证后记采纳/修改；显式 Esc 放弃当前草稿记拒绝。焦点切换、目标失效、模型失败和自动取消不记拒绝。紧接写入且原光标/文档未变化时，Ctrl+Z 精确恢复原选中文字并回读，成功后将原采纳/修改记录替换为撤销；原记录已删除则不再生成反馈。其他宿主历史撤销不推断成语气反馈。
- 修改学习的是一次局部替换，不学习“以后所有句子都要更短”这类全局风格；全局偏好仍由 `style_preferences` 和 L3 统计表达。
- 记录里有草稿和提交文字，属于用户内容，因此按语料同等级别加密保存；设置页不展示正文，命令行的 `list` 会展示（那是用户显式发起的本机查询）。
