# 按我的语气回复与续写（L4）

L4 已把本地起草、纯文本模型调用、输入法预览修改、确认替换选区和 L5 自动反馈接到同一条源码调用链。生成不执行 Agent 任务或工具；普通候选排序仍使用原来的 ModelHost。

当前证据是 Windows x64 Debug 构建、自动化回归、本机 HTTP 集成和隔离桌面的预览测试。**尚未在用户实际使用的应用中完成 TSF 人工验收，也没有用真实云端模型评估回复效果。** 具体操作与配置见 [tone-input-flow.md](tone-input-flow.md)。

| 已接入 | 尚待验收 / 后续范围 |
| --- | --- |
| 同场景例句、摘要、偏好与反馈提示 | L6 留出语料评测与语气盲评 |
| 环境变量配置的 OpenAI 兼容纯文本接口 | 用户选定模型的真实兼容性与质量 |
| 不抢焦点的预览，拼音候选修改，显式确认替换选区 | 微信 / QQ / Word 等真实宿主的焦点、回读与撤销 |
| 成功上屏后采纳 / 修改、Esc 拒绝、即时撤销关联 | 跨应用回复目标、延后或任意历史撤销 |

## 一条请求里有什么

`engine/tone_draft.*` 的 `build_tone_draft_plan` 组装的内容，顺序固定：

1. 场景（聊天 / 工作 / 其他，由当前应用可执行名推断，与 L3 相同）；
2. 风格摘要：平均句长、短句占比、句末标点比例、每句四类标点的次数、正式程度（样本不足时写“样本不足”）、最多 8 个重复口头语；
3. 用户手写的偏好（`style_preferences`，原样，不改写）；
4. 最多 4 句**本人**在同场景写过的句子（接口允许调用方把上限调到 8，命令行固定用 4）；
5. L5 学到的说法（命令行最多 3 条，来自同一场景的反馈记录，见 [tone-feedback.md](tone-feedback.md)）；
6. 当前要回复的消息，或用户已经写下的开头；
7. 固定要求：2–3 条、每条一行、不加编号；事实只能来自当前消息；续写必须保留开头。

例句的挑选是**可复核**的：按与当前消息共享的“两字组合”个数排序，数量相同再按语料 id（新的在前）。输出的 `example=<共享数>\t<句子>` 行就是这个依据。

场景开关（`style_scene_mask`）同时约束 L3 的档案和 L4 的例句：关掉的场景，其句子既不会出现在摘要里，也不会出现在请求里。

## 事实只能来自当前消息

发送前的要求只是一半，另一半是发送后的**确定性**检查 `check_tone_draft`：

- 草稿里的每一段阿拉伯数字，必须在当前消息里出现过；
- 草稿里的每个英文单词，必须在当前消息里出现过，或者是用户自己例句里用过的词（那是词汇，不是新事实）；
- 与任何例句连续相同的片段达到 12 个字符，且该片段不在当前消息里，判为照搬；
- 空、超长（>1024 字节）、含换行、与消息完全相同的草稿一律丢弃；
- 续写模式下，草稿必须以用户写下的开头原样开始，否则丢弃（因为它会替换当前输入）。

每条被丢弃的草稿都带一句原因，例如 `第 1 条：含当前消息里没有的数字或英文（1 处）`。候选按模型给出的顺序保留前 3 条，去重，并剥掉模型自带的编号、引号和项目符号。

**已知边界**：没有数字的中文人名、地名、承诺（“我明天会去问老师”）无法用这套规则识别。请求里的规则和用户预览仍是主要防线；文档不把这项检查说成完整的事实校验。

## 默认关闭

`tone_reply_enabled`、`tone_continuation_enabled`、`tone_cloud_model_enabled` 三个字段默认都是 `false`；schema 19 及更早的配置迁移后也保持关闭。

- 前两个是功能开关，分别对应“回复消息”和“整句续写”。
- 第三个只表示**是否允许把已组装好的请求交给云端模型**。它打开时，设置页写明发送范围：当前消息或开头、风格摘要、最多 4 句本人同场景句子、最多 3 条反馈说法、手写偏好和固定指令；只使用同场景且符合当前应用允许/排除列表的例句；不读取其他应用窗口，不发送敏感字段。
- 关闭时，本地起草计划照常可用，并允许调用显式配置的字面回环地址模型；禁止发送给其他网络目标。

关闭这些开关不影响普通输入、下一词联想和 L3 档案查看。

## 命令行

```bash
owo_corpus_shell --app WeChat.exe tone "明天组会几点？"
```

输出 `scene=`、`mode=`、`ready=`、`examples=`、`cloud_model=`、`style=` 与每条例句，然后是 `--- prompt ---` 和完整请求文本。`--continue` 切换为续写模式，`--app` 指定应用（缺省按“其他”场景）。

离线检查一段模型输出（文件里一行一条，或用换行分隔）：

```bash
owo_corpus_shell --app WeChat.exe tone-check "明天组会几点？" drafts.txt
```

输出 `accepted=`、`candidate=<序号>\t<句子>`、`rejected=` 与每条的 `reason=`。两个命令都只读本机文件，不联网。

`tone` 还会在 `cloud_model=` 之后输出 `hint=` 行（L5 学到的说法）；`tone-check` 在过滤后按这些说法稳定重排候选，同分保持模型顺序。反馈记录的格式与回滚方式见 [tone-feedback.md](tone-feedback.md)。

退出码：`2` 用法错误，`3` 语料不可读，`4` 参数或文件错误，`6` 没有可用的起草计划（诊断写到 stderr），`7` 设置中没有打开对应开关。

## 设置中心

“学习与排序”页新增三张卡片：按我的语气回复、整句续写、语气回复允许调用云端模型，以及一张只读的“语气反馈”卡片。云端卡片下方实时显示发送范围（会随场景开关变化）。“我的风格”页底部新增“发送预览”：输入一条消息即可看到将要发送的完整内容，同样不联网。“语气反馈”页可查看各类记录与偏好数量，并逐条删除或全部清空。

这些开关和其他配置一样参与自动保存、保存 / 重新加载 / 重置本页。学习总开关关闭时三张卡片都不可点。

## 与普通输入的关系

起草通过独立显式快捷键进入，不注册普通候选来源，不改动 `CandidateGroup`，也不会在语料学习关闭时读取语料。语料不可读、场景关闭、消息为空或过长时，`build_tone_draft_plan` 返回 `ready=false` 和一句诊断，调用方据此提示，普通输入不受影响。

## 验证

- `owo.engine.tone_draft`：空消息/非法 UTF-8/超长/关闭场景/无句子各自的诊断；例句按共享两字组合排序且不跨场景；请求包含摘要、偏好、例句、消息与事实规则，且不泄露其他场景；`--continue` 的规则与伪造小节头的括号替换；数字与英文单词的事实核对、例句词汇放行、照搬阈值、空/多行/超长/回声；续写必须保留开头；候选的编号与引号剥离、去重、上限与拒绝原因。
- `owo.engine.corpus_shell_tone`：无配置视为未授权；默认关闭；单独打开续写时回复仍关闭；请求正文与例句；关闭场景后拒绝；云端开关只改变 `cloud_model=` 的说明；`tone-check` 接受一条、拒绝一条并给出原因；续写检查；反馈记录的增删清与 `profile` / `summary` 输出，学到的说法进入请求并改变排序；用法错误与策略拒绝的退出码不同。
- `owo.config.store` / `owo.config.shell_integration`：schema 20 往返、迁移后三个开关为关、缺失或非布尔值被拒绝、`set` 与 `set-all` 传参顺序。
- `tests/settings_center`：风格偏好转义与折行规则不变；反馈概要与记录行的格式化。
- 尚未在真实设置中心窗口里人工点击验收，未调用真实云端模型；新增传输和输入法预览证据见 [tone-input-flow.md](tone-input-flow.md)。
