## 切换与恢复

切换会把当前用户的 x64/x86 COM 注册指向新副本，并向可选输入法列表追加 OwO；保留现有两项，不改变默认输入法。执行前须确认，脚本会检查原注册和副本哈希，发现别的安装改动即停止。

- 切换入口：[register-current-user.ps1](../build/tone-acceptance/20261022-233221/register-current-user.ps1)。不激活会话、不启动 Core、不打开学习、不配置云端。
- 恢复入口：[restore-registration.ps1](../build/tone-acceptance/20261022-233221/restore-registration.ps1)。恢复原两种 DLL 的注册，原列表没有 OwO 时移除本次新增项；不删除配置、反馈和语料。需关闭并重新打开测试宿主才能卸载已加载 DLL。
- 原 DLL 文件和旧工作树保持不变。恢复仅针对注册路径和新增列表项，不恢复本次激活前的会话输入法选择，也不改模型、配置或用户文档；恢复脚本尚未真实执行。

## 操作前提

1. 使用新开的空白可编辑文档，不在现有工作文档里试写。先检查普通输入和设置窗口；若 Core 尚未启动，不能把无候选当作拼音算法回归。
2. 学习默认关闭，由用户在设置页显式授权；建议只允许测试应用，所有敏感字段继续拒绝。不要导入聊天记录、粘贴内容或合成词条冒充“本人输入语料”。
3. 通过输入法亲自输入几句无个人信息的短句，等待成句/写盘后在语料和风格页面核对。确认同一场景有足够例句后再试语气生成。
4. 使用用户明确指定的模型。云端需另开云端语气授权；只给测试宿主进程注入环境变量，凭据不进入脚本、配置、日志或文档。没有模型时只验收明确的未配置诊断，不宣称生成成功。
5. 真实模型的质量评测与本机固定 HTTP 响应测试分别记录，后者不能作为“模仿语气有效”的证据。
