# P2 阶段启动单：基础输入引擎 MVP

## 阶段目标

在不依赖 AI、插件或网络的前提下，将真实全拼输入转换为可排序、可翻页、可选择并上屏的中文候选，并给出可重复的延迟数据。

## 本阶段范围

- 与拼音解耦的输入方案接口，首个全拼实现。
- 音节解析、模糊路径保留与未完整音节处理。
- 雾凇拼音源词库的构建期导入、清洗、许可和哈希记录。
- 版本化的紧凑二进制词典，运行时不解析大型源文本。
- 基于系统词频、Bigram/N-gram 和用户词频的 DP/Beam Search 候选生成。
- 候选选择、翻页、删除、提交，以及用户词频原子持久化和损坏恢复。
- 引擎单元测试、真实中文用例、微基准与 TSF 端到端验收。

## 明确不做

- AI 模型推理、云候选和网络必需路径。
- 完整设置中心、插件框架、插件商店和资源包公开 SDK。
- 双拼、注音、五笔的具体实现；本阶段只保留可扩展接口。
- macOS、Linux 和移动端适配。

## 实施切片

1. **P2.1 解析纵向切片**：输入方案抽象、全拼解析、小型可追溯词典夹具、多候选协议。
2. **P2.2 词库构建**：固定雾凇版本与许可，导入器、确定性二进制格式、完整性校验。
3. **P2.3 排序引擎**：DP/Beam Search、系统词频与 Bigram/N-gram，确定性 tie-break。
4. **P2.4 学习与交互**：用户词频存储、损坏恢复、翻页和删除操作。
5. **P2.5 端到端与性能**：Core Service/TSF 集成、真实中文输入矩阵、Debug/Release 基准。

每个切片必须可构建、可测试、可单独回滚；P2.5 通过前不标记 P2 完成。

## 计划新增或修改的文件

- `include/owo/engine/`：输入方案、候选、词典和排序的公共 C++ 接口。
- `src/engine/`：全拼解析、查询、搜索与用户学习实现。
- `tools/lexicon_compiler/`：词库构建工具。
- `data/`：版本化 manifest 和仅供测试的小型词库；不盲目提交未审核的上游大文件。
- `tests/engine/` 与 `benchmarks/`：功能、损坏、回归和延迟测试。
- 现有协议、Core Service、TSF 候选状态和 CMake 目标。

## 核心接口与数据流

```text
按键 / 编辑操作
  → InputSchema::parse(raw_input)
  → 音节图
  → CompactLexicon::lookup(syllable_span)
  → CandidateGenerator (DP/Beam + system LM + user score)
  → 分页 CandidateList
  → Core Service 响应
  → TSF 选择与提交
  → UserLexicon 批量、原子落盘
```

协议在 P2.1 内部扩展为多候选和分页语义，但仍是项目内部原型，不声明稳定公共 API。

## 验收标准

- `nihao` 可生成“你好”等真实中文候选，多候选顺序可重复。
- 覆盖单音节、多音节、分隔符、未完整音节、非法输入和歧义切分。
- 真实 Windows 11 应用中通过 TSF 完成候选显示、翻页、选择和上屏。
- 重启 Core Service 后用户词频仍生效；主文件损坏时可从上一个有效快照恢复。
- 无模型、无网络、无插件时全部基础输入用例通过。
- Release 基准报告包含数据集、机器环境、样本数、p50/p95/p99 和最大值；未采集数据前不虚构性能结论。

## 主要风险

- **上游词库许可与可追溯性**：锁定版本、记录来源/许可/哈希，导入前失败封闭。
- **词典格式过早固化**：使用内部版本头和独立读写层，P2 不承诺长期兼容。
- **排序质量与延迟相互拉扯**：先建可重复基准，再调整 Beam 和语言模型权重。
- **用户数据损坏或泄露**：与系统词频分离，最小化存储，原子替换并保留可验证备份。
- **TSF 热路径回归**：保持异步请求、取消和 generation 校验，不在按键线程读盘。

## 可回滚方案

- 新引擎作为独立 `owo_engine` 库接入；每个切片保持单独提交。
- Core Service 在接入前保留 P1 固定候选测试夹具，引擎失败时返回显式空/错误响应，不伪造候选。
- 词典编译器与运行时读取器使用格式版本拒绝不兼容数据。

## 本阶段的临时决策

依据已有授权，以下作为 P2 内部可回滚默认，不声明为长期公共约定：

- 首个方案为不带声调的全拼，支持英文单引号音节分隔。
- 先用仓库内小型许可清晰夹具打通代码；完整雾凇资源必须在锁定上游版本、许可和哈希后导入。
- 字典二进制格式和评分权重仅为 P2 内部版本。
- 基准先报告实测分布，不在启动阶段预先承诺虚构的毫秒阈值。

## 需要开发者决定的事项

当前无阻塞 P2.1 的决策。完整雾凇词库的上游版本/许可锁定、默认每页候选数和用户数据保留策略将在首次影响外部资源或迁移前提交证据与备选方案。
