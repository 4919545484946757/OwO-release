# 阶段启动单：P3C 插件框架基础

- 状态：候选验收
- 日期：2026-08-01

## 本阶段边界

P3C 建立插件包、信任、权限、安装和进程隔离基础。受信 `.owopkg` 已可安装到版本化存储；活动版本的进程入口已可通过受控 PluginHost 生命周期在零能力 AppContainer 中启动。插件仍不开放网络，也不把插件代码加载进 TSF 或 Core Service。

## v1 可回滚决策

- `.owopkg` 是受限 ZIP 兼容容器。预检最大包体 64 MiB、单文件解压后 64 MiB、总解压后 256 MiB、1024 项；只接受 Store/Deflate，不接受 ZIP64、多卷、加密、数据描述符、注释、扩展字段、符号链接、重叠条目或可疑压缩比。
- 包路径使用 `/`，必须为严格 UTF-8 安全相对路径；按 Windows ASCII 大小写折叠后不得重复，并拒绝路径穿越、盘符、ADS、反斜杠、空组件、尾随点/空格和保留设备名。根目录必须有精确小写的 `manifest.json`。
- Manifest 是 UTF-8、无 BOM、最大 64 KiB 的封闭 JSON 子集；v1 字符串只接受原始 UTF-8 及引号、斜杠、反斜杠转义。未知字段、重复字段、尾随数据和未知权限失败封闭。
- MVP 仅接受 `runtime=process`、`api_version=1` 和安全的 `bin/*.exe` 相对入口。
- 权限仅接受总控提示词给出的五项白名单；`network=true` 在 v1 无条件拒绝。
- 未签名、签名无效或发布者不受信的软件包拒绝安装；P3C 不提供未签名开发模式。
- 插件安装目录、数据目录和暂存目录分离；可执行目录不可写入运行数据，也不得加入进程 DLL 搜索路径。

## 已完成切片

- 有独立 `owo_plugin` 静态库，不进入 TSF DLL；Core Service 仅通过 `owo_core_plugin` 链接可信宿主与调度代码，不可信插件二进制仍只在独立 AppContainer 进程执行。
- 合法最小 manifest 可解析；路径穿越、未知字段、重复字段、未知权限、网络请求和不兼容版本均被拒绝。
- 默认 Release 构建和全量 C++ 回归通过。
- `.owopkg` 中央目录和本地头必须一致；预检不创建输出文件、不调用系统解压器。
- 预检为每项计算压缩数据 SHA-256，并按路径字节序生成与存档顺序无关的 `OwOPackageInventoryV1` 规范化清单摘要；摘要覆盖路径、压缩方式、CRC、压缩前后尺寸和数据摘要，排除精确根路径 `signature.json` 以避免自引用。
- `signature.json` v1 是最大 32 KiB 的封闭 JSON 子集，只接受 `schema_version=1`、规范化清单摘要、`cms-detached-sha256` 和最大 24 KiB 的规范 Base64 DER CMS。签名内容固定为 ASCII `OwOPackageInventoryV1:<摘要>\n`；不接受自报发布者名称或证书指纹。
- `signature.json` 必须是根目录非空 Store 条目。ZIP 预检从同一次内存快照捕获其精确字节，组合检查随后严格解析并核对摘要，从而不通过重新打开包文件引入 TOCTOU；组合检查的结果名称明确为“签名元数据有效”，不是“签名可信”。
- Windows 信任验证要求 CMS 恰有一个签名者、SignerInfo 内部哈希为 SHA-256、分离签名有效、签名证书显式包含代码签名 EKU，并通过系统 Authenticode 强签名链、当前有效期及缓存撤销状态；链构建禁用 AIA 和全部 URL 下载，离线撤销状态未知也失败封闭。成功时发布者名称和证书 SHA-256 只从已验证证书提取。
- Windows 暂存解包只消费预检保留的不可变包快照，不重新打开源路径。Store 始终可用；`windows-release-zlib` 使用固定 zlib 1.3.2 静态解码原始 Deflate，普通预设遇到 Deflate 时在创建目标前失败。目标必须是本地绝对路径下尚不存在的新目录，既有父链不得含重解析点；文件以 `CREATE_NEW` 写入，不覆盖，全部解码、尺寸和 CRC 在任何写入前验证，写后再通过句柄复核非目录、非重解析点和精确尺寸。
- 唯一高层安装入口只读取 `.owopkg` 一次，并按“预检 → 同一快照签名绑定与 Windows 发布者信任 → 安全暂存解包与输出计数复验 → 版本发布 → 原子激活”执行。未受信包不会创建存储；事务失败只清理自身精确暂存目录，清理失败显式返回保留路径；发布后激活失败保留为可审计的未激活版本。
- 启动恢复扫描是只读、确定性审计：不存在的存储视为空状态；已有存储必须通过固定布局和重解析点检查。扫描报告事务暂存残留、孤立版本/记录、未激活版本、无效活动记录和非预期条目，但不自动删除或切换任何状态。
- PluginHost v1 内部契约独立于安装库，使用 `OWPH` 小端有界二进制消息，提供能力协商、调用、取消、关闭、确认和错误状态。请求 ID 非零，调用超时最大 30 秒，业务负载最大 256 KiB，未知枚举、保留位、尾随数据和无效字段组合失败封闭。
- 权限授权记录绑定插件 ID、精确版本、包清单摘要和已验证发布者证书；授权必须是当前 manifest 声明的子集。缺失记录或任一绑定变化默认拒绝，网络仍不开放。
- 授权记录按精确版本原子保存到独立目录，加载时重新核对安装 manifest 与不可变安装记录。新版本不继承旧授权；无效或悬空授权纳入只读恢复扫描。
- Windows 11 已建立每插件确定性零能力 AppContainer profile 和真实启动探针；集成测试验证 AppContainer 令牌、Job 归属、父句柄不继承，以及父进程可连通的回环端口对子进程不可达。
- 沙箱启动固定在恢复执行前加入 Job，启用关闭即终止、最多一个活动进程、单进程 128 MiB 和未处理异常终止限制。
- AppContainer 本地管道已使用目标容器的会话命名对象路径、128 位随机名、首实例/单实例和显式最小 DACL；首帧后必须模拟客户端并精确核对 `TokenAppContainerSid`。普通同用户进程的 `LOCAL` 视图不可见，即使使用完整限定路径连接也会因 SID 不符被断开。
- 管道传输使用有界长度前缀和有限时 overlapped I/O；超时、超限、身份不符或 OWPH 解码失败立即断开。真实 AppContainer hello 往返已纳入集成测试。
- PluginHost 启动入口每次重新解析活动记录并核对版本、manifest、清单摘要和发布者证书绑定；只接受固定绝对 `.exe` 入口。安装树以受保护 DACL 向插件 SID 只授予读取/执行，独立数据树授予可读写删除但不含 `WRITE_DAC/WRITE_OWNER` 的修改权限，全部拒绝重解析点。
- 插件进程只接收 Windows 启动所需的环境白名单和 `OWO_PLUGIN_DATA`，不继承父进程任意环境变量；固定 `TEMP/TMP` 指向插件数据目录。启动必须完成精确 ID 的 `hello_request` 才对调用方可见。
- 已提供可运行的示例进程插件和端到端宿主测试，验证真实安装版本启动、AppContainer/Job、安装目录不可写、数据目录可写、父环境秘密不泄漏、协议关停，以及宿主会话析构后的 Job 强制回收。
- invoke 控制面只接受以 `.v1` 结尾的版本化服务，单插件并发上限固定为 1，竞争调用立即返回忙碌。每次敏感调用重新核对活动安装绑定和精确版本授权，并要求可信调用方显式标记用户动作。
- 调用最大期限 30 秒；C++20 `stop_token` 触发 OWPH cancel，插件必须先确认取消并在 500 ms 内返回终态。取消不合作、硬超时、协议乱序、身份变化、异常断线或进程崩溃都关闭整个 Job。示例插件端到端覆盖 echo、延迟、取消、挂起和断线场景，并通过 10 次连续竞态回归。
- 插件管理以后端唯一活动记录作为启用状态；停用通过携带预期版本的独占句柄重验并删除活动记录，安装版本、精确授权和插件数据均保留。启用与回滚复用原子版本激活，不增加重复状态源。
- 独立 `owo_plugin_shell` 提供版本化 JSON 列表、启用、停用和恢复清理命令。恢复清理同时绑定用户看到的索引、类别、路径、插件 ID 和版本，并在命令层与仓库层各重新扫描一次；未激活版本只允许切换，不自动删除，不安全条目永远只报告。
- WinUI 设置中心已接入插件版本与恢复维护区，所有状态变更显示具体对象并要求二次确认；Debug 构建与真实启动空仓库冒烟通过。
- Core Service 已拥有独立插件执行线程：`submit` 只进行有界校验和最多 32 项入队，排队、启动和调用共享最大 30 秒总期限。TSF 来源无条件拒绝，只有内部可信用户动作来源能携带敏感权限；插件服务调用深度上限为 8。
- 插件执行审计只记录调用 ID、来源、插件 ID、版本化服务和稳定结果，不记录负载、输入上下文或返回正文。取消、队列满载、启动失败和插件失败均显式降级；活动绑定变化会关闭旧插件 Job。
- 物理卸载只接受精确未激活版本，并与安装、版本切换、停用和恢复清理共享跨进程变更锁。版本目录先原子移动到 `.uninstall-*` 墓碑，随后独占删除精确版本记录与授权；最后一个版本还会删除确定性 AppContainer profile，插件用户数据始终保留。
- 设置中心已提供逐版本卸载确认；卸载事务残留纳入恢复扫描与显式安全清理。测试使用进程级唯一插件 ID，避免触碰真实或并行测试的全局 AppContainer profile。
- P3C 明确不开放外部插件调用协议：生产 Core 的执行器保持空闲，候选 IPC 拒绝 `plugin_invoke` 和所有未知类型；`trusted_user_action` 只用于内部专项测试，不是同用户客户端可提交的凭据。首批插件的真实 UI/快捷键入口进入 P4 单独设计。
- 插件版本目录的原子发布、卸载墓碑移动和回滚对 Windows 实时扫描导致的三类瞬时占用错误执行最多 475 ms 有界重试；Release 存储事务连续 30 轮通过，非瞬时错误仍立即失败。
- 固定 `owo_plugin_shell install` 只调用唯一高层受信安装事务，并在成功或失败时返回稳定 schema 1 JSON。WinUI 设置中心已接入与主窗口绑定的 `.owopkg` 文件选择、精确路径与离线信任风险确认、安装成功身份反馈及失败后的恢复刷新；不存在未签名或低层发布旁路。
- 安装入口切片后 Debug/Release 全量回归均为 39/39，通过 Release 设置中心零警告构建和两项真实 Core 子进程契约；Windows 11 冒烟确认安装按钮、`.owopkg` 原生文件过滤器和取消路径正常，未修改用户插件仓库。

## 后续切片

版本化插件存储的目录布局、发布故障状态和原子激活/回滚语义已经在 ADR 0010 固化。低层发布 API 只接受安装事务产生的预验证暂存目录，版本只新增不覆盖，活动记录原子切换，插件数据目录跨版本保留；用户入口只暴露 ADR 0021 的完整受信事务。
