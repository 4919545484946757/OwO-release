# ADR 0027：刷新期间延迟候选提交

- 状态：P3 后体验优化已采用；修订 ADR 0026 中“快照不可交互”的键盘和候选鼠标语义
- 日期：2026-08-03

## 背景

ADR 0026 在异步请求期间保留上一份候选快照，但同时禁用所有候选交互。`OnTestKeyDown` 因此会将数字键和空格放行给宿主。当用户输完 `ni'hao'shi'jie` 后立即按 `2` 选择“你好”时，最后一个候选请求可能尚未返回，`2` 会直接进入文本框；同一时窗内的“你好”仍可见，造成交互与视觉状态不一致。

## 决策

1. 只要拼音缓冲非空，请求进行期间的数字键和空格仍由 TSF 吞掉，不传递给宿主文本框。
2. 用户选择快照中的候选时，TSF 只暂存其文本，不使用快照的旧 `candidate_consumed` 立即提交。鼠标点击候选使用相同规则；翻页和展开按钮在请求期间仍禁用。
3. 延迟选择同时保留用户选择时的 TSF 文本上下文，不在响应到达时重新查找当前焦点。最新响应必须通过 request ID、context generation 和 page 校验。交换新候选与消费范围后，只有新列表仍包含暂存文本时才尝试向原文本上下文提交，并使用新列表中与该文本对齐的消费范围。
4. 每次新输入、退格、分隔符、翻页、取消或部分提交发起新请求时，清除上一次延迟选择，避免跨输入世代提交。
5. Core 契约固定 `ni'hao'shi'jie` 的候选和消费范围：“你好世界”消费 14 字节，“你好”与“你号”各消费 6 字节。选择“你好”后，TSF 删除 `ni'hao` 及紧随的分隔单引号，对 `shi'jie` 重新请求。

## 结果

快速选词不再把 `1`～`9` 或空格泄漏给应用，也不会用视觉快照的过期消费范围删错拼音。若最新响应已不包含用户点选的文本，本次延迟选择安全丢弃，候选窗显示最新结果供用户重选。

## 边界

- 延迟选择按候选文本匹配。Core 候选生成器对文本去重，因此同一页不存在同文本、不同消费范围的歧义。
- 如果原文本上下文在等待响应时已失效，提交会失败；TSF 不会改为向新获得焦点的文档上屏。

## 回滚

移除延迟候选文本状态，并恢复 ADR 0026 在 `candidate_request_pending` 期间禁用数字、空格和鼠标候选的行为。Core 协议与消费范围契约可独立保留。
