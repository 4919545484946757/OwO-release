# ADR 0018：插件精确版本卸载与存储变更串行化

- 状态：P3C 已采用
- 日期：2026-08-02

## 背景

P3C 已能显式启停、切换版本和清理可证明安全的恢复项目，但总控交付仍要求卸载。卸载会同时改变安装目录、版本记录、授权记录和 AppContainer profile；如果它与安装、启停或恢复清理并发，可能产生活动记录悬空、误删正在使用的暂存墓碑或只完成一半的状态。插件用户数据还必须跨版本保留，不能与程序卸载隐式绑定。

## 决策

1. 卸载入口必须携带合法插件 ID 和精确语义版本，只接受已安装且未激活的版本。活动记录损坏或目标版本仍活动时失败封闭，要求先修复或停用。
2. 安装发布、版本激活、停用、卸载和恢复清理共享一个当前用户会话内的跨进程命名互斥体。最多等待 5 秒，无法取得锁时不改变存储。管理操作频率低，优先保证状态一致性而不是并行吞吐。
3. 卸载先把精确安装目录以 `MoveFileEx(..., MOVEFILE_WRITE_THROUGH)` 原子移动到 `staging/.uninstall-*` 墓碑，再通过拒绝写入和删除共享的独占句柄重验并删除精确版本记录。精确版本授权也通过独占句柄删除，拒绝目录和重解析点。
4. 只有卸载该插件最后一个安装版本时才删除由插件 ID 确定性派生的零能力 AppContainer profile。若后续可回滚步骤失败，恢复版本目录、版本记录和 profile；无法完整回滚时保留可扫描的卸载墓碑并返回诊断。
5. 墓碑按既有安全后序遍历删除，任何重解析点或中途变化都失败。遗留 `.uninstall-*` 由恢复扫描单独标记，只有用户显式确认后才能清理。
6. `data/<plugin-id>` 在所有卸载路径中原样保留，本阶段不提供“同时删除数据”选项。删除用户数据必须是未来独立、再次确认的动作。
7. 设置中心只允许对未启用版本点击“卸载此版本”，确认框显示插件和精确版本，并明确说明版本及授权不可恢复、用户数据保留。后端仍重新验证全部条件，不信任陈旧 UI 状态。

## 结果

P3C 具备安装、启用、停用、版本切换和精确卸载闭环。卸载不会绕过安装绑定，不会删除活动版本或用户数据；最后版本的全局沙箱身份也不会无期限残留。代价是插件存储写操作被保守地全局串行化，崩溃后可能出现需要用户确认清理的卸载墓碑。

## 回滚

移除设置中心卸载按钮、`owo_plugin_shell uninstall`、卸载 API 和 `.uninstall-*` 恢复类别即可退回只启停与恢复清理的状态。版本化安装、PluginHost、Core 调度和输入主链路不依赖卸载入口。
