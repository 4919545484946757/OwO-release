# ADR 0016：插件启停与显式恢复管理

- 状态：P3C 已采用
- 日期：2026-08-02

## 背景

版本化插件存储已经能审计安装事务残留、孤立对象、未激活版本和损坏记录，但只读扫描不能满足用户启停、回滚和恢复维护。管理入口必须避免绕过安装信任链，也不能把正常保留的旧版本或无法证明安全的路径当作垃圾递归删除。

## 决策

1. `active/<plugin-id>.record` 继续作为唯一启用状态源。停用只删除用户确认的精确活动记录，不删除安装版本、版本授权或 `data/<plugin-id>`；启用与版本切换复用既有原子激活 API。
2. 停用请求必须携带预期活动版本。实现以独占、拒绝写入和删除共享的文件句柄读取并重验活动记录、安装绑定和摘要，再在同一句柄上设置删除状态；活动版本已变化时失败，不误停新版本。
3. 设置中心不直接读写插件目录。独立 `owo_plugin_shell` 输出版本化 JSON，并提供 `list`、`activate`、`deactivate` 和 `cleanup` 命令；它与配置后端一同随 unpackaged 设置中心复制。
4. 恢复清理只能消费一次新扫描中的精确项目。设置中心提交用户看到的索引、类别、路径、插件 ID 和版本；命令端全部匹配后，仓库 API 再次扫描并匹配，任一变化都要求刷新重试。
5. 自动清理仅允许事务暂存残留、孤立版本、孤立版本记录、孤立授权记录和无效活动记录。先遍历整棵精确对象并拒绝任何重解析点，再按后序删除。失败可能留下更小的、下次仍可扫描的残留，并返回诊断。
6. `inactive_version` 永远不由清理操作删除，只能由用户显式激活或作为回滚版本保留。`unsafe_store_entry` 永远只报告和展示，必须手工检查。
7. 每个启停、版本切换和清理动作都由设置中心显示具体插件、版本或路径并二次确认。列表刷新与空仓库查询是只读操作。

## 结果

插件管理不引入第二份容易漂移的启用状态，停用也不会造成授权或用户数据丢失。恢复操作同时受到 UI 选择绑定、命令端重新扫描和仓库端重新扫描三层约束。物理卸载与 AppContainer profile 删除随后由 ADR 0018 完成；在线更新仍属于后续阶段。

## 回滚

移除设置中心插件区、`owo_plugin_shell` 和本 ADR 即可退回只读恢复扫描；版本化存储、安装、PluginHost 和输入主链路均不依赖管理 UI。
