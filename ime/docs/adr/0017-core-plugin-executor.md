# ADR 0017：Core Service 插件执行器与调用来源

- 状态：P3C 已采用；外部可信入口按 ADR 0020 明确不在 P3C 开放
- 日期：2026-08-02

## 背景

PluginHost 已能安全启动和调用进程插件，但直接从 TSF 请求处理或任意同用户命名管道转发 `user_initiated=true` 会破坏安全边界。插件启动、握手、调用、取消和回收也都可能等待，不能进入 TSF 按键同步路径。Core 需要一个内部调度点先固定线程、背压、来源与审计语义，再接具体 UI、快捷键或插件服务入口。

## 决策

1. 新增 `owo_core_plugin`，只由 Core Service 和专项测试链接。它依赖可信的 PluginHost 实现，但插件二进制仍只在独立零能力 AppContainer 进程执行；`OwO.TSF.dll` 和通用 `owo_ipc` 不依赖该库。
2. Core Service 启动时创建一个 `PluginExecutor`，默认指向 `%LOCALAPPDATA%\OwO\InputMethod\plugins`，测试或诊断可用 `--plugin-store` 覆盖。构造执行器不创建、扫描或启动任何插件。
3. `submit()` 只做有界校验和入队，不在调用线程启动或等待插件。执行器固定一个工作线程、最多 32 个排队调用，并在不同插件间切换时关闭旧会话；同一插件会话可顺序复用。
4. 调用总期限覆盖排队、插件启动和 invoke，最大仍为 30 秒。排队时过期、启动失败、取消、插件超时和调用失败使用稳定状态返回；队列满载立即失败，不等待空位。
5. 调用来源使用封闭枚举：`tsf_input`、`core_background`、`trusted_user_action`、`plugin_service`。TSF 来源无条件拒绝。只有 Core 内部已验证的 `trusted_user_action` 能携带敏感权限；后台与插件服务调用只能使用零敏感权限。
6. 插件服务调用携带深度，v1 最大为 8。未来代理下游调用时必须递增该值；当前不把该字段暴露给不受信外部协议。
7. 每次结果写一条结构化审计，字段只含 Core 调用 ID、来源、插件 ID、版本化服务和稳定结果。业务负载、输入上下文、插件返回正文和内部诊断均不写入默认日志。
8. 活动绑定在已启动会话后变化时，PluginHost 不再只拒绝调用，而是立即关闭整个 Job。停用或版本切换后的旧进程不能作为空闲会话继续驻留。
9. 当前不新增外部插件调用管道，也不允许命令行或普通同用户进程自报 `trusted_user_action`。ADR 0020 将此冻结为 P3C 验收边界；未来入口必须在 P4 结合实际插件交互另行设计和验收。

## 结果

Core 已拥有独立于 TSF 的真实插件执行路径、确定背压和取消语义，插件失败不会阻塞或改变候选主链路。代价是 Core 可执行文件开始链接 PluginHost 的可信宿主代码，并常驻一个空闲工作线程；不可信插件代码仍不进入 Core 地址空间。

## 回滚

移除 Core Service 中的 `PluginExecutor` 构造、`owo_core_plugin` 目标和本 ADR，即可恢复仅由专项测试直接使用 PluginHost 的状态，不影响插件安装、设置中心管理或输入主链路。
