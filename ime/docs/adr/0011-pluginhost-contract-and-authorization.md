# ADR 0011：PluginHost v1 内部契约与权限授权记录

- 状态：P3C 已采用，公共 SDK/ABI 尚未冻结
- 日期：2026-08-01

## 背景

插件不得加载到 TSF 或 Core Service 地址空间。Core Service、PluginHost 和独立插件进程之间需要可版本协商、可取消、有限长且失败封闭的内部契约；manifest 权限声明只表示插件请求能力，不能自动形成用户授权。

## 决策

1. 新建独立 `owo_plugin_contract` 静态库，仅包含 PluginHost 消息编解码、授权记录和受限运行时传输逻辑。它不链接包解析、CMS、zlib、安装存储或插件可执行文件，避免运行进程继承安装面依赖；Windows AppContainer 管道细节由后续 ADR 0013 固化。
2. PluginHost v1 使用小端有界二进制消息，魔数为 `OWPH`，协议版本为 1。消息头包含消息类型、状态、保留位、非零请求 ID、取消目标请求 ID、超时和能力数量；字符串均使用 `uint32` 长度前缀。保留位、尾随数据、未知枚举、无效类型字段组合和超限内容全部拒绝。
3. v1 支持 `hello` 能力协商、`invoke` 请求/响应、`cancel`、`shutdown`、确认和错误响应。单次业务负载最大 256 KiB，能力最多 32 项，诊断最大 4 KiB，调用超时上限 30 秒。能力与服务名称使用严格 ASCII token；能力必须排序且唯一。
4. `request_id` 标识每条消息；取消消息另带非零且不同于自身的 `target_request_id`。命名管道等待、并发上限、取消宽限、超时强制终止和断线回收已由 ADR 0015 接入真实进程生命周期，不能由消息中的自报状态替代。
5. 授权记录 v1 绑定插件 ID、精确版本、包清单 SHA-256、已验证发布者证书 SHA-256 和用户授予权限。授权只能是 manifest 已声明权限的子集，按字节序排序且不得重复。每次判定都重新核对当前安装 manifest；缺少记录、版本变化、包内容变化、发布者变化、记录被加入未声明权限或权限未被授予都默认拒绝。
6. 授权记录采用最大 2 KiB 的规范行格式，字段顺序固定、字段集封闭。记录位于 `authorizations/<plugin-id>/<version>.record`，使用同目录 `CREATE_NEW` 临时文件、刷盘和原子替换写入；既有记录或父目录为重解析点时拒绝。加载时重新读取已安装 manifest 和安装记录，逐项核对 ID、版本、包摘要、发布者证书、schema 和权限子集；任何失败由调用方按零授权处理。
7. 新安装版本默认没有授权记录，不复制旧版本授权。旧版本记录可随回滚版本保留，但只在其自身安装绑定仍然完整时加载。启动恢复扫描报告损坏、悬空或绑定失效的授权记录，不自动删除。
8. 网络仍无条件关闭。消息 payload 是有界不透明字节，diagnostic 必须是严格 UTF-8；payload 不代表调用方已经获得其中请求的任何能力。PluginHost 必须在每次敏感操作前以当前 manifest、安装绑定和权限名重新判定。

## 影响

协议错误、超时、取消和权限拒绝可以稳定表达，权限升级不会因旧版本授权自动继承。内部二进制契约减少解析歧义且无需新增第三方依赖，但目前不承诺第三方直接链接的 ABI 稳定性。

## 回滚

`owo_plugin_contract` 尚未接入 TSF、Core Service 或插件进程。删除该目标、测试和本 ADR 即可回滚，不影响基础输入、安装存储或模型链路。
