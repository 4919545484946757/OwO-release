# ADR 0008：插件包与信任基础

- 状态：P3C 已采用；在线撤销与受信时间戳边界见 ADR 0019
- 日期：2026-08-01

## 背景

插件包是直接面向不可信输入的供应链边界。TSF 和 Core Service 必须在插件损坏、恶意或不兼容时继续提供基础输入，因此包解析、安装和执行必须拆成相互隔离的阶段。

## 决策

1. 保留总控提示词中的 `.owopkg` 和 `manifest.json`，采用受限 ZIP 兼容容器。P3C 预检器仅解析元数据，不解压；拒绝 ZIP64、多卷、加密、数据描述符、注释、扩展字段、符号链接、重叠条目、非 Store/Deflate 算法和超出文件数、大小或压缩比限制的包。
2. Manifest v1 使用封闭字段集合。只接受严格三段数字版本、反向域名式小写 ID、API 1、进程运行时、安全相对路径和枚举权限。解析成功不代表包可信或可执行。
3. 网络默认关闭，v1 解析器直接拒绝 `network=true`。未来开放网络需同时具备用户授权、运行时强制和可审计撤销，不能只相信 manifest 声明。
4. 正式安装默认要求完整性与发布者信任同时通过。签名必须覆盖规范化 manifest 和每个包文件的路径、大小、SHA-256；不得仅签名一个可被替换的 `signature.json`。
5. 解包必须在隔离暂存目录完成，拒绝绝对路径、驱动器路径、`..`、链接/重解析点、重复规范化路径、设备名、大小或文件数超限，再以原子目录切换发布。
6. 插件只能在 PluginHost/独立插件进程执行，不加载进 TSF 或 Core Service。运行时不继承多余句柄，使用固定绝对入口和安全 DLL 搜索策略。

### `OwOPackageInventoryV1` 规范化摘要

规范化字节流以 ASCII `OwOPackageInventoryV1` 和 NUL 开始，随后是小端 `uint32` 条目数。除精确根路径 `signature.json` 外，条目按 UTF-8 路径原始字节升序排列，每项依次写入：小端 `uint32` 路径字节数、路径字节、小端 `uint16` 压缩方式、小端 `uint32` CRC-32、小端 `uint64` 压缩尺寸、小端 `uint64` 解压尺寸、64 个小写 ASCII 字节的压缩数据 SHA-256。最终对完整字节流计算 SHA-256。

排除 `signature.json` 只解决签名自引用，不意味着忽略它：后续验证器必须严格解析该文件，并用其中的签名验证上述摘要。摘要相同只表示规范化内容相同，不表示发布者可信。

### 签名容器 v1

`signature.json` 使用封闭四字段 Schema：`schema_version=1`、`inventory_sha256`、`format=cms-detached-sha256`、`signature_base64`。CMS 使用 DER 编码并携带签名证书；分离内容固定为 ASCII `OwOPackageInventoryV1:<inventory_sha256>\n`。JSON 不接受发布者名称、信任布尔值或任意证书指纹，因为这些自报字段不能建立信任。

解析成功只证明元数据格式有效。正式接受必须继续满足：JSON 摘要与本次包预检摘要一致、CMS 密码学签名有效、签名者证书允许代码签名、证书链终止于系统受信根、证书时间有效，并按安装策略完成撤销检查。任何未知或离线不可判定状态默认拒绝，开发模式例外不得复用正式“已信任”状态。

包预检要求 `signature.json` 是根目录非空 Store 条目且不超过 32 KiB，并在读取 ZIP 的同一内存快照中捕获内容。元数据组合检查不重新打开路径，避免攻击者在结构检查与签名解析之间替换文件。该检查只返回摘要一致的签名元数据；在 CMS 与证书链验证完成前，调用方不得显示“已签名”或“可信发布者”。

Windows 正式信任路径使用 CryptoAPI：CMS 必须恰有一个签名者，SignerInfo 的摘要算法必须是 SHA-256，分离签名必须覆盖规定的域隔离内容；签名证书必须显式声明代码签名 EKU。随后以系统信任根构建 Authenticode 链，并按 ADR 0019 使用强签名、完全离线链构建和缓存撤销检查。证书无效、自签、链不完整、弱密钥、撤销、撤销状态未知或缓存不可用均拒绝。P3C 不接受“过期证书 + 时间戳”的降级；在线刷新与受信时间戳进入 P5 发布流程。

暂存解包器只消费预检返回的不可变内存快照，避免再次打开源包。Store 始终可用；显式 zlib 构建按 ADR 0009 使用固定 zlib 1.3.2 解码原始 Deflate，未启用依赖时失败封闭。解包前先验证所有条目范围、解码尺寸和 CRC，因此内容损坏不会创建目标目录。目标必须是本地绝对路径下全新的目录，父链不得包含重解析点；子目录逐级创建并复验，文件用 `CREATE_NEW` 和独占写句柄落盘、刷盘，再从句柄复核对象类型与尺寸。

低层暂存 API 不等于安装授权：调用方仍必须先获得 `verify_signed_package_trust().ok`。磁盘写入或系统错误可能留下部分但永不覆盖的暂存目录，后续安装事务只能清理自己生成并记录的精确目录；不得对宽泛路径递归删除。

## 影响

版本化发布、活动记录原子切换和独立数据目录的具体决策见 ADR 0010。该存储层只消费已经由本 ADR 信任与解包流程验证的暂存结果，不改变“未通过发布者信任不得正式安装”的默认拒绝原则。

当前实现可在没有压缩库和证书依赖的情况下验证 manifest 与 ZIP 元数据中最危险的输入面，同时不会制造“已经支持安装或执行”的假象。解压库、证书来源、开发者模式和自动更新源仍可替换，但容器限制和默认拒绝原则保持不变。

## 回滚

`owo_plugin` 当前没有接入任何运行进程。删除该库、测试和 P3C 文档即可完整回滚，不影响输入引擎、配置、ModelHost、Core Service 或 TSF。
