# ADR-0002：P0/P1 IPC 原型信封

- 状态：提议（可替换原型）
- 日期：2026-07-31

## 背景

TSF DLL 与 Core Service 需要低依赖、可诊断的本地 IPC。最终序列化尚无真实性能和兼容数据。

## 决策

传输优先使用 Windows 命名管道。P0 测试信封采用 4 字节小端长度前缀和 UTF-8 JSON 负载，最大负载暂定 1 MiB。逻辑信封必须包含协议版本、请求 ID、上下文代际和错误信息。

此格式不作为稳定公共协议。P1 通过传输与编解码接口隔离实现，禁止业务代码直接依赖 JSON 表示。

## 备选方案

- Protobuf：版本演进成熟，但立即引入生成器和依赖的收益不足。
- 自定义二进制：体积更小，但在缺少基准时增加解析和兼容风险。

## 影响

原型易于诊断且无第三方依赖，但解析开销和类型约束弱。任何解析器都必须限制消息、字符串、数组和嵌套深度。

## 回滚或迁移

保持帧传输与负载编解码分离；基准或协议稳定需求出现后替换负载编码。
