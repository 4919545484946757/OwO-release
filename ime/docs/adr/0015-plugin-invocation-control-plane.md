# ADR 0015：进程插件调用、取消与期限控制面

- 状态：P3C 已采用，Core Service 与设置管理面尚未接入
- 日期：2026-08-02

## 背景

安全启动和 hello 握手只能证明正确 AppContainer 中的已安装入口已连接，不能保证后续调用仍绑定同一版本和授权，也不能处理并发挤压、取消不合作、永久挂起、插件崩溃或响应乱序。调用控制必须由宿主执行，而不是依赖插件自报超时或权限状态。

## 决策

1. `PluginHostSession::invoke` 是 P3C 内部同步调用 API，可由非 TSF 工作线程使用。服务名必须是 OWPH ASCII token 且以 `.v1` 结尾，payload 继续受 256 KiB 协议上限约束，调用期限大于 0 且不超过 30 秒。
2. v1 单插件在途调用上限固定为 1。调用使用不可复制的会话互斥门禁；竞争调用立即返回稳定的忙碌错误，不排队、不写入管道。关停在调用活动时同样立即拒绝。
3. 每次调用重新读取活动记录，并与启动时的完整 manifest、安装路径、清单摘要和发布者证书摘要逐项比较。任何变化按权限拒绝处理，不向已启动进程发送请求。
4. 调用方显式给出本次 payload 所需的权限集合。集合必须是已知、排序后无重复的权限；非空集合还必须携带可信宿主产生的用户动作标记。宿主重新加载精确版本授权记录，并对每项权限执行 manifest、版本、清单和发布者绑定判定。插件自身不能设置用户动作标记或降低所需权限。
5. 每个宿主请求从会话级 64 位非零计数器分配 ID。正常响应必须匹配插件 ID 和 invoke 请求 ID，且只能是 `invoke_response` 或 `error_response`；未知、乱序或身份不符消息视为协议破坏并终止 Job。
6. API 接受 C++20 `stop_token`。取消后宿主发送带独立请求 ID 和目标调用 ID 的 `cancel_request`；插件必须先返回对应 acknowledgement，再返回原调用的终态。取消宽限固定为 500 ms，未确认、未返回终态或取消发送失败都会终止 Job。
7. 独立 watchdog 使用单调时钟执行调用期限。硬超时、管道断线、插件崩溃和协议破坏均关闭整个 Job，使会话失效并返回 `forced_termination=true`。Windows 毫秒等待向下取整仅在截止点附近使用 5 ms 分类容差，不延长实际 watchdog 期限。
8. 宿主只有在本控制面就绪后才通过 hello 宣告排序后的 `cancel.v1` 与 `invoke.v1`。示例插件实现 echo、延迟、合作取消、故意挂起和故意断线，端到端测试覆盖权限拒绝/授予、用户动作门禁、并发上限、取消、硬超时、崩溃回收及失败后的重新启动。

## 影响

插件调用不会进入 TSF 按键线程，单个恶意或损坏插件最多损失自己的会话，不会阻塞基础输入。v1 的并发上限 1 优先保证消息相关性和可审计性；未来提高上限必须先引入独立接收分发器和有界 pending 表，不能仅移除互斥锁。

`required_permissions` 和 `user_initiated` 是可信宿主内部契约，不是插件提供的证明。Core Service 接入时必须由具体操作适配器固定权限映射，并从真实用户交互生成动作上下文，禁止把这两个字段暴露为插件可控参数。

## 回滚

移除 `invoke` API、示例插件调用分支、控制面测试和 hello 能力标记，即可回到 ADR 0014 的仅启动/握手/关停状态。不得通过取消 watchdog、跳过逐次绑定检查或扩大并发上限作为降级方式。
