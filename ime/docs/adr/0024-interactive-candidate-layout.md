# ADR 0024：稳定双行交互候选布局

- 状态：P3 后体验优化已采用；拼音预览与候选消费语义由 ADR 0025 修订，固定宽度与刷新策略由 ADR 0026 修订，展开行为由 ADR 0029 修订
- 日期：2026-08-02

## 背景

首版 Direct2D 候选窗根据每次输入和候选文本动态改变宽度，并在按键处理里先刷新空候选、再标记请求进行第二次刷新。连续输入时，窗口尺寸变化、重复失效和透明清屏会产生可见闪烁。单行内容也无法同时清楚表达拼音分段、候选、分页能力和更多候选入口；非激活窗口没有鼠标上屏路径。

## 决策

1. 折叠候选窗固定为 780×88 DIP 的两行布局。首行显示 `[ni'hao]` 形式的拼音分段，次行显示候选胶囊和右侧的上一页、下一页、展开按钮；显示器工作区不足时才收窄窗口。
2. 内部 Core 协议升级到 v4，在所有消息末尾增加严格的 `syllables` 字符串数组。Core 使用基础候选列表首项实际携带的 `Candidate::syllables` 返回分段；每段限 1～16 个 ASCII 小写字母、总数不超过 32。TSF 只负责用 ASCII `'` 连接，不在按键线程复制拼音解析器。
3. 展开状态将当前页候选按三列排成表格，高度按行数增长；编辑输入或切页时恢复折叠，避免异步结果令展开窗反复伸缩。键盘数字选择、空格上屏和方括号/PageUp/PageDown 翻页保持不变。
4. 候选、翻页和展开区域统一参与像素级命中测试。窗口继续返回 `MA_NOACTIVATE`；候选点击通过当前 `ITfThreadMgr` 的焦点文档取得顶部 `ITfContext`，沿用同步 TSF 编辑会话上屏，因此鼠标不会把焦点从目标文本框移到候选窗。
5. 一次按键先设置请求状态，再只触发一次窗口更新；等待结果和收到结果各进行一次 Direct2D 缓冲绘制。折叠状态不再按文本动态缩放，不使用 `CS_HREDRAW/CS_VREDRAW`，不执行背景擦除，并以不透明颜色清理 Render Target。几何位置和尺寸未变化时不调用 `SetWindowPos`。
6. 命中区域只由最后一次成功布局生成。候选被清空后即使收到旧鼠标消息，索引和 request/generation 校验也不能提交旧候选。

## 结果

连续输入不会再因为每个字母改变窗口宽度或经历“无候选→加载中”的双刷新而闪烁。用户可直接观察解析后的音节边界、点击候选上屏、点击翻页，并在横向空间不足时展开查看当前页全部候选。TSF 仍只新增 Windows 系统图形依赖；拼音解析、词典和模型保持在 Core/ModelHost 边界。

## 已知边界

- 分段对应基础候选列表的首项；智能模型只重排文本而不修改分段。未来模型若允许跨读音改写，必须同时返回与候选绑定的结构化读音。
- 展开表格只显示当前页，跨页仍使用分页按钮；配置允许的页大小上限 9，因此最多三行。
- 鼠标点击依赖宿主仍有有效的 TSF 焦点文档。焦点已被外部操作移走时点击安全失败，不向其他窗口注入文本。

## 回滚

协议 v4 与窗口布局必须成对回滚：恢复 v3 消息 Schema、移除 `syllables`，并恢复无鼠标命中的候选绘制。词库、用户词频和配置文件均无需迁移。
