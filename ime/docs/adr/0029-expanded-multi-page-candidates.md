# ADR 0029：可滚动的多页展开候选表

- 状态：P3 后体验优化已采用
- 日期：2026-08-03

## 背景

ADR 0024 的“展开”只把当前一页候选改排成三列，候选数量仍受每页候选数限制，不能替代连续翻页。候选较多时，用户也需要在不改变输入上下文的情况下浏览并点击更靠后的候选。

## 决策

1. Core 内部协议升级到 v6。候选请求与响应增加 `expanded`，候选响应增加 `page_size`；TSF 据此按设置中心配置的每页候选数划分行，而不猜测配置。
2. 展开请求必须从第零页开始。Core 一次生成最多八页且不超过协议允许的 64 个候选；默认每页五项时最多返回 40 项。展开批次不进入只面向单页候选的异步模型重排。
3. 折叠状态保持单行候选及上一页、下一页、展开按钮。展开状态隐藏翻页按钮，每个原分页占一行，只保留收起按钮；候选编号使用展开批次内的绝对序号，每项保持独立鼠标命中区域和拼音消费范围。
4. 展开视口最多显示五行。多余行由鼠标滚轮、上下方向键、PageUp/PageDown 或 `[`/`]` 逐行滚动。滚动只移动本地视口，不发送 Core 翻页请求，也不改变组合文本。
5. 浮窗宽度取所有候选行所需宽度的最大值，并继续受窗口及显示器工作区约束。空间不足时，同一行候选按原始测量宽度等比例收缩并裁剪文字，保证该页全部候选仍可见、可点击；高度由实际可见行数决定。

## 结果

展开按钮现在提供真正的多页候选浏览。用户可在一个稳定浮窗中滚动并点击最多八页候选；收起后回到普通分页模式，若 Core 仍有更多候选，仍可继续使用翻页。

## 已知边界

- 展开批次受八页和 64 项双重上限保护，避免生成开销和浮窗状态无限增长；这不是词库候选总量上限。
- 数字键仍直接选择展开批次的前九项，其余项使用鼠标点击；滚动键只移动视口。
- 协议 v6 的 Core 与 TSF 必须成套部署，旧版本会按严格协议校验拒绝消息。

## 回滚

Core 与 TSF 必须一起恢复协议 v5，并移除多页展开请求、响应布局元数据和本地滚动视口。配置文件、词库和用户词频无需迁移。
