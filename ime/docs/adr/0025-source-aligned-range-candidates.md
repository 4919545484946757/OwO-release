# ADR 0025：原始输入对齐与范围候选

- 状态：P3 后体验优化已采用
- 日期：2026-08-03

## 背景

协议 v4 只返回一组候选文本和首选词的词典读音。对于不完整拼音 `n`，词典读音可能是 `na`、`ni` 等，候选窗因此会把用户实际输入改写成首选词读音。协议也没有描述每个候选消费了多少输入，所以 TSF 只能在选择任意候选后清空全部缓冲，无法支持 `nihaoshijie` 中先选择“你好”、再继续转换 `shijie`。

连续声母还存在解析歧义：`n`、`m` 本身都是合法音节，纯解析路径预算不能可靠覆盖 `ni + ma` 等常用缩写组合。

## 决策

1. 内部协议升级到 v5。候选响应增加与 `candidates` 等长的 `candidate_consumed` 数组，每项是候选实际消费的原始 ASCII 输入字节数；数组缺失、长度不一致、零值或越界值均拒绝。
2. `Candidate` 同时保存词典读音、原始输入分段和消费字节数。`syllables` 协议字段改为传递原始输入片段，例如输入 `n` 时返回 `n`，即使候选来自词典读音 `na`；输入 `nm` 时返回 `n`、`m`。候选窗仅连接这些原始片段，不添加中括号。
3. 候选生成先提供最佳整段候选，再提供从输入开头匹配的词典词语候选，最后保留其余整段候选。前缀候选必须携带其末音节在原始输入中的结束位置。
4. 选择前缀候选时，TSF 提交候选文本，只删除其消费范围和紧随其后的分隔单引号，然后以新的 context generation 对剩余输入重新请求候选。整段候选仍清空组合状态。
5. 对 2～8 个不含元音的连续声母，候选生成器使用词典感知回退：逐字母查询单音节词、按束搜索组合，并保留每个前缀范围。该回退与正常全拼解析分开，避免将 `nihao` 扩展成逐字母缩写噪声。
6. 智能模型增量排序只能重排基础响应中的候选文本。Core 按文本恢复并返回对应消费范围；模型返回基础集合之外的文本时忽略，避免文本与消费范围错配。

## 结果

候选窗显示的拼音始终来自用户输入；不完整拼音和纠错拼音不会被首选词的完整读音覆盖。`nm` 可按 `n`、`m` 两段生成字符组合。长输入可同时提供整句和词语范围候选，选择“你好”后继续显示并转换剩余的 `shijie`。

## 边界

- 消费范围按当前 ASCII 拼音缓冲计数；协议尚不承担光标位于预编辑串中部的任意区间替换。
- 范围候选只从输入开头开始，不能直接选择中间词并保留左右两侧。
- 用户学习仍按已提交候选文本计数；前缀提交和整段提交均产生一次独立反馈。

## 回滚

协议 v5、Core 与 TSF 必须成对回滚到 v4。回滚会移除范围消费信息和部分提交能力，但词库、用户词频和配置文件无需迁移。
