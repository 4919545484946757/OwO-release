# ADR 0031：本地上下文自适应排序与可调学习灵敏度

- 状态：已接受
- 日期：2026-08-09

## 决策

1. 用户学习同时保留全局候选计数和“规范化输入拼音 → 候选文本”计数。全局计数继续改善常用词排序；上下文计数仅在设置中的“智能排序（本地自适应）”开启时参与排序，避免同一个汉字在无关拼音中被全局过度提升。
2. 学习灵敏度为 1～10 档，默认 7。全局计数每次选择的分数增益为 `250 + (档位 - 1) × 250`，上下文计数为其两倍。档位只影响评分，不改变持久化计数。
3. `candidate_committed` 反馈携带候选文本和实际消费的原始拼音片段。TSF 只在编辑会话成功后发送；部分候选提交只学习已消费前缀，不记录剩余拼音。
4. OWUF v3 在同一校验和与原子替换边界内存储全局、拼音关联与短期语言上下文计数。读取器兼容 OWUF v1/v2；旧文件在下一次落盘时升级，不需要清空用户数据。
5. Core 同步生成基础候选并应用轻量本地排序。ModelHost 接口继续保留给许可证明确、质量验证通过的可替换排序模型；外部模型失败、超时或未安装时不影响基础输入。
6. 当前 MockModelBackend 只用于协议和流水线测试，不作为产品智能能力，也不随普通开发启动脚本启用。
7. 2026-09-17 起，用户学习不再局限于单次直接候选选择。连续消费同一段拼音并最终成功上屏时，TSF 同时记录各个已选片段以及“完整拼音 → 完整组合词”；未转换的拉丁字母、中文标点、Unicode 面板符号、Alt 数字代码和 Agent 返回文本不写入中文用户词库。
8. 拼音关联计数同时构成可检索的本机用户词库索引。候选生成器先按完整拼音召回这些词条，再与系统词典候选统一去重和排序，因此系统词典中原本不存在的用户组合词也能在后续输入时重新出现。OWUF 文件格式保持 v3，不需要迁移既有数据；加载时会从已有拼音关联计数重建索引。
9. 用户词库同时支持有界的不完整拼音前缀召回。输入至少两个拉丁字母且严格匹配已学习拼音的开头时，可召回对应用户词；缺失字符越多，候选分数惩罚越高。候选仍消费当前已输入的全部拼音，不会把预览自动补写为完整拼音，也不会把单字母输入扩散成长用户词。
10. 学习计数采用分层自适应衰减和饱和增益。全局词频、同拼音词频、局部语言上下文计数的计数上限依次为 256、128、64；某条记录将越过上限时，只衰减同一竞争范围内的计数至原来的 3/4，再写入最新证据。全局范围覆盖全部全局词，同拼音和语言上下文只影响各自同组候选。评分在低计数阶段近似线性，随后分别以 32、16、8 为饱和拐点逐渐趋于上限，避免长期习惯或误选无限压过基础词典，同时让更局部的上下文更快适应变化。
11. 语言上下文不再依赖整段文本完全相等。学习和查询均使用最近 1～4、8、16 个字符及当前完整尾部的分层特征，并采用命中项中的最高加权分数。连续保留 1～4 字可覆盖常见短语结构，跳跃保存长尾部则把每个候选的哈希查询限制为最多 7 次，并限制用户数据膨胀。单字符上下文只获得 40% 权重，长度越高权重越强，8 字符起获得完整权重。句号、问号、感叹号和换行会切断此前上下文；各层只在自身“上下文尾部 + 拼音”竞争组内衰减，从而兼顾短语泛化、长上下文消歧和跨句隔离。

## 隐私与边界

学习数据仅包含输入法内部的拼音片段、已上屏候选/组合词和饱和计数，不包含应用名称、窗口标题、周边正文或网络标识。关闭学习停止写入；关闭智能排序停止使用语言上下文分数，但保留用户词条及全局词频以便基础候选召回和重新启用。

## 回滚

关闭 `model_ranking_enabled` 可立即回到全局词频排序。程序仍可读取旧 OWUF v1/v2；若需要回滚二进制，应先导出或清除新格式上下文记录，因为旧程序不能解析 v3 文件。协议 v9 的 TSF 与 Core 必须成套部署。
