# ADR 0010：版本化插件存储与原子激活

- 状态：P3C 已采用
- 日期：2026-08-01

## 背景

插件更新不能覆盖正在使用的版本，也不能把运行数据混入可执行目录。安装期间还可能发生磁盘写入失败、进程退出或系统重启，因此“文件已经解包”“版本已经发布”和“版本已经激活”必须是可区分的状态。

## 决策

Windows 插件存储采用以下固定布局：

```text
<root>/
  staging/<transaction>/
  versions/<plugin-id>/<version>/
  records/<plugin-id>/<version>.record
  active/<plugin-id>.record
  authorizations/<plugin-id>/<version>.record
  data/<plugin-id>/
```

1. `staging` 只接收安装事务创建并完成验证的暂存目录。低层发布 API 接受“已预验证暂存目录”作为前置条件；它本身不是信任授权，也不得用于跳过包签名、证书链或解包复验。
2. 版本目录只新增、不覆盖。暂存目录必须是同一存储根下 `staging` 的直接子目录，并通过同卷目录重命名原子发布到 `versions`。实时安全扫描可能短暂占用刚解包的 EXE；仅对 `ACCESS_DENIED`、`SHARING_VIOLATION` 和 `LOCK_VIOLATION` 在精确源/目标及存储变更锁内做最多 20 次、间隔 25 ms 的有界重试，其他错误立即失败。
3. 每个版本有一份不超过 1 KiB 的封闭字段记录，绑定插件 ID、版本、包清单 SHA-256 和已验证发布者证书 SHA-256。记录文件通过同目录新建临时文件、刷盘和原子替换写入；记录文件及父目录不得为重解析点。
4. `active/<plugin-id>.record` 是唯一活动版本指针。激活和回滚只原子替换该记录，不使用符号链接、junction 或目录覆盖。切换前重新验证目标 manifest 和版本记录的一致性。
5. `data/<plugin-id>` 独立于版本目录，安装、更新和回滚均不得替换或删除它。运行时写入可执行版本目录的限制将在 PluginHost 沙箱切片中强制实施。
6. 发布版本记录成功但活动记录替换失败时，该版本保留为“已安装、未激活”，旧活动记录不变。崩溃也可能留下无活动引用的已发布版本；后续恢复逻辑只能依据严格记录进行识别，不得递归清理宽泛路径。
7. 版本目录在存储语义上不可变。当前切片以“不覆盖既有版本”和受控 API 保证该约束；文件系统 ACL 与运行进程写权限收紧留给 PluginHost 安装集成切片。
8. `authorizations` 按精确版本保存 ADR 0011 授权记录，与活动指针和插件数据分离。安装新版本不创建或复制授权；只有设置中心完成用户确认后才能原子写入。

## 影响

更新和回滚不再依赖覆盖或复制正在使用的目录，插件数据可跨版本保留。一次失败最多产生可审计的未激活版本或精确暂存目录，不会把部分写入版本设为活动状态。

正式安装入口 `install_plugin_package` 把包预检、同一内存快照上的签名元数据绑定与系统发布者信任、暂存解包及写后复验、版本发布和活动记录替换组合为单一高层事务。路径只在首次预检时读取；签名验证和解包不重新打开源包。未通过发布者信任时不初始化存储，也不创建暂存目录。

事务暂存目录使用 `.install-<process>-<tick>-<sequence>` 命名，且只能位于当前存储根 `staging` 的直接子级。解包或发布前失败只清理本事务的精确目录；清理失败时结果必须返回 `retained_staging_path`，不得隐藏残留。版本目录已经原子发布后不再回删：若活动记录替换失败，结果明确返回 `version_published=true`、`activated=false`，供 UI 提示和后续恢复。

`verify_signed_package_trust(path)` 保留为便捷接口；安装事务使用接受 `PackageInspection` 的重载，避免路径二次读取。低层解包和发布函数仍不面向 UI 或外部调用方，也不构成信任授权。

启动恢复使用只读 `scan_plugin_store_recovery`。存储根尚不存在表示没有安装状态，扫描成功且返回空列表；已有存储必须具备完整、安全、无重解析点的固定布局，否则扫描整体失败。扫描逐项报告：`.install-*` 事务残留、无匹配 manifest/版本记录的发布目录、无匹配版本的孤立记录、损坏或绑定失效的授权记录、有效但未激活的版本、损坏或悬空的活动记录，以及非预期或不安全的存储条目。

恢复发现不自动触发删除、激活或回滚。旧版本未激活可能是正常的回滚保留状态，孤立目录也可能包含诊断证据；调用方必须展示具体类别和精确路径，后续显式恢复操作再按记录与用户意图执行。扫描要求本地绝对路径和安全既有父链，并在返回前对发现项稳定排序，便于测试、日志去重和设置中心展示。

## 回滚

将活动记录原子切换到仍然存在且记录有效的旧版本即可回滚。删除存储实现不会影响输入引擎；物理清理旧版本属于后续显式维护操作，不在激活事务中隐式执行。
