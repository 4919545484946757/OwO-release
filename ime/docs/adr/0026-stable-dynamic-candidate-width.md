# ADR 0026：无闪烁快照与动态候选宽度

- 状态：P3 后体验优化已采用；刷新期间的选择交互由 ADR 0027 修订，请求失败恢复由 ADR 0028 修订
- 日期：2026-08-03

## 背景

ADR 0024 用固定 780 DIP 宽度避免每次按键引起窗口伸缩，并在请求新候选前清空旧候选。后续交互验证发现，清空状态仍会形成“旧候选胶囊消失—新候选胶囊出现”的可见闪烁；固定宽度在短候选时留白过多，也不能满足浮框总宽度随当前候选内容适配的要求。

## 决策

1. 输入、退格、显式分隔、翻页和部分提交触发新请求时，不清空当前候选及其消费范围。旧候选只作为视觉快照保留，`candidate_request_pending` 期间数字键、空格、翻页、展开和鼠标命中全部禁用，不能提交过期内容。
2. 新结果通过 request、generation 和 page 校验后，一次性交换候选文本、消费范围、分段与分页状态。无中间空候选帧。
3. 浮框宽度由当前页所有候选的 DirectWrite 实测宽度、编号胶囊基础宽度、候选间距、左右边距、候选与控制区间距，以及上一页、下一页、展开按钮宽度求和。拼音预览更宽时以预览宽度为准。
4. 宽度下限为 240 DIP，上限为 1400 DIP；最终像素宽度继续受当前显示器工作区约束。展开状态沿用同一宽度，只增加候选表格所需高度。
5. 窗口位置或尺寸改变时使用 `SWP_NOCOPYBITS`，随后通过无背景擦除的同步 `RedrawWindow` 完成当前帧绘制；尺寸不变时同样只执行一次同步绘制。

## 结果

连续输入期间候选文本和胶囊不再经历清空与重建两帧；本决策最初禁用视觉快照交互，后由 ADR 0027 改为验证后延迟提交。新候选到达时内容与窗口宽度在同一次更新中生效。短候选页使用更紧凑的浮框，长候选页按内容扩展，超出屏幕时安全收窄。

## 边界

- 请求进行期间会继续显示上一帧；超时后的终态清理与错误反馈由 ADR 0028 规定。
- 显示器工作区不足时，折叠行可能只显示能容纳的前几个候选；展开按钮仍可查看当前页表格。

## 回滚

回滚到 ADR 0024 的固定 780 DIP 宽度，并在请求开始时清空候选。该回滚不影响 Core 协议、词库和配置。
