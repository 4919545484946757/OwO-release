# ADR 0020：P3C 不开放外部可信插件调用入口

- 状态：P3C 已采用
- 日期：2026-08-02

## 背景

插件敏感权限要求一次真实用户动作，但当前设置中心、Core Service 和 TSF 都是 unpackaged 同用户进程。普通命名管道、命令行参数、JSON 字段或客户端自报进程名不能证明一次不可伪造的用户动作；把这些信号映射成 `trusted_user_action` 会让任意同用户进程借用已授权插件读取输入上下文等敏感数据。

P3C 的交付目标是建立插件包、安装、管理、授权、沙箱、宿主与调度基础，不要求在没有首批官方插件交互设计时提前开放敏感调用面。

## 决策

1. P3C 不增加外部插件调用 IPC、命令行或设置中心调用按钮。生产 Core 只构造空闲 `PluginExecutor`，不把它交给候选管道服务器，也没有任何生产代码调用 `submit()`。
2. Core/TSF v1 IPC 继续使用封闭消息枚举，只包含候选、学习、增量更新和关停语义；`plugin_invoke` 及任何未知消息类型解析失败。不得在现有候选消息中偷渡插件 ID、服务、权限、来源或任意 payload。
3. `PluginCallSource::trusted_user_action` 仅是 `owo_core_plugin` 内部归因值，不是凭据、令牌或可序列化协议字段。未知枚举值失败；TSF 来源无条件拒绝；非可信来源携带任何敏感权限仍失败。
4. 设置中心的 `owo_plugin_shell` 只管理已安装版本、启停、卸载和恢复项目，不能启动或调用插件。管理二次确认不自动转换为运行时敏感调用授权。
5. P4 若需要官方插件用户动作，必须另行选择 Core 自有交互入口，或具备受保护安装位置、可验证包身份/签名、客户端进程与会话绑定、一次性挑战和重放防护的认证 broker。新入口必须单独威胁建模和验收，不能只检查同用户 SID。
6. 专项测试可以直接构造内部来源，验证执行器和 PluginHost 的权限防线；这不形成产品入口，也不把测试 API 暴露给外部进程。

## 结果

P3C 的插件执行基础可验证但默认不可从外部触发，敏感权限不会因为伪造来源而被绕过。代价是当前设置中心不能“运行插件”，首批插件的快捷键和 UI 触发要在 P4 结合实际交互设计完成。

## 回滚

如果未来已经具备可验证的用户动作 broker，应新增 ADR 和独立协议，而不是删除本决策后复用候选管道。移除内部执行器不会影响输入、安装或插件管理。
