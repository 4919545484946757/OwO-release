# 插件化输入方案：分阶段接入

当前已开放实验性插件方案选择及 TSF 接线：通用接口、隔离进程、独立授权、异步候选、Unicode 编码编辑、分页/展开与受保护上屏。默认方案仍为全拼，需要用户明确授权并选择插件方案；它不是稳定 SDK、二进制 ABI 或 IPC 格式。当前仅有小型表码示例，不包含真实仓颉/五笔词库；支持宿主范围及实机验收限制见文末 S3b2。

## 阶段启动单：输入方案 S1

目标：把方案描述、原始编码、候选文本和消耗范围分离，避免用拼音音节模拟所有输入方案。

范围：`input_method_provider.h/.cpp` 提供描述与验证接口、提供者注册/移除、请求派发和响应校验；专用测试覆盖仓颉、五笔、外文转写模拟提供者。模拟提供者只验证协议边界，不包含真实词典。

明确不做：不改现有拼音算法；不引入词典依赖；不加载第三方 DLL；不修改插件清单或权限；不开放 UI 中的第三方方案选择。

数据流：宿主工作线程 → 注册的提供者适配器 → 身份/范围/容量校验 → 宿主候选结果。提供者不直接上屏。

验收：三类方案可注册及派发；非法 UTF-8、错误身份、越界范围和候选数量超限被拒绝；取消和停用后返回的旧结果不发布；提供者异常不外泄详细信息。

风险及回滚：接口仍需结合真实方案修订；撤销本阶段提交即可移除，不涉及配置或用户词库迁移。公共命名、权限和线协议在 S2 前确认，当前不冻结。

## 宿主侧实验接口

头文件：`include/owo/engine/input_method_provider.h`。接口为 C++20，`InputMethodProvider` 是宿主适配器，不是要求第三方导出虚函数的 DLL 接口。S2a 的进程适配器实现该接口。

### 描述与输入

- `id`：`<plugin_id>/<local_scheme_id>`，注册时拒绝跨命名空间方案 ID。正式接入时宿主还须验证 `plugin_id` 与已授权清单一致，不能只信描述中的声明。
- `kind`：`phonetic`、`table`、`transliteration`，分别适用于音码、形码/表码和外文转写；不会根据类型调用拼音解析器。
- `language_tag`：语言标识，当前仅做字符和长度校验，完整 BCP 47 校验留到配置接入。
- `alphabet`：Unicode 标量集合，明确包含支持的大小写、分隔符及非 ASCII 字符；宿主校验原始输入，不隐式转小写或补音节。
- `max_input_bytes`、`max_candidates`：输入字节限长与每次响应候选上限；硬上限分别为 16384 字节和 256 条。

请求包含 `request_id`、`session_id`、`scheme_id`、`action`、`input`、`caret_byte`、`page`、`page_size` 和 `selected_candidate_id`。动作包括组合输入、选择和取消。选择必须携带候选 ID，其他动作不能携带该 ID；只有后续宿主会话层保存的有效候选才可被选择，字符串合法不等于获得执行权限。

### 候选与范围

响应携带相同的请求/会话/方案/页身份、状态、显示预览、候选、`has_more` 和简短诊断。每条候选具有独立 ID、文本、注释及 `consumed_ranges`。

范围是原始 UTF-8 输入的半开字节区间 `[begin, end)`，必须非空、有序、不重叠、不越界且落在字符边界。不能基于预览字符串、音节数或候选文字长度推算消耗范围。例如输入 `éa` 的字节长为 3，`é` 的范围为 `[0, 2)`，不是 `[0, 1)`。TSF 的 UTF-16/UI 光标位置需由适配层显式转换。

`preview` 仅用于显示，不解释为命令。候选可消耗一段或多段原始编码；剩余编码继续组合。是否暂存、上屏或学习由宿主策略决定，而非提供者直接写入应用。

每条文本最多 4096 字节；显示预览最多 16384 字节；诊断最多 1024 字节；响应内容计数预算为 128 KiB（非最终序列化包长）。S2 需对实际 IPC 包长另设边界。

### 注册、取消与错误

注册表只持有描述与适配器生命周期，不授予权限、不加载插件代码。相同方案 ID 不允许重复注册。移除插件后，即使原提供者仍在运行，旧注册代数的结果也被丢弃。

派发时不持有注册表锁调用提供者；提供者负责自身状态的同步。基础注册表的 `stop_token` 为协作式取消：调用前/后检查，不能强制终止卡死的本地提供者。S2a 的进程适配器使用 PluginHost 超时与 Job 终止，后台工作线程处理最新请求仲裁；不能在 TSF 按键回调中同步等待本接口。

不可用、取消、异常或非法响应均不返回可选择候选。原始输入由宿主保留；不得以出错为理由清空或上屏用户输入。身份校验只保证与当前传入请求一致，跨请求的新旧优先仍需宿主调度层处理。

## 后续解耦与安全清单

S2/S3 必须逐项处理现有拼音专用路径，不能只扩大配置的方案 ID 白名单：

- 把 TSF 字符接收、预览分隔和音节光标移动改为方案能力驱动；Agent 的首字符 `v`、拼音纠错和缩写不能强加到形码或外文方案。
- 分区、模型排序、局部提交、标点转换和词预测按方案能力启用；不支持的功能明确禁用或回退。
- 词典、用户词频及学习编码带方案命名空间，避免五笔编码和拼音键冲突；迁移旧拼音数据保持兼容。
- 用户启用、停用、切换方案时明确生命周期，旧会话结果不能覆盖新方案候选。
- 提供者默认只获得本次编码及必要配置，不获得跨应用上下文、剪贴板、文件访问或网络权限。词典只读资源访问单独授权，密码/安全输入框不外发组合文本。
- 独立进程插件不进入 TSF/Core 地址空间；输入方案权限不隐含执行程序、删除文件或 Agent 权限。
- S2 先定义清单扩展、权限与 IPC 版本协商，再添加第三方安装支持。此文档中的结构不能直接填入现有封闭的 API v1 清单。

## 阶段启动单：输入方案 S2a

目标与范围：使用现有 PluginHost v1 AppContainer/Job/命名管道基础设施，增加实验输入方案载荷、授权绑定的进程提供者和一个独立的 Core 后台输入方案工作线程，贯通小型表码示例。

明确不做：不改变插件清单格式，不新增权限，不自动扫描/启用插件，不修改 Core 对 TSF 的正式候选请求入口，不开放方案选择，不修改拼音词典、学习和配置。

核心数据流：宿主批准的描述 → `register_plugin_input_method` 验证 active 安装绑定与授权 → 注册表 → `InputMethodWorker` → `ProcessProvider` → PluginHost → 独立插件 → 严格解码及候选校验 → 后台结果。

验收标准：真实沙箱进程返回候选及下一页；格式错误、进程崩溃、超时可恢复；新输入取消旧请求；撤销授权或停用后无候选输出；失败不修改原始输入。

S2a 当时的风险：`input.context` 比方案所需权限更宽，只用作实验门禁。S2b1 已改为独立 `input.scheme`，不会继承旧授权。后台路由仍未与服务客户端身份及安全输入框检测绑定，因此不能接入现有按键链路。

回滚：撤销 S2a 提交，保留 S1 接口与测试；没有用户数据迁移。线协议、服务名均显式标记 experimental，可替换，不冻结。

### 进程适配与后台路由

`include/owo/core/input_method_runtime.h` 提供授权注册与 `InputMethodWorker`。注册只接受已安装且 active 的 `process` 插件，不安装、不授权、不启用。输入方案描述由宿主提供，插件不能自行注册他人的方案。

每次调用前/后交叉验证安装路径、版本、内容摘要、发布者摘要及明确的 `input.scheme` 授权。缺少授权不得发送编码；撤销、停用或更新使旧结果失效。停用被下一次请求检测到时终止保留的进程会话；立即主动通知生命周期和焦点切换仍为后续工作。

选择请求必须属于提供者最后一次有效候选响应的同一会话、原始编码与候选页，并引用实际返回的候选 ID。未知、过期选择在进程调用前被拒绝；错误、取消和新的请求会使旧选择快照失效。宿主负责消费编码和上屏，插件不能通过选择响应直接执行系统操作。

适配器仅发送本次请求字段，不获取应用信息或局部上下文。`user_initiated` 由宿主选定方案的适配器设置，不从外部载荷反序列化；正式 Core 接线前必须补上方案选择许可、会话绑定和密码/安全场景阻断，不能拿该内部函数当通用插件执行入口。

后台组件只有一个线程和一个待处理槽；提交不等待插件。新提交取消运行中的旧调用，并以取消结果替换尚未派发的请求。发布前再比较提交代数，避免忽略取消的旧结果覆盖新输入。调用方应在 Core 回调中消费 future，不能在 TSF 按键回调 `.get()`。

注册超时参数为 1–5000 ms，默认 1000 ms，包含启动与请求；不配合取消的进程最多还有 PluginHost 的 500 ms 取消宽限。实际注册表中的任意本地提供者仍只有协作取消；正式第三方方案必须走进程适配器。

### 实验载荷格式

服务：`owo.input-method.experimental.v1`，外层仍是现有 PluginHost v1 消息。S2b1 起使用独立 `input.scheme` 门禁，既在后台执行器的标准服务表中注入，也在输入方案适配器调用 PluginHost 时明确要求。此前实验用的 `input.context` 不再满足该服务的授权要求。

载荷为小端二进制，不是 JSON。数字宽度固定，不序列化 `size_t`、指针、虚函数或编译器布局；字符串为 `u32` 字节长度加 UTF-8 内容。

- 请求：`OWIQ`（4 字节）、`u32 version=1`、`u64 request_id`、session 字符串、scheme 字符串、`u8 action`、input 字符串、`u32 caret_byte`、`u32 page`、`u32 page_size`、selected ID 字符串。
- 响应：`OWIR`、版本、request ID、session、scheme、`u8 status`、preview 字符串、`u32 page`、`u8 has_more`、diagnostic 字符串、`u32 candidate_count`；每条候选为 ID/text/annotation 字符串、`u32 range_count`，随后每段的 `u32 begin/end`。
- 动作值为 compose=0、select=1、cancel=2；状态值为 success=0、cancelled=1、unavailable=2、error=3；布尔值只能为 0/1。

最终载荷最多 128 KiB；解码在分配前限制字符串、候选数和区间数，拒绝截断、尾随字节、未知版本及身份不一致。失败时输出对象清空，不允许使用半解码的候选。候选编号和展示文本不能作为控制指令执行。

示例源代码位于 `plugins/input-method-example`，只有四条演示表码，无完整仓颉/五笔词典。故障注入只编译进测试探针，不存在于示例发行目标。

## 阶段启动单与验收：S2b1 发现、授权和会话

目标：让宿主从已授权的插件进程发现真实声明的输入方案，而不是硬编码某个插件的字符集合；为 Core 服务接线提供会话门禁。

本阶段文件：方案权限/服务目录、设置中心权限说明、描述编解码、Core 输入方案运行时、表码示例、定向测试及本文档。明确不做：不增加 TSF 按键拦截，不扩展现有候选协议，不自动切换输入方案，不发布安装包。

### 独立授权与隐私

`input.scheme` 是高风险但不要求完整信任的独立权限，可运行于现有 AppContainer 沙箱。用户需要针对包、版本和摘要明确授予；现有 `input.context` 或任何其他权限不能代替。旧实验插件需更新清单并重新授权，不自动继承；现有拼音用户数据无需迁移。

该权限只允许宿主将所选方案的本次编码、光标字节位置、候选分页、候选 ID 与请求/会话 ID 传入。输入内容可能含有私人信息，应在授权说明中告知。它不授予窗口周边文本、历史上下文、剪贴板、网络、系统操作或直接上屏能力。代码和权限命名仍属于分阶段接口设计，不将实验线协议冻结为公共 ABI。

### 方案发现协议

调用 `discover_plugin_input_methods(root, plugin_id)`，仅针对用户明确请求的一个已启用、已授权进程插件，不在启动时扫描并执行所有插件。调用只能位于宿主控制工作线程；它可能等待进程启动与超时，不能从输入回调直接调用。

服务为 `owo.input-method.describe.experimental.v1`，请求载荷为空，响应为 `OWID` 元数据。响应格式：4 字节魔数、`u32 version=1`、`u32 descriptor_count`，随后每项依次为 ID、plugin ID、名称、语言字符串，`u8 kind`、`u32 max_input_bytes`、`u32 max_candidates`、`u32 alphabet_count`、Unicode 标量的 `u32` 序列。字符串仍为 `u32` 长度加 UTF-8，小端数字。

单插件最多声明 16 个方案，响应不超过 128 KiB；拒绝重复 ID、跨插件命名空间、非法 Unicode、超限和尾随字节。解码失败不会返回部分描述。音码=0、表码=1、转写=2。

发现前/后检查授权及安装绑定，结果带版本、内容摘要和发布者摘要；打开会话时再次核对，避免发现旧版本后误注册新版本。发现不授予权限、不启用插件、不发送用户编码。发现进程随后释放，输入进程由实际提供者按需启动。

### Core 会话请求组件

`InputMethodSessionRouter` 提供 `open(owner_id, session_id, plugin_id, scheme_id)`、异步 `submit(owner_id, request, sensitive_input)` 及 `close(owner_id, session_id)`。

当前只允许一个活动组合会话：其他 owner 不能劫持或关闭它；同一 owner 可重新选择方案。宿主必须先关闭旧 owner 再切换焦点。`open` 只接受插件真实声明的方案，绑定版本/摘要后才建立路由；不是任意服务执行接口。

输入请求必须匹配 owner、会话及方案，且 request ID 严格递增。无效输入不会抢占有效任务；有效新输入仍按最新请求优先派发。敏感场景请求在发送前被拒绝，同时取消任务并关闭会话，之后必须明确重新打开。打开过程中的关闭操作会使发现代数失效，迟到的发现结果不能重新打开已取消会话。

owner ID 必须由可信宿主根据实际客户端身份生成或验证；`sensitive_input` 必须来自 TSF/宿主的安全场景判断，不能采信插件自己声明的值。当前 C++ 组件并不自行识别密码框，也未连接服务 IPC。S2b2 接线时需要提供真实身份、安全状态和焦点生命周期；完成前不得对外开放此输入路径。UI 获取结果时也必须检查当前焦点/会话代数，不能消费已经关闭会话的早前已发布结果。

- 管道：`\\.\pipe\OwO.InputMethod.Core.InputSchemes.experimental.v1`。

### 焦点与隐私门禁

默认策略要求连接进程拥有当前前台窗口及焦点控件，只允许标准 Edit/RichEdit，
拒绝 ES_PASSWORD、无焦点、其他进程和未知控件。不会采集控件文本、剪贴板或应用历史。
客户端 `sensitive_input=true` 会关闭会话，false 无法放宽宿主检查。
等待 IPC 时也定期检查焦点，焦点控件变化立即取消、断开连接，释放管道给新焦点应用。
发送结果前再次核对焦点、会话以及安装版本/摘要/权限，拒绝撤销授权后留在队列中的结果。

`FocusResolver` 是 C++ 宿主/测试专用注入点，不从配置、IPC 或插件加载。
当前只能识别窗口级焦点，不能完整识别同一控件内的 TSF 文档/光标位置变化，
也不支持 WinUI 等未知输入控件。S3 必须补齐文档级安全判断与生命周期，不能删除门禁
来扩大控件覆盖范围。瞬时焦点切换发生在采样间隔内的情况也需要 TSF 事件补足。

### 请求时序与有界执行

1. discover/open 提交后立即返回 pending，ticket 为被提交请求的 request ID。
   独立控制线程完成发现/打开，最多一个活动任务和一个排队任务，不按键创建线程。
2. 使用新且严格递增的 request ID 发送 poll，ticket 指向原任务。
   ready 的发现/打开 payload 为 OWID；打开返回实际选中的单一描述。
3. submit payload 为该方案的 OWIQ；内层 request ID 必须等于外层 ID，session/scheme
   必须匹配打开会话。返回 pending；ready 的候选 payload 为 OWIR。
   新有效输入取消旧输入，旧 ticket 不能继续读取；非法输入不会替换合法的待处理任务。
4. close 只可关闭本连接匹配的 session；返回 ready 空载荷。打开过程中关闭也有效，
   迟到的发现不能重新打开会话。已消费的 ticket 不可再次读取。

控制任务未被消费/取消完成前，新的 discover/open 会返回 busy，客户端应稍后用新 ID
重试。错误返回固定短诊断，不记录用户编码；用户原输入必须仍保存在客户端组合态。
本阶段是 pull 协议，不发送主动 UI 更新；应用不要在键盘回调中等待 future 或轮询。

## S3b1：后台客户端与文档生命周期适配

`InputMethodAsyncClient`（`include/owo/ipc/input_method_client.h`）封装独立实验管道，
所有 exchange、open 和 poll 都在一个后台线程执行。UI 入口只排队并返回 promise future；
UI 应在消息循环检查完成状态，不在按键回调或编辑会话中调用阻塞 get。
最多一个执行中任务和一个待执行任务，有效新任务会取消旧任务及旧结果发布。
非法输入、错误文档代数或重放请求在排队前拒绝，不抢占有效任务。

### 调用与编号

- discover(generation, plugin_id)：显式发现，返回实际声明列表，不安装、启用或授权插件。
  发现会结束此客户端的旧连接，不用于输入中反复扫描。
- open(generation, plugin, scheme, session, sensitive)：返回实际选中描述。打开完成前拒绝输入。
  新 open 重置旧连接，不把旧组合态带入新会话。
- submit(generation, request, sensitive)：只接受匹配已打开方案/会话和严格递增本地 ID 的请求。
  返回包含文档代数和经验证的候选响应。
- close()：立即撤销本地结果发布资格，后台断开连接，触发服务侧会话关闭；UI 不必等待它。

open/submit 的 sensitive 参数默认 true，调用者必须根据可信 TSF 安全状态显式传 false。
true 会取消会话且不发送用户编码；它不是插件可配置的豁免选项，也不能放宽服务焦点检查。

客户端内部独立维护实际管道编号，因为一次用户请求可能生成多次 poll。
先将用户请求映射到新的线协议 ID，严格验证整个响应的 ID/session/scheme/page/ticket，
再还原本地请求 ID；不能让 poll 编号冲突或污染组合态的本地序列。

总操作等待上限为 2 秒，每次管道 exchange 使用至多 200 ms 的剩余预算，轮询间隔
10 ms；取消可唤醒轮询等待，但正在进行的 exchange 要等其期限结束。
服务/授权拒绝、IPC 断连、超时或非法响应只返回固定诊断，不记录原始编码。
底层持久客户端可能在交换失败后尝试重连并重发当前交换载荷，但不会自动重新 open；
新服务连接没有方案绑定时会拒绝 submit。恢复需要宿主显式重新打开，不能自动切入全拼。

### 文档级结果门禁

`InputMethodDocumentSession`（`include/owo/tsf/input_method_session.h`）是 UI 线程上的
文档生命周期适配器，不持有 COM 指针、不读取应用文本。enter 只接受新的递增文档代数；
bind 只接受该代数且操作类型为 open 的成功结果，发现描述不能冒充已打开会话；
每代只能绑定一次，避免重复处理完成 future 清空输入。
apply 和 finish_commit 都检查当前文档代数。

宿主失焦、替换文档/上下文、进入敏感场景或结束输入服务时，必须同时调用
文档适配器 invalidate 和后台客户端 close。仅取消后台任务不够：先前已完成的 future
不会被追溯修改，UI 仍必须通过文档门禁拒绝它。新文档不能复用旧代数，确认上屏前也需
检查原 ITfContext/编辑会话身份；代数不是权限凭据。

本轮已经验证实际管道 → 后台客户端 → 文档门禁 → Unicode 组合态 → 两阶段选择确认，
但**尚未挂接实际 TextService 的 TSF 事件与按键**，也没有在设置中心开放插件方案。
未部署、未打包，不改变当前全拼路径。S3b2 将处理 TSF 安全上下文、编辑会话、非阻塞
完成消息以及焦点事件；之后才开放方案发现/选择与按键能力配置。

| 内存预算 | 通用沙箱 128 MiB；当前明确授权方案的沙箱 512 MiB；原 full-trust 512 MiB 不变 |
| 应用上下文、网络、系统操作及其他资源 | 独立授权及相应宿主接口，不随 `input.scheme` 自动开放 |

512 MiB 是 Job 内存上限而非预分配。仅在清单声明且当前安装绑定的授权有效时提高，
仅声明权限不能获得该预算。单进程、零网络 capability 与文件 ACL 隔离保持不变。
权限名称不代表任意宿主 API 已实现；需要新能力时应添加独立、可审计的代理接口。
不自动切换 full-trust、不自动授予全盘访问或上下文权限。

## S3b2（第二部分）：开放插件输入方案（实验性）

设置中心「输入方案」页新增「发现已授权插件输入方案」。先在插件页完成安装、风险
确认、`input.scheme` 单独授权和启用，再点击发现；只有实际返回合法描述的活动插件
进入列表。选择后点击保存，配置值为 `plugin:<plugin_id>/<local_scheme_id>`。
该值只是引用，不能作为路径或权限凭据。未安装/停用/撤销授权的已保存引用不会被静默
改为全拼，输入失败时保留原编码。重新发现会执行已获授权插件的 describe 服务，
不采集应用文本，不安装或自动授权插件。

Core 现在默认启动受保护方案管道，无须另传实验开关；管道不可用不会阻止基础候选服务。
实际 TSF 接线使用独立文档门禁、单后台客户端与 Unicode 编码编辑器，不经过全拼
纠错、Agent 的 `v` 标记、拼音模型排序、分区或拼音用户学习。
设置中心将这些不适用的选项以及候选暂存、拼音失焦上屏、文本区导航、中文标点转换
置灰，保留原配置供切回内置方案使用；插件编码之外的字符由应用正常接收。

- 普通编码保留大小写和显式分隔符；只接受方案 alphabet 中的 Unicode 标量。
  首次异步打开前暂存输入，若方案拒绝该编码则保留并显示错误。
- Backspace/Delete 删除编码，配置中的左右移动快捷键及鼠标点击预览移动编码光标。
  预览暂显示原编码而非提供者装饰性 preview，避免在未定义映射时错删编码。
- 数字选择、Space 选择首候选、鼠标选择走同一 ID 确认路径；等待新候选时保留旧画面，
  但旧候选不能被选中。数字在存在组合态时保留给候选选择。
- 分页使用方案协议；展开请求至多 descriptor.max_candidates 个候选，再以配置每页
  数量分行，滚轮浏览；不是无限拉取，超出协议上限的列表仍需分页获取。
- Enter（及配置的原样输出快捷键）直接输出原编码；切到英文时也先原样输出编码。
  Escape、失焦、文档/输入位置改变会关闭方案会话；插件路径不使用拼音失焦自动上屏。
- 插件先确认选择，宿主再异步申请 TSF 写会话；成功写入后才消耗编码范围。
  写入前再次验证文档代数、COM 上下文身份、原选择范围、安全元数据及期限。
  写入超时/失败保留编码，迟到写会话不得继续上屏。写会话期间按键排队，结束后
  在普通消息循环中恢复当时的修饰键状态处理，不在写锁中嵌套请求读取。
