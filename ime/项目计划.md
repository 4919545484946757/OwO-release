## OwO 输入法计划增补：字符编码转换功能

### 一、新增官方插件

在首批官方插件列表中增加：

1. **字符编码转换插件（Character Code Converter）**
   - ASCII、Unicode及常见字符编码的查询与转换；
   - 支持单字符、字符串和批量文本；
   - 支持以列表形式逐字符预览；
   - 支持从剪贴板、选中文本和输入法预编辑文本读取内容；
   - 支持将转换结果复制、替换原文或导出；
   - 可被AI Agent、OCR和文本处理插件调用。

更新后的首批插件列表：

1. 截图工具插件；
2. OCR识别与翻译插件；
3. 语音输入插件；
4. 文本润色与翻译插件；
5. **字符编码转换插件**；
6. 快捷键管理插件；
7. AI Agent核心插件。

------

### 二、功能定位

字符编码转换插件负责在以下表示之间转换：

```text
普通文本
↔ Unicode码点
↔ ASCII数值
↔ UTF-8字节
↔ UTF-16编码单元
↔ UTF-32数值
↔ 编程语言转义序列
↔ HTML/XML字符实体
```

需要明确区分以下概念：

- **ASCII**：仅定义`0～127`范围内的字符；
- **Unicode码点**：例如字符“中”为`U+4E2D`；
- **UTF-8**：Unicode字符的一种字节编码方式；
- **UTF-16**：以16位编码单元表示Unicode字符；
- **转义序列**：源代码中表示字符的书写形式，例如`\u4E2D`。

非ASCII字符的ASCII列应显示为：

```text
不适用（Non-ASCII）
```

不得错误地把Unicode码点直接称为ASCII码。

------

### 三、支持的转换格式

#### 3.1 ASCII表示

对于ASCII范围内的字符，支持：

- 十进制；
- 十六进制；
- 八进制；
- 二进制；
- ASCII控制字符名称；
- ASCII字符反向转换。

示例：

```text
A
十进制：65
十六进制：0x41
八进制：0101
二进制：01000001
```

支持输入：

```text
65
0x41
0101
0b01000001
```

并转换为：

```text
A
```

对于数值输入，必须允许用户显式选择进制，避免把`0101`误判为十进制或八进制。

------

#### 3.2 Unicode码点

支持以下形式：

```text
U+4E2D
4E2D
\u4E2D
\U00004E2D
&#20013;
&#x4E2D;
```

支持功能：

- 字符转Unicode码点；
- Unicode码点转字符；
- 多码点序列解析；
- 增补字符平面字符；
- Emoji和组合字符分析；
- Unicode字符名称与分类显示；
- 无效码点检查。

示例：

```text
中 → U+4E2D
😀 → U+1F600
```

必须拒绝：

- 大于`U+10FFFF`的值；
- Unicode代理项范围内的独立码点；
- 格式不完整的转义序列。

------

#### 3.3 UTF-8

支持：

- 文本转UTF-8十六进制字节；
- UTF-8字节转文本；
- 空格分隔、逗号分隔和连续十六进制输入；
- 无效UTF-8序列检查；
- BOM识别；
- 逐字符字节长度显示。

示例：

```text
中
→ E4 B8 AD
```

输入格式可以包括：

```text
E4 B8 AD
0xE4, 0xB8, 0xAD
E4B8AD
```

------

#### 3.4 UTF-16

支持：

- UTF-16LE；
- UTF-16BE；
- BOM识别；
- UTF-16编码单元显示；
- 代理项对解析；
- 非法孤立代理项检测。

示例：

```text
😀
Unicode码点：U+1F600
UTF-16：D83D DE00
```

界面中应分别显示：

```text
Unicode码点数量：1
UTF-16编码单元数量：2
```

避免把代理项对错误地显示为两个独立字符。

------

#### 3.5 UTF-32

支持：

- UTF-32LE；
- UTF-32BE；
- 十六进制编码单元；
- BOM识别；
- 编码字节序切换。

UTF-32主要用于调试、教学和数据检查，不作为输入法内部默认文本格式。

------

#### 3.6 编程语言转义

支持生成和解析：

- C/C++转义；
- C#转义；
- Java转义；
- JavaScript/TypeScript转义；
- Python字符串转义；
- JSON字符串转义；
- Rust字符串转义；
- URL百分号编码；
- HTML/XML实体。

示例：

```text
中文
```

可转换为：

```text
C/C++：\u4E2D\u6587
JavaScript：\u4E2D\u6587
Python：\u4e2d\u6587
HTML十进制：&#20013;&#25991;
HTML十六进制：&#x4E2D;&#x6587;
UTF-8 URL编码：%E4%B8%AD%E6%96%87
```

不同语言存在表示能力差异时，应显示说明。例如JavaScript的`\uXXXX`形式不能用单个四位转义表示所有增补平面字符。

------

#### 3.7 Unicode正规化

支持以下Unicode正规化形式：

- NFC；
- NFD；
- NFKC；
- NFKD。

列表预览中应显示正规化前后的码点变化。

例如某些带重音字符可能表示为：

```text
单一码点
```

或者：

```text
基础字母＋组合附加符号
```

插件应允许用户比较两种文本：

```text
视觉是否相同
码点是否相同
正规化后是否相同
```

------

### 四、列表预览界面

转换结果默认提供两种视图：

```text
1. 整体结果视图
2. 逐字符列表视图
```

#### 4.1 逐字符列表

推荐列结构：

| 列名        | 内容                                |
| ----------- | ----------------------------------- |
| 序号        | 字符在文本中的顺序                  |
| 字符        | 当前字符或字素簇                    |
| Unicode码点 | 例如`U+4E2D`                        |
| 字符名称    | Unicode标准名称                     |
| Unicode分类 | 字母、数字、标点、符号等            |
| ASCII       | 十进制、十六进制；非ASCII显示不适用 |
| UTF-8       | 十六进制字节                        |
| UTF-16LE    | 十六进制编码单元                    |
| UTF-16BE    | 十六进制编码单元                    |
| UTF-32      | 十六进制编码单元                    |
| 转义形式    | 例如`\u4E2D`                        |
| 字节数      | 在所选编码中的长度                  |

示例：

| 序号 | 字符 | Unicode | ASCII     | UTF-8       | UTF-16    | 转义         |
| ---- | ---- | ------- | --------- | ----------- | --------- | ------------ |
| 1    | A    | U+0041  | 65 / 0x41 | 41          | 0041      | `\u0041`     |
| 2    | 中   | U+4E2D  | 不适用    | E4 B8 AD    | 4E2D      | `\u4E2D`     |
| 3    | 😀    | U+1F600 | 不适用    | F0 9F 98 80 | D83D DE00 | `\U0001F600` |

#### 4.2 字符与字素簇视图

对于Emoji、旗帜、肤色修饰符和组合字符，支持切换：

```text
按Unicode码点拆分
按用户可见字符拆分
```

例如：

```text
👨‍👩‍👧‍👦
```

可能由多个码点组成，但用户看到的是一个字符。列表中应允许：

- 展开字素簇；
- 查看其中全部码点；
- 查看零宽连接符；
- 查看变体选择符；
- 查看Emoji修饰符。

### 五、列表交互

列表预览应支持：

- 按列排序；
- 显示或隐藏列；
- 搜索字符或码点；
- 筛选ASCII字符；
- 筛选控制字符；
- 筛选不可见字符；
- 筛选无效编码；
- 复制当前单元格；
- 复制选中行；
- 复制整列；
- 复制全部结果；
- 将选中项转换回文本；
- 导出CSV；
- 导出JSON；
- 导出Markdown表格；
- 对比两个文本的编码差异。

对于空格、换行、制表符、零宽字符等不可见字符，字符列应使用可识别标记：

```text
<SPACE>
<TAB>
<LF>
<CR>
<ZWJ>
<ZWNJ>
<NBSP>
```

同时保留其真实字符值，避免复制时发生变化。

### 六、调用入口

字符编码转换插件支持以下启动方式：

1. 全局快捷键启动；
2. 候选窗口工具按钮；
3. 选中文本后调用；
4. 从剪贴板读取；
5. 手动输入文本；
6. AI Agent工具调用；
7. OCR结果菜单调用；
8. 插件间API调用。

推荐快捷操作：

```text
选中文本
→ 按下编码转换快捷键
→ 自动读取选区
→ 打开列表预览
```

也可以在输入状态下使用：

```text
输入Unicode码点
→ 触发转换命令
→ 预览字符
→ 选择后上屏
```

例如：

```text
u+4e2d
```

转换并上屏为：

```text
中
```

该功能必须使用显式快捷键或命令触发，不能默认拦截用户的普通文字输入。

### 九、插件服务接口

字符转换功能应设计成可被其他插件调用的服务，而不仅是独立界面。

```cpp
enum class EncodingType {
    Ascii,
    UnicodeCodePoint,
    Utf8,
    Utf16LE,
    Utf16BE,
    Utf32LE,
    Utf32BE,
    HtmlEntity,
    UrlPercent,
    JsonEscape,
    CppEscape,
    JavaScriptEscape,
    PythonEscape
};

struct CharacterInfo {
    std::string grapheme;
    std::vector<std::uint32_t> code_points;
    std::string unicode_name;
    std::string unicode_category;
    std::vector<std::uint8_t> utf8_bytes;
    std::vector<std::uint16_t> utf16_units;
    std::optional<std::uint8_t> ascii_value;
};

class ICharacterCodeService {
public:
    virtual ConversionResult encode(
        const Text& input,
        EncodingType target
    ) = 0;

    virtual ConversionResult decode(
        const EncodedText& input,
        EncodingType source
    ) = 0;

    virtual std::vector<CharacterInfo> inspect(
        const Text& input
    ) = 0;

    virtual Text normalize(
        const Text& input,
        NormalizationForm form
    ) = 0;
};
```

AI Agent可以通过该接口完成：

```text
“把这段文字转换为Unicode列表”
“检查文本中是否含有零宽字符”
“把UTF-8十六进制还原成文本”
“比较两个看起来相同的字符串”
```

### 十一、错误处理

转换失败时不得静默替换或丢弃数据。

需要显示：

- 错误所在位置；
- 原始输入片段；
- 预期格式；
- 错误原因；
- 是否允许替换无效序列；
- 替换后可能产生的结果。

例如：

```text
错误：第3个字节不是合法的UTF-8续字节
位置：0x02
输入：E4 B8 41
```

对于无效编码提供三种模式：

```text
严格模式：发现错误立即停止
替换模式：使用U+FFFD替换
跳过模式：跳过无效数据
```

默认使用严格模式。

### 十二、性能要求

| 项目            | 建议目标           |
| --------------- | ------------------ |
| 1万字符文本解析 | 小于50ms           |
| 列表首次显示    | 小于100ms          |
| 超长列表        | 使用虚拟化表格     |
| 后台解析        | 不阻塞输入法主线程 |
| Unicode数据库   | 内存映射或按需加载 |
| 剪贴板读取      | 用户触发后执行     |
| 大文本导出      | 流式写入           |

当文本超过设定长度时，插件应：

- 后台增量解析；
- 优先显示前部结果；
- 使用虚拟化列表；
- 显示解析进度；
- 允许取消操作。
