# Agent SDK 产品闭环与架构收口实施指南

> 文档性质：`agent-sdk/` 当前最高优先级施工与验收依据，替代旧版 A0–A7 架构迁移顺序。
> 更新日期：2026-09-20。
> 当前分支与审计基线：`agent-frame`，HEAD `fc8251d42aa192715fa9f3208585802fa87d88ef`。
> 开发范围：仅 `agent-sdk/`；根目录 OwO C++ 输入法继续冻结。
> 事实优先级：当前源码与当前提交构建出的真实产物 > 真实交互证据 > 本文档 > 测试记录 > 历史规划。
> 配套证据：`agent-sdk/docs/architecture/ARCH-MICROKERNEL.md` 记录 M0–M15 拆分过程；`agent-sdk/docs/reports/archive/2026-09/AUDIT-MICROKERNEL-2026-09-20.md` 记录拆分后审计。两者是证据补充，不再作为后续任务排序依据。

## 0. 总决策：停止继续机械拆分，先把产品做成

M0–M15 已经完成了 Rust crate 级模块边界建设。下一阶段不再以“再拆一个 crate”“再加一批路由”“再做一个实验面板”为进度，而以用户可以稳定完成真实任务为唯一主线。

本轮结束时必须同时得到：

1. 一个权威 Agent 服务，桌面端、CLI、TUI 使用同一会话、模型、权限、工具、审计和运行状态；
2. 能持续使用的真实模型对话，首 token 实时显示，取消、断线、重试和失败均有明确终态；
3. 文件读取、搜索、写入、命令执行、审批、diff、撤销形成完整工具闭环；
4. MCP、OCR、语音、浏览器、WorkSwarm 等可选功能故障时不拖垮基础聊天；
5. 所有用户可见按钮都可执行真实动作；未完成能力必须隐藏或明确标为实验，不允许用 mock/占位伪装成功；
6. 可导出并验证 `owo-agent.exe` CLI、Agent Daemon、桌面 EXE/安装包；双击桌面端和直接使用 CLI 均可工作；
7. 发布产物与当前源码提交、sidecar、协议版本、前端资源可以通过 manifest 和哈希核对；
8. 有固定真实任务的启动、首 token、工具、审批和整轮 P50/P95 报告；
9. 后续增加普通产品功能时，可以沿稳定服务边界并行开发，不再频繁修改巨型 `AppState`、重复 Agent 启动链或触发无关原生重链。

### 0.1 当前阶段判断

| 层面 | 当前状态 | 本文结论 |
|---|---|---|
| M0–M15 crate 拆分 | 基本完成，已有独立 crate、定向测试和兼容 re-export | 保留成果，不回滚，不继续按行数机械拆分 |
| 运行时微内核 | 未完成；Policy、Executor、Perception 仍被同一 Core 进程直接依赖 | 先用稳定服务门面收口；只有重原生与高风险执行需要独立进程 |
| 多客户端统一 | 未完成；CLI/TUI/REPL/turn 仍会自行建 Agent、开数据库、连 MCP | 最高优先级统一到同一 Daemon |
| 基础聊天性能 | 未完成；仍有整轮缓存后回放的假流式 | 最高优先级修复 |
| 启动链 | 未完成；监听端口前等待 MCP | 最高优先级改成基础 ready 后后台加载 |
| 运行证据 | 最新 M15 smoke 复用了 M0 旧二进制 | 先修验收工具，否则后续 PASS 无效 |
| 产品功能 | 大量路由和面板存在，但真实模型、真实工具、真机 UI 证据不完整 | 可见即必须可用，否则隐藏或降级实验 |
| 发布 | 有历史构建脚本与 sidecar 证据，但没有当前 HEAD 的完整身份链 | 作为最终发布门重新验收 |

### 0.2 明确停止的工作

在本文 P0–P3 完成前，禁止：

- 新增 WorkSwarm、Fleet、WorldModel、ProductEval、插件市场的大功能；
- 为减少单文件行数继续无目标搬文件；
- 启动 Python Agent Daemon 全量迁移或 React 全量重写；
- 再复制一套会话、权限、MCP、模型或工具启动逻辑；
- 用 mock、reference replay、静态 JSON 或“接口返回 200”替代真实功能验收；
- 用延长 timeout、增加重试次数或隐藏日志来掩盖卡死；
- 在没有当前源码产物身份校验时宣称桌面、CLI 或微内核完成。

Python、TypeScript 重写保留为以后可选技术决策，不是本轮产品可用性的前置条件。现阶段优先利用已经存在且经过大量测试的 Rust 实现，把运行边界和产品闭环做好。

## 1. 当前源码事实与必须整改的问题

### 1.1 已完成的结构基础

当前 workspace 已包含稳定原语、协议、契约、策略、执行、感知、MCP、记忆、插件、工作流等独立 crate。M0–M15 的主要价值是：

- 大量领域实现不再全部堆在 `owo-agent-core/src`；
- 多个领域可以定向编译和定向测试；
- `perception`、`executor`、`workflow` 已经具备迁出进程或替换实现的源码边界；
- Policy、Grant、Tool Effect 已有独立归属；
- ProductEval 已与生产 Core 分开；
- 旧调用路径通过 re-export 保持兼容，降低了搬迁期间的大面积回归风险。

这些成果是后续收口的基础，不得重新合并回巨型 Core。

### 1.2 当前规模与集中点

| 区域 | 当前审计值 | 主要风险 |
|---|---:|---|
| `owo-agent-core/src` | 32 个 Rust 文件，约 25,028 行 | 剩余均是 Agent、工具、会话、WorkSwarm、Fleet 等总线型模块，不能再盲拆 |
| `owo-agent-server/src` | 62 个文件，约 29,400 行 | `AppState` 仍有 30 个公开字段，约 276 处路由注册，正在成为新单体 |
| `owo-agent-cli/src` | 约 6,019 行 | 同时承担客户端、Daemon 启动和直接 Agent Runtime，职责混合 |
| `ToolRegistry::new()` | 默认注册 34 个工具 | 每轮 schema 过大、误调用和审批噪声增加 |
| `desktop/web/panels/workswarm.panel.js` | 约 3,575 行 | 高耦合 UI 热点，不允许继续堆功能 |
| `core/workswarm.rs` | 约 4,328 行 | 高级编排仍在基础编译和理解路径中 |
| `core/computer_use.rs` | 约 2,201 行 | 感知、动作、模拟面和工具包装混合，仍把 Perception 拉回 Core 链接闭包 |

文件较大本身不是拆分理由。只有出现独立所有权、独立生命周期、独立失败模式或明确编译收益时才拆服务；否则优先在现有文件内提取私有子模块和稳定门面。

### 1.3 最新运行态证据无效

`mk-smoke-m15-exec-workflow` 报告中的 `build_id` 是 `3f4bb03...`，对应 M0；当前 HEAD 是 `fc8251d...`。`scripts/mk-smoke.ps1` 直接运行现存 `target/debug/owo-agent.exe`，没有构建当前源码，也没有比较 HEAD、二进制 build ID 或源码时间。

因此：

- M15 的 crate/server 测试可以作为编译级证据；
- M15 的 18/18 smoke 不能证明 M14/M15 代码进入了运行产物；
- 该 smoke 在未配置 Provider、ProductEval reference 模式下运行，也不能证明真实对话和工具调用；
- 修复验收身份链是所有后续工作的 P0 前置。

### 1.4 当前问题总表

| 编号 | 问题 | 用户影响 | 根因 | 目标处置 |
|---|---|---|---|---|
| F-01 | CLI、TUI、REPL、turn 与桌面不是同一 Agent | 行为不同、会话不同、重复启动、数据库竞争 | 多入口直接构造 `Agent` | 全部改为 `owo-agent-client` 连接同一 Daemon |
| F-02 | 假流式 | 长时间无内容、像卡死 | ResilientProvider 缓存 `Vec<String>`，成功后回放 | 首 delta 立即转发；发出首 delta 后禁止透明整轮重试 |

| F-10 | Server 状态过度集中 | 修改冲突、难并行 | 30 字段公开 `AppState` | 收敛成 4–6 个领域服务句柄，路由只依赖所需服务 |

| F-15 | 根目录存在 0 字节未跟踪 `Cargo.toml` | 在仓库根运行 Cargo 会选错 manifest | 临时文件未清理 | 确认无 owner 后删除并加入清理检查 |

## 2. V1 最终运行架构

### 2.1 唯一权威拓扑

```text
owo-agent-desktop.exe ─┐
                       ├─ HTTP + SSE ─► owo-agentd.exe（唯一 Agent Daemon）
owo-agent.exe CLI/TUI ─┘                    │
                                            ├─ AgentRuntime
                                            ├─ SessionService（唯一会话写者）
                                            ├─ ToolCatalog / ApprovalService
                                            ├─ Memory / Skill / Plugin
                                            ├─ ToolHostService（受信执行门面）
                                            │    ├─ Policy / Grant
                                            │    ├─ Sandbox / Executor
                                            │    └─ Audit / Diff / Revert / Receipt
                                            ├─ MCP Host（后台连接）
                                            └─ PerceptionService
                                                 └─ owo-perception-worker.exe（按需）
```

V1 不做每个 crate 一个进程。进程拆分只用于：

- 唯一长期运行的 Agent Daemon；
- 重型、慢启动、可崩溃的 Perception Worker；
- 后续确有安全隔离要求时的 Tool Host 子进程。

Tool Host 在本轮可以先作为 Daemon 内部的受信服务门面，但必须满足“无法绕过 Policy、Capability 和 Receipt”的类型与测试约束。只有该门面稳定后，才允许在不改变调用方的情况下切换为独立进程。

### 2.2 发布二进制

| 产物 | 职责 | 禁止事项 |
|---|---|---|
| `owo-agentd.exe` | Agent Daemon；服务端、Agent loop、会话、工具协调 | 不提供交互式 TUI；不承载桌面窗口 |
| `owo-agent.exe` | CLI、REPL、TUI、doctor、status；通过客户端协议连接 Daemon | 不直接打开 `index.db`；不构造 Agent；不直接连接 MCP |
| `owo-agent-desktop.exe` | Tauri 壳、窗口、托盘、Daemon 生命周期、原生选择器、更新 | 不复制业务逻辑；不直接写会话库 |
| `owo-perception-worker.exe` | OCR、STT、视觉、UIA 感知；按需启动 | 不写会话、Grant、审批；不执行高风险动作 |

兼容期允许 `owo-agent serve` 启动或转发到 `owo-agentd.exe`，但不能在 CLI 进程中再构造第二份运行时。

### 2.3 Daemon 发现与自动启动

Daemon 必须写入原子替换的 `runtime/daemon.json`：

```json
{
  "pid": 1234,
  "port": 4096,
  "instance_id": "uuid",
  "api_version": "0.8",
  "build_id": "git-sha",
  "started_at": "RFC3339",
  "data_root": "masked-id"
}
```

规则：

1. CLI/桌面先读取 discovery，再验证 PID、`instance_id`、`/health`、API 版本和 build 兼容性；
2. 发现文件存在但进程不在时按既有安全规则清理 stale PID/discovery；
3. 没有 Daemon 时，桌面壳或 CLI 只允许有一个启动者获得启动锁；其余客户端等待同一实例；
4. token 不写入 discovery；认证仍从权限受控文件或桌面 pairing 获得；
5. CLI 启动的 Daemon 与桌面启动的 Daemon 使用同一个 data root，后启动者必须复用，不得另起；
6. 客户端退出默认不终止共享 Daemon；显式 `daemon stop` 或桌面安装策略负责退出；
7. 升级时必须先检查协议兼容，再优雅停止旧实例，禁止两个版本同时写同一数据库。

## 3. 内核与服务边界

### 3.1 每个 crate 的唯一职责

| 模块 | 允许拥有 | 禁止拥有 | 对外边界 |
|---|---|---|---|
| `owo-agent-protocol` | HTTP DTO、事件、稳定错误码、API 版本 | 数据库、Agent、工具实现、Windows API | 生成 Rust/TS 客户端类型的唯一契约源 |
| `owo-agent-client`（新增） | Daemon discovery、认证、HTTP、SSE、重连、CLI/TUI client facade | Core、Server、SQLite、MCP、Tool 实现 | `AgentClient` |
| `owo-agent-kernel` | 错误原语、能力卡、审计类型、凭据、CAS、deadline、平台最小原语 | Agent loop、业务状态机、HTTP 路由 | 稳定底层库 |
| `owo-agent-core` | Agent loop、模型路由、上下文、会话领域、turn 状态机、工具协调 | HTTP、Tauri、直接 UI、原生 OCR/STT 实现 | `AgentRuntime` |
| `owo-agent-policy` | Policy、PermissionSpec、Grant、ToolEffect、MCP 健康策略 | 工具执行、UI、模型调用 | `PolicyService` |
| `owo-agent-tool-safety` | 沙箱、审计链、执行前后安全原语 | Agent 自主决策、审批 UI | `SafetyService` |
| `owo-agent-executor` | 文件/命令/桌面动作执行器 | 自行批准、直接构造 Grant、感知模型 | 仅由 `ToolHostService` 调用 |
| `owo-agent-perception` | OCR/STT/UIA/视觉/定位/场景 | 点击、输入、文件写入、会话状态 | `PerceptionService`/worker RPC |
| `owo-agent-mcp` | MCP transport、schema、连接与进程生命周期 | 决定最终权限、写会话库 | `McpHost` |
| `owo-agent-memory` | 记忆、观察、学习候选 | 直接执行动作 | `MemoryService` |
| `owo-agent-plugins` | manifest、加载状态、插件生命周期 | 绕过 ToolHost、直接写其他服务数据库 | `PluginManager` |
| `owo-agent-extensions` | notes、automation、change set、cloud queue 等可选服务 | 阻塞基础 ready | 独立 extension service |
| `owo-agent-workflow` | 工作流定义、断言、动作计划 | 直接 OS 调用、绕过执行门 | 调用 ToolHost/Perception 接口 |
| `owo-agent-workswarm` | 团队契约、项目空间、输出结构 | 基础聊天启动依赖 | Experimental extension |
| `owo-agent-server` | HTTP/SSE 适配、认证中间件、路由装配 | 领域规则、重复状态、巨型公共 AppState | `AgentDaemon` API |
| `owo-agent-cli` | 参数解析、CLI/TUI 展示、调用 `AgentClient` | Agent/Core/Server/SQLite 直接依赖 | 用户客户端 |
| Tauri/Desktop Web | 窗口、生命周期、视图、交互 | Agent、会话、权限的第二套实现 | 与 CLI 相同 API |
| ProductEval | 开发评测、批处理、报告 | 生产默认启动、桌面稳定导航 | devtool only |

### 3.2 强制依赖方向

```text
clients ─► owo-agent-client ─► owo-agent-protocol

owo-agent-server ─► AgentRuntime / domain services ─► kernel/contracts/protocol

AgentRuntime ─► ToolHostService interface
AgentRuntime ─► PerceptionService interface
AgentRuntime ─► McpHost interface

executor ─► kernel + perception DTO（不得反向依赖 core/server）
perception ─► kernel（不得依赖 executor/core/server）
policy ─► kernel + mcp DTO（不得依赖 Agent）
```

CI 必须增加依赖守卫，拒绝：

- `owo-agent-client` 依赖 core/server/sqlite；
- CLI/TUI 引用 `Agent`、`SqliteSessionStore`、`McpClient`；
- Perception 引用 Executor/Policy/Core；
- Executor 直接创建 Grant 或跳过 Receipt；
- Server API 文件直接实现领域规则；
- production feature 依赖 ProductEval；
- 新代码继续使用 `owo_agent_core::<已迁出模块>` 兼容别名。

### 3.3 数据所有权

| 数据 | 唯一写入者 | 存储 | 其他模块如何访问 |
|---|---|---|---|
| session/turn/item/message | SessionService | `state.db`，WAL，单写队列 | 只经服务接口/API |
| pending approval/grant/policy audit | ToolHostService | `policy.db` 或明确 schema namespace | 只读投影/API |
| execution receipt/diff/revert | ToolHostService | `execution.db` + CAS | receipt/diff API |
| memory/skill metadata | MemoryService | `memory.db` 或明确表域 | Memory API |
| plugin/extension state | PluginManager/各扩展 owner | 各自 namespace | 事件/API |
| OCR/STT 缓存 | Perception Worker | 可删除 cache | 非权威状态 |
| runtime discovery/PID | Daemon supervisor | `runtime/` | 原子读、带实例校验 |
| logs/traces/metrics | ObservabilityService | 轮转日志 + trace store | 诊断 API |

禁止 CLI、TUI、桌面 Web 或 Perception Worker 直接打开 `index.db/state.db`。数据库迁移只允许 Daemon 在获得单实例锁后执行。

### 3.4 Server 状态收口

把当前 30 字段公开 `AppState` 收敛为以下组合，不再继续增加顶层字段：

```rust
pub struct AppState {
    pub runtime: Arc<RuntimeServices>,
    pub tools: Arc<ToolServices>,
    pub extensions: Arc<ExtensionServices>,
    pub platform: Arc<PlatformServices>,
    pub observability: Arc<ObservabilityServices>,
}
```

每个路由模块通过窄 trait 或子状态拿依赖，不允许任意访问所有服务。迁移按修改到的路由逐批进行，不做一次性 62 文件大改。

## 4. 统一协议与运行语义

### 4.1 会话与 Turn

核心稳定模型：

- `Session`：工作区、模型、创建时间、最近活动、状态；
- `Turn`：输入、状态、开始/结束时间、取消标志、usage、错误；
- `Item`：user message、assistant delta/message、tool call/result、approval、diff、artifact、diagnostic；
- `Event`：`seq`、`session_id`、`turn_id`、`item_id`、`type`、`created_at`、`payload`。

同一 `session_id` 的事件必须由 Daemon 分配单调递增 `seq`。客户端重连使用 `after_seq` 补拉，不能仅依赖内存 SSE。

Turn 终态只有：

- `completed`
- `failed`
- `cancelled`
- `interrupted`

任何失败路径都必须写终态并发终态事件，禁止 UI 永久停在“运行中”。

### 4.2 真流式规则

修改 `agent-sdk/crates/owo-agent-core/src/gateway.rs`：

1. Provider 收到 delta 后立即调用上层 callback，不再保存到 `Vec<String>` 等整轮成功；
2. 尚未发出任何 delta 时，可以按明确的 retry/fallback policy 重试；
3. 一旦发出首个 delta，禁止自动换 Provider 重放整轮，避免重复文本；
4. 首 delta 后网络失败，保留已输出内容，Turn 进入 `interrupted`，UI 显示“保留部分输出，可重试”；
5. 工具调用参数增量在完整 JSON 前只作为内部 accumulator，不向执行器发送半包；
6. usage 可以在最终事件补齐，不得阻塞文本 delta；
7. 取消必须贯穿 Provider 请求、工具执行和 SSE producer；
8. trace 记录 provider request、first byte、first semantic token、stream end、turn end。

测试必须覆盖：首 token 前失败可重试、首 token 后失败不重复、UTF-8 跨 chunk、工具 JSON 跨 chunk、取消、断线重连、终态唯一。

### 4.3 SSE 背压

修改 `agent-sdk/crates/owo-agent-server/src/turn_api.rs`：

- `unbounded_channel` 改为有界 `mpsc::channel`，初始容量建议 256，通过压测调整；
- 文本 delta 每 20–50 ms 或 1–4 KB 合并一次；
- token usage、typing/progress 等可合并事件允许覆盖旧值；
- approval、tool result、error、completed/cancelled 等关键事件必须可靠送达或落持久事件表；
- 客户端断开后根据请求策略决定取消或后台继续，不能让 producer 永久阻塞；
- 慢客户端、断连和重连必须有指标。

### 4.4 工具生命周期

统一生命周期：

```text
model proposes tool
  → ToolCatalog resolves exact tool/version
  → PolicyService classifies effect and scope
  → allowed / denied / approval_required
  → approval result creates short-lived capability
  → ToolHostService validates capability and canonical args hash
  → snapshot（写操作）
  → execute
  → receipt + audit
  → diff/artifact preview
  → model/client receives structured result
```

Capability 至少绑定：tool name、tool version、canonical args hash、workspace、session、turn、effect、scope、expiry、nonce。Executor 的高风险公共函数必须要求 `ExecutionContext`，没有 capability/receipt sink 的执行在类型上不可表达。

### 4.5 权限体验

默认 deny 不等于每个读取动作都询问 `y`。产品权限层级：

| 操作 | 默认体验 | 可选授权 |
|---|---|---|
| 工作区内只读 | 首次明确工作区后允许 | 本次会话/长期工作区 |
| 工作区内写入 | 首次按路径或变更集审批 | 仅一次/本次会话/工作区长期 |
| 工作区外读写 | 必须审批 | 精确路径 + 期限 |
| 安全只读命令 | 策略允许后执行 | 会话/工作区 |
| 修改系统、安装、删除、网络发布 | 必须审批 | 一次性或极短期限 |
| 桌面点击、输入、浏览器提交 | 按 effect 和目标域审批 | 会话级细粒度授权 |
| 完全访问 | 默认关闭、醒目风险提示、可随时撤销 | 有明确过期时间，不得静默永久 |

桌面与 CLI 必须支持相同四种动作：拒绝、允许一次、允许本次会话、允许当前工作区。Grant 必须持久化真实 scope/expiry，并在权限中心可查询、撤销和审计。

### 4.6 结构化错误

先统一以下边界的错误枚举：Provider、Turn、ToolHost、Perception、MCP、Storage、Approval。错误响应至少包含：

```json
{
  "code": "provider/not_configured",
  "category": "configuration",
  "message": "面向用户的说明",
  "retryable": false,
  "action": "open_model_settings",
  "trace_id": "..."
}
```

Server 不允许通过字符串包含判断映射语义。UI 根据 `code/action` 提供下一步，不解析中文错误文本。

## 5. 现有功能闭环标准

### 5.1 基础能力：必须 Stable

以下能力是本轮发布阻断项：

1. Daemon 自动启动、复用、停止和崩溃恢复；
2. Provider 配置检查、真实模型请求、真流式输出；
3. 会话新建、列表、恢复、重命名、删除/归档；
4. CLI、REPL、TUI、Desktop 共用会话和运行状态；
5. 文件读取、目录、搜索；
6. 文件写入、diff、撤销；
7. 命令执行、超时、取消、输出截断和 artifact；
8. 权限审批、Grant 持久化、撤销、审计；
9. MCP 配置、后台连接、健康状态、失败降级；
10. 设置、诊断、日志导出、版本和 build identity；
11. 桌面端安装、首次启动、正常退出、升级后的状态恢复。

任何一项只有 API/单测而无 CLI 与桌面真实入口，不得标记 Stable。

### 5.2 可选能力：可失败但不能拖垮基础能力

| 能力 | 本轮要求 |
|---|---|
| Skills/Plugins | 安装、启停、加载失败可诊断；插件不能阻塞 ready |
| Memory | 添加、检索、删除、禁用可用；不能自动执行动作 |
| Automation | 创建、启停、触发记录可用；后台失败可见 |
| Browser | 工具按需加载；浏览器不可用时明确降级 |
| OCR/STT/UIA | 按需启动 worker；缺模型/依赖不影响聊天 |
| Notes | CRUD 与搜索真实落盘，保持轻量 |

### 5.3 Advanced/Experimental

WorkSwarm、Fleet、WorldModel、Cloud、ProductEval 在完成真实端到端验收前统一归入 Advanced/Experimental：

- 默认导航不展示；
- 用户主动开启实验功能后才加载路由和前端资源；
- mock 后端、reference replay、模拟远端必须明确显示“模拟”；
- 不计入 Stable 功能数量；
- 不得成为基础启动、基础编译或发布的阻断依赖；
- ProductEval 只保留开发入口，不进入正式桌面用户导航。

### 5.4 CLI 与桌面功能同源矩阵

| 功能 | CLI/TUI | Desktop | 共同服务 |
|---|---|---|---|
| daemon status/start/stop | `owo-agent daemon ...` | 壳自动管理 + 诊断页 | Runtime API |

| prompt/stream/cancel | 文本与 JSONL | 对话区 | Turn API/SSE |

| approval | 交互选择/命令 | 审批条与权限中心 | Approval API |
| diff/revert | 命令/TUI | diff 查看器 | Execution API |
| settings/provider | 命令/配置向导 | 设置页 | Settings API |
| MCP/plugins | 命令 | 设置页 | Extension API |
| diagnostics/log export | `doctor`/`logs` | 诊断中心 | Diagnostics API |

客户端可以有不同展示，但业务含义、权限结果、状态码和会话数据必须一致。

### 5.5 UI 约束

- 首页只呈现：会话、输入、运行状态、工具活动、审批和错误恢复；
- 设置按模型、权限、工具/MCP、外观、诊断分区；
- 枚举、布尔、范围、路径、模型和工具必须使用选择器、开关、数字控件或原生路径选择，不用无说明纯文本；
- JSON 编辑器只放在“高级”折叠区，必须提供校验和恢复默认；
- 每个按钮必须有明确动词、禁用原因、loading、成功和失败反馈；
- provider 未配置时显示配置向导，不能只出现空白聊天；
- Daemon 启动失败时显示阶段、错误码、日志位置和“重试/打开诊断”；
- 实验面板不能与稳定功能混在主导航；
- 所有可见功能必须有 Playwright/浏览器交互或真机桌面截图证据。

## 6. 启动、性能与稳定性

### 6.1 冷启动阶段

```text
start process
  → acquire single-instance lock
  → open/migrate authoritative stores
  → load auth and minimum settings
  → build minimal AgentRuntime and routes
  → bind localhost port
  → emit core_ready
  → clients become usable
  → background: plugins / MCP / memory warmup / optional workers
```

禁止在 `core_ready` 前：连接外部 MCP、加载 OCR/STT 模型、扫描大型插件目录、运行 ProductEval、恢复 WorkSwarm 或执行网络检查。

### 6.2 MCP 与插件后台加载

- MCP 按 server 并发连接，总并发有界；
- 每个 MCP 独立 timeout/circuit breaker，不串行累加；
- `ready`、`degraded`、`connecting`、`failed`、`disabled` 状态可查询；
- 同一 MCP 的重连 single-flight；
- 插件 manifest 快速扫描，真正初始化延后；
- 后台加载只通过事件更新 ToolCatalog，不重建 Agent；
- 坏插件/MCP 不得让 `/health` 失败，只在 capability health 中报告。

### 6.3 最小工具集

默认对模型暴露不超过 8 个基础工具：读取文件、列目录、搜索、受控写入、受控命令、技能/工具发现、必要的 artifact 操作。浏览器、桌面、OCR、STT、WorkSwarm 工具通过以下方式按需加载：

- 用户显式开启能力；
- 技能 manifest 声明；
- 模型先调用工具发现；
- 当前客户端/平台确认可用；
- Policy 允许该 capability。

工具 manifest 是名称、描述、schema、effect、权限提示、成熟度、版本和测试样例的单一来源。UI、CLI help 和模型 schema 均由它生成，禁止手写三份。

### 6.4 性能 SLO

| 指标 | 发布门 |
|---|---:|
| Daemon 冷启动到 `core_ready` P50/P95 | ≤1.5 s / ≤3 s |
| 桌面双击到可输入 P50/P95 | ≤2.5 s / ≤5 s |
| 客户端请求到 Provider 发出 | P95 ≤150 ms |
| Provider delta 到客户端显示附加开销 | P95 ≤50 ms |
| 本地只读工具调度附加开销 | P95 ≤30 ms |
| 审批提交到工具恢复 | P95 ≤100 ms |
| 取消请求到 Turn 停止 | P95 ≤500 ms |
| 基础 Daemon 空闲内存（不启 Perception） | P95 ≤500 MB |
| SSE 队列 | 有界；压力测试中不随时间线性增长 |
| 默认工具 schema | 固定预算，超预算必须按需发现 |

模型网络延迟与本地附加开销分开报告，不得把远端模型慢归因到 UI，也不得用总耗时掩盖本地假流式。

### 6.5 固定性能任务

每次发布至少运行 20 次并报告 P50/P95：

1. 启动 Daemon 并创建会话；
2. 纯文本短对话，记录首 token；
3. 读取一个 100 KB 文件；
4. 搜索 1,000 文件工作区；
5. 写入一个小文件并生成 diff；
6. 一次需要审批的命令；
7. 一个失效 MCP 存在时启动和对话；
8. 客户端中途断开、重连和取消。

输出 `performance-report.json` 与人类可读 Markdown，记录机器、版本、提交、Provider、样本数和原始 trace 路径。

## 7. 代码整理规则

### 7.1 新增客户端 crate

新增 `crates/owo-agent-client`，包含：

```text
src/
  discovery.rs
  auth.rs
  http.rs
  sse.rs

```

CLI/TUI 只能通过该 crate 访问服务。TypeScript 客户端继续从同一 OpenAPI/schema 生成，并与 Rust client 跑相同 contract fixtures。

### 7.2 Daemon 与 CLI 二进制分离

新增或调整为：

```text
crates/owo-agent-daemon/   # 只组合 server + core/domain services
crates/owo-agent-cli/      # 只组合 client + CLI/TUI
```

迁移期间 `owo-agent-cli` 可以暂时保留兼容 `serve` 子命令，但最终 production CLI 的普通命令依赖树中不得出现 server/core/perception/ORT/Sherpa。

### 7.3 Core 剩余模块处理原则

- `agent/gateway/session/trace/settings`：留在 Agent Runtime，按领域子模块整理；
- `tools/computer_use`：通过 ToolCatalog、ToolHostService、PerceptionService 解环后再整理；
- `goal/worker_pool/workswarm/fleet`：移动到可选 extension 只在能减少默认运行/编译依赖时进行；
- `sqlite_store`：收口为 SessionStore 实现，禁止客户端直接引用；
- 大文件按职责提取私有模块，不通过增加公共 crate 制造新依赖。

### 7.4 兼容桥清理

M0–M15 的 re-export 兼容层分两阶段：

1. 新代码立即使用真实 crate 绝对路径；CI 拒绝新增 `owo_agent_core::permissions` 等旧桥引用；
2. 每个消费域完成迁移和 API 稳定后删除对应内部 `crate::<alias>`，外部兼容路径至少保留一个版本并标记 deprecated。

不允许一次性机械替换 177 处后直接提交；按 domain 分批、定向测试、保持可回滚。

### 7.5 Panic、死代码和占位治理

- 守护进程生产路径禁止输入可触发的 `unwrap/expect/panic!`；
- 优先审计 WorkSwarm、Env、Perception；
- `todo!()`、`unimplemented!()` 不得进入 Stable 路径；
- 两个发布周期无入口、无 owner、无测试的代码列入删除候选；
- mock 只允许测试或明确实验模式，命名和 UI 必须带 `mock/simulated`；
- 路由存在但无真实处理链、按钮存在但无真实动作，一律按占位统计；
- 删除前用 `rg`、路由表、OpenAPI、客户端引用、测试和 release feature 六侧确认；
- 根目录 0 字节 `Cargo.toml`、临时日志、scratch、过期 QA 产物分别由 owner 确认后清理，不在功能提交中顺手批量删除。

### 7.6 并行开发所有权

按服务边界认领文件：

| 工作面 | 主要目录 | 可独立验证 |
|---|---|---|
| Protocol/Client | `protocol`、`client`、TS client | schema + client contract |
| Agent Runtime | `core/agent,gateway,session,trace` | core 定向测试 |
| Tool Host | `policy,tool-safety,executor` | capability/receipt contract |
| Perception | `perception`、worker | worker 定向测试 |
| Daemon/API | `server`、daemon | route contract + smoke |
| CLI/TUI | `cli` | fake-daemon client E2E |
| Desktop UI | `desktop/web`、Tauri 壳 | frontend tests + Playwright + 真机 |
| Release | `scripts`、Tauri packaging | isolated artifact acceptance |

同一文件同一时间只允许一个 owner。跨面变更先改契约和 fixture，再分别实现，禁止多人同时修改 `server/src/lib.rs` 或 `desktop/web/app.js`。

## 9. 验证策略与资源红线

### 9.1 分层验证

| 层级 | 目的 | 触发 |
|---|---|---|
| 静态/格式 | 编码、依赖方向、schema、lint | 每次改动 |
| crate 定向 | 当前领域行为 | 每个小提交 |
| contract | 路由、事件、错误码、客户端 fixture | 契约变更 |
| integration | Daemon + 存储 + ToolHost/MCP | 波次完成 |
| client E2E | CLI/TUI/Desktop 同源行为 | P1 起 |
| real-model E2E | 真流式、工具选择、usage、错误恢复 | P2 起 |
| artifact acceptance | 当前二进制和安装包 | P0/P6 |
| visual acceptance | 真机布局、键盘、按钮 | P4/P6 |

单测通过不能替代真实运行；HTTP 200 不能替代真实业务；当前源码存在不能替代当前二进制；桌面进程存在不能替代可见窗口和可交互界面。

### 9.2 Rust 资源安全红线

1. 定向 Rust：`CARGO_BUILD_JOBS=2`、`RUST_TEST_THREADS=2`、`-j 2`；
2. 完整 workspace/core/release/原生重链：`-j 1`、`--test-threads=1`；
3. 禁止同时启动两组 Cargo；
4. 可用内存 <6 GB 或已用 ≥80% 时不得启动；
5. 完整构建卷剩余 <20 GB、定向构建 <6 GB 时不得启动；
6. Cargo 前必须走 `Resolve-OwoOrtEnv`，直到基础 workspace 完全脱离 ORT；
7. 禁止 `--quiet`、`Select-Object -Last` 等隐藏长任务进度；
8. 必须经 `Invoke-CiCargo` 获取心跳、资源门、磁盘门和真实退出码；
9. 不用增加并发换时间；不允许后台偷偷编译；
10. 验收跑动时禁止并行编译；
11. `.ps1` 修改后复查 UTF-8 BOM；
12. 完整构建只在波次门和 release 门运行，日常优先定向测试、contract fixture 和客户端 fake-daemon E2E。

### 9.3 测试真实性

- 所有 report 写明 source commit、binary hash、binary build ID；
- dirty tree 构建必须记录 dirty flag 和 diff hash，不能伪装成 commit 产物；
- mock/reference/simulated 与 real 分开统计；
- 旧报告只证明当时产物，不自动继承到新提交；
- smoke 脚本不得自行猜测产物路径；
- 跳过项必须在汇总中显式显示，不能计入 passed；
- flaky 重跑要同时保存首次失败和重跑证据；
- 超时必须确认目标进程树已终止，不能只停止外层 PowerShell job。

## 10. 黄金路径与故障矩阵

### 10.1 发布黄金路径

在 CLI、TUI、Desktop 三端分别或交叉完成：

1. 启动/连接同一 Daemon；
2. 新建工作区会话；
3. 发送真实模型请求并逐 token 显示；
4. Agent 读取文件并搜索代码；
5. Agent 请求写入文件；
6. 用户选择“允许一次”或会话授权；
7. 工具执行并显示结构化结果；
8. 查看 diff；
9. 撤销变更并确认文件恢复；
10. 取消一个运行中的 turn；
11. 重启客户端后恢复同一会话；
12. CLI 创建的后续消息能在 Desktop 看到，反之亦然；
13. 导出诊断包，内容脱敏且包含 trace/build manifest。

### 10.2 必测故障

| 故障 | 预期 |
|---|---|
| Provider 未配置 | Daemon 正常 ready，客户端进入配置向导，turn 返回稳定错误码 |
| Provider 401/429/5xx/timeout | 分类正确、有限重试、已输出文本不重复 |
| 一个 MCP 卡死 | 基础服务按 SLO ready，MCP 显示 degraded |
| SSE 客户端很慢 | 队列有界、内存稳定、关键终态可恢复 |
| 客户端断线 | 重连后按 seq 补事件，或明确 turn 后台继续/取消 |
| 重复启动 Daemon | 复用已有实例，不出现两个 DB writer |
| stale PID/discovery | 安全校验后恢复，不误杀无关进程 |
| 数据库迁移失败 | 进入只读/诊断状态，不破坏原库 |
| 审批拒绝/过期 | 工具不执行，Turn 有可理解结果 |
| 工具超时/输出过大 | 终止进程树，结果截断并写 artifact |
| Perception 缺依赖/崩溃 | 基础聊天和文件工具继续可用 |
| sidecar 与壳版本不符 | 启动被拒并给出重新安装提示，不连接错误实例 |
| release 中缺文件 | 安装/启动前明确报 binary_missing，不回退仓库 target |

## 11. 最终完成定义

只有全部满足才能写“现有架构功能闭环完成”：

### 架构

- CLI、REPL、TUI、Desktop 全部连接同一权威 Daemon；
- 只有 Daemon 写会话数据库；
- CLI 普通路径不依赖 Core/Server/Perception；
- 工具执行只能通过 ToolHostService；
- Perception 不执行动作，基础 Daemon 不因其故障失效；
- M0–M15 crate 职责符合 §3，不再新增反向依赖；
- Advanced/Experimental 不进入默认启动链。

### 功能

- §5.1 全部 Stable 能力在 CLI 与 Desktop 有真实 E2E；
- 黄金路径完整通过；
- 真流式、取消、重连、审批、diff/revert 均可使用；
- 默认 UI 没有点不开、无反馈或只返回占位数据的功能；
- 所有可见选项含义明确，高频配置不要求手填 JSON；
- Provider/MCP/Worker 失败有明确降级和恢复入口。

### 性能与稳定性

- 达到 §6.4 SLO，保留原始 trace 和 P50/P95 报告；
- 一个坏 MCP、一个慢客户端、Perception 不可用均不影响基础聊天；
- SSE、日志、队列和工具输出均有上限；
- 生产路径的输入不可触发 panic；
- 24 小时基础 soak 无持续内存增长、孤儿进程或数据库锁死。

### 发布

- 成功导出并验证 `owo-agent.exe`、`owo-agentd.exe`、桌面 EXE/安装包和必要 sidecar；
- CLI 包可在隔离目录运行；桌面安装包可在隔离数据目录双击运行；
- shell、daemon、worker、前端和协议版本均写入 release manifest；
- sidecar 和安装包内文件哈希与当前构建一致；
- 当前源码、构建产物、运行进程、截图证据四者身份一致；
- 没有泄漏密钥、绝对开发路径、模型、大型缓存或测试数据。
