# CLI 状态可见性与反馈速度 — 分析与修复（2026-09-30）

> 触发：用户反馈「多工具链调用/长任务时看不到进度，像默认隐藏了思考内容」。
> 本文件记录根因、修复与排查清单；实现细节见同批代码。

## 1. 结论摘要

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 多工具并发时看不到任何工具状态 | core 并发组把 `ToolStart`/`ToolResult` 缓存到**整组结束**才回放 | `ToolStart` 立即外发；等待期间每 100ms drain 一次 `ToolResult` |
| 2 | 长句/段落像"没在输出" | CLI Markdown 渲染**按整行缓冲**，换行前不显示 | 改为增量渲染：行首最多缓冲 7 字符判定块类型，其余即时输出 |
| 3 | 不知道模型在干什么、工具用了多久 | 无思考状态、无参数、无耗时 | `⏳ 思考中…`（首 token 原地清除）、`▶ tool <参数预览>`、`✔ tool（1.2s）` |
| 4 | 工具参数不可见 | `TurnEvent::ToolStart` 不带参数 | 增加 `args_preview`（脱敏+截断），SSE `ToolUse.args` 同步 |
| 5 | Daemon REPL Ctrl+C 监听器泄漏 | 每回合 spawn 永不结束的监听任务 | 回合结束 `Notify` 通知监听器退出（与本地 REPL 一致） |
| 6 | 目标无人推进 | 无目标模式 | `/goal`：未完成时自动续推，模型输出 `GOAL_DONE` 才停 |

### 1.1 `/goal` 的目标"附带"范围（澄清）

`/goal <目标>` 设置后，目标文本会**附加到目标周期内的每一次输入**：

- 目标推进轮：`goal_first_prompt` / `goal_continue_prompt` 携带 `目标：<objective>` 与
  `GOAL_DONE` 标记说明；
- **目标进行中用户手动插话**：`goal_context_prompt` 在输入前加 `【当前目标】<objective>`，
  模型不会因为插话而丢失目标（`done=true` 或已 `/goal clear` 后不再附加）。

当前限制：目标状态存在 **REPL 会话内存**，不随会话持久化（`/resume` 不恢复目标）；
若需跨进程持久化，需要服务端 `POST /session/{id}/goal` 与会话字段扩展（后续可选项）。

> 2026-10-18 更新：该可选项已落地——会话 `SessionGoal` + SQLite migration v10 +
> `POST /session/{id}/goal`（set/advance/done/clear）+ 客户端/daemon REPL 接线；
> 重开进程 `/resume` 会恢复目标与已推进轮次（真机冒烟：重启后 objective/iterations 保留）。

## 2. 逐条根因

### 2.1 并发工具组事件被延迟到组末（主因）

`crates/owo-agent-core/src/agent/mod.rs` 的有界并发组（默认 4）为保持事件顺序，
把组内 `ToolStart`/`ToolResult` 先写入 `group_events`，**等 `join_all` 全部完成**后
统一回放。长工具（搜索/构建/网络）会让 CLI 长时间零输出。

修复：
- `ToolStart` 在创建 future 前**立即 emit**（顺序仍是组内插入序，确定性不变）；
- 非 deadline 分支改为 `FuturesUnordered` 式等待：`tokio::select!` + 100ms tick
  周期性 drain 已完成工具的 `ToolResult`，完成后再兜底 drain 一次。

### 2.2 Markdown 整行缓冲（观感"卡住"）

上一版 `MarkdownStream` 遇到换行才渲染整行；模型输出长段落时，整段会在换行时"跳出来"。

修复：`markdown.rs` 重写为增量状态机——
- 行首只缓冲到能判定块类型（标题 ≤7、列表/引用 2、围栏 3 字符），随后立即输出；
- 行内样式（粗体/斜体/行内代码/删除线）用 `pending` 字符配对即时切换 ANSI；
- 围栏代码块内原样输出；换行复位样式。

### 2.3 缺少状态与耗时

新增 `ui_output::StreamPrinter`（本地 `TurnEvent` 与 Daemon `SseEvent` 共用）：
- `⏳ 思考中…`：模型调用开始时显示；首个 token 到达时 `\r\x1b[2K` 原地清除（仅 tty）；
- `▶ tool <args_preview>`：工具启动即显示参数（脱敏、截断 160 字符）；
- `✔/✘ tool（1.2s）`：按 tool id 配对 `Instant`，显示耗时。

### 2.4 参数预览贯通

`TurnEvent::ToolStart` 新增 `args_preview: Option<String>`（`#[serde(default)]` 向后兼容），
由 `permissions::redact_args` 脱敏后截断；`turn_api::wire` 把它映射进 `SseEvent::ToolUse.args`。

### 2.5 Daemon REPL Ctrl+C 泄漏

`repl_daemon::run_turn_capture` 每回合 spawn 一个 `ctrl_c()` 监听任务且永不结束：
`/goal` 多轮会累积监听器，回合结束后按 Ctrl+C 仍会误置 `abort`（可能误停目标推进）。
修复：`tokio::select! { ctrl_c, turn_done.notified() }`，回合结束 `notify_waiters()`。

## 3. 反馈速度排查清单（系统性）

| 环节 | 结论 | 处置 |
|---|---|---|
| Provider 流式 | 已按 token 流式（`TokenDelta`） | 无需改 |
| 并发工具 | 只读+宿主验证工具已并发（`tool_concurrency=4`） | 无需改 |
| SSE 有界队列 | 容量 128，半满（64）时合并 token，防背压丢帧 | 保留（有界是契约） |
| 审批等待 | 服务端 50ms 轮询 | 保留（审批是人工阻塞点） |
| 上下文压缩 | 仅超预算时触发一次模型调用 | 保留（`/compact` 可手动） |
| 每回合 SQLite/审计/trace 写 | 每回合各一次，不在工具热路径 | 保留 |
| 工具结果注入扫描 | CPU 级，无 I/O | 保留 |
| MCP 连接 | 启动期一次性；失败仅告警 | 保留 |
